# Formwright 表匠操作手冊

這份手冊說明怎麼用 Formwright：在設計器建一個功能（模組）、加欄位、設公式與規則、分配權限，然後讓使用者在自動產生的列表與表單上操作。想先看實際畫面，可以直接開[線上 Demo](https://dynamic-modules-demo.onrender.com)。設計理由見[設計文件](superpowers/specs/2026-11-03-dynamic-modules-design.md)。

## 1. 開始之前

### 啟動

需要 .NET 8 SDK 與 Bun 1.4 以上。

```bash
cd poc/frontend && bun install && cd ../..   # 第一次才需要
poc/start.command                            # macOS；Windows 用 poc\start.cmd
```

後端在 `http://127.0.0.1:5180`、前端在 `http://127.0.0.1:9180`，就緒後自動開瀏覽器。macOS 按 Ctrl-C 停止；Windows 關掉兩個視窗即停止。

### 第一次安裝

全新資料庫只有一個管理員 `admin`，沒有任何示範使用者、群組、模具或客戶。`admin` 的初始密碼這樣決定：

- 設了環境變數 `Auth__InitialAdminPassword`，就用它（至少 8 碼，太短站台啟動失敗並說明原因）。
- 沒設，系統產生隨機密碼，只在啟動 log 以 Warning 印一次，沒抄到就得重來（見下面的緊急救援）。
- 本機用 `poc/start.command` 啟動時是 Development 環境，初始密碼為 `admin1234`。Windows 的 `poc\start.cmd` 沒有設定 Development，`admin1234` 不適用：請自己設 `Auth__InitialAdminPassword`，或到啟動 log 找系統產生的隨機密碼。

第一次用 `admin` 登入，系統會要求改密碼。引導只在「資料庫裡沒有任何啟用中且已設密碼的系統管理員」時執行，之後改環境變數不會覆寫既有密碼。

**緊急救援**：唯一的管理員忘記密碼時，在啟動環境設 `Auth__ResetAdminPassword`（至少 8 碼）再重啟。啟動時會重設 `admin` 的密碼，同時啟用帳號、解除鎖定、要求下次登入改密碼，並讓既有 session 全部失效，log 會留一筆 Warning。救回之後務必把這個設定移除，否則每次重啟都會再重設一次。

### 登入與改密碼

開網址會先到登入頁。輸入帳號與密碼；帳號不分大小寫，前後空白會被忽略，密碼則完全照打。

- 帳號不存在、密碼錯、已停用、已鎖定，畫面都只顯示同一句「帳號或密碼錯誤，或帳號暫時無法登入」，避免被人探測有哪些帳號。真正原因只寫在伺服器 log。
- 登入失敗依「帳號＋來源 IP」限流：同一組在 15 分鐘內輸錯 5 次，只擋那個來源；單一 IP 15 分鐘內失敗 20 次也會被擋。外人猜錯密碼不會讓本人登入不了。單一帳號 1 小時內累積 50 次失敗（多個來源輪流猜）時，該帳號改成每 10 秒只放行一次嘗試。**已知限制**：這時別人也可以搶在本人之前送出嘗試，所以被多個來源輪流針對的帳號，本人可能要多試幾次才登得進去（只變慢，不會被鎖死）。成功登入會清掉該來源的紀錄；站台重啟會歸零。
- 登入後停在首頁（網址 `/`），不會自動跳去別的頁面；若是從別的網址被帶來登入，登入後回到原本的網址。首頁的內容見 [§7](#7-使用模組)。
- 第一次登入與被管理員重設密碼後，會被導到改密碼頁。這段期間除了登入、登出、改密碼與取得目前使用者之外，所有 API 都回 403，不只是畫面導頁。
- 登入狀態存在 `HttpOnly` cookie 裡，8 小時內有操作會順延，關閉瀏覽器就失效。右上角選單有「變更密碼」與「登出」。被強制改密碼時看不到右上角選單，改密碼頁自己有「登出」按鈕，按了回到登入頁；自願改密碼時另有「回到系統」。登出失敗（例如斷線）時留在原頁並顯示錯誤，不會假裝已登出。
- 介面語言：登入頁與登入後右上角各有一個「語言」圖示（地球儀樣式的翻譯圖示），選單列出繁體中文、English、ไทย、Tiếng Việt。選了立即生效，不必重新整理；日期選擇器、表格分頁等內建文字也一起換。第一次開啟固定是繁中，選過之後記在這個瀏覽器，下次沿用；換瀏覽器或清除網站資料就回到繁中。被強制改密碼時看不到右上角選單，請先在登入頁選好語言。某個語言缺的文案會顯示繁中。
- 密碼至少 8 碼，沒有其他組成規則；改密碼要輸入舊密碼，新密碼不可與舊密碼相同。
- 系統不寄信，忘記密碼由管理員重設（見 [§11](#11-系統管理使用者)）。
- 停用、重設密碼、改密碼都會讓該使用者其他 session 在下一個請求立刻失效；自己改密碼時，目前這個 session 會換發新 cookie，不必重新登入。
- 後端若暫時回應異常（不是 401），會顯示公開的頁面，寫著「目前無法連線到伺服器，請稍後再試」，按「重試」重新載入原本的路徑；這種情況不會清掉登入狀態。

新建的模組只有系統管理員能用，其他群組要在權限分頁授權才看得到（見 [§5](#5-權限)）。使用者不屬於任何群組時沒有任何模組權限。

### 重設資料

停止服務後刪除 `poc/backend/data/poc.db`（旁邊的 `keys` 目錄是登入用的金鑰，可一併刪除），下次啟動會重建資料庫，只剩 `admin`，模組、使用者、群組都要重新建。

## 2. 建立模組

以系統管理員身分，從左側選單「系統管理 > 動態模組設計」進入設計器。

### 2.1 新增模組

1. 在模組清單按「新增模組」。
2. 填代碼與名稱。代碼是小寫英文開頭，可含數字與連字號，長 2 到 40 字，建立後就是網址的一部分（例如 `/dynamic/repair-request`），不能改。
3. 「選單分區」可留空。填了的話，模組在左側選單會放在這個分區底下；留空就放在「自訂功能」。建立後也能在設計器上方修改，最多 100 字。
4. 建立後系統自動配一組 ProgramCode（`DYN00001` 起），模組狀態是「草稿」，並附一個區塊和一個文字欄位，這個欄位預設是記錄標題。

名稱和其他顯示文字都有 4 個語系（繁中、English、ไทย、Tiếng Việt）；繁中必填，展開「其他語系」可填其他語言。

系統介面本身與內建應用程式（CRM 與銷售）的文案，ไทย 與 Tiếng Việt 目前是機器翻譯，對客戶上線前需要母語人士校對。

### 2.2 區塊

區塊是表單與明細頁上的分組。按「新增區塊」或區塊旁的「編輯區塊」，可設定名稱與「預設收合」；「編輯區塊」另可選「每列欄數」（1 到 4，預設 4）。欄位依順序由左到右、由上到下排；實際欄數依畫面寬度遞減：不到 600px 一律 1 欄，600 到 1023px 最多 2 欄，1024 到 1439px 最多 3 欄，1440px 以上最多 4 欄，並取區塊設定的欄數與該寬度上限中較小者。多行文字與設為「佔滿整列」的欄位固定佔整列。

### 2.3 欄位

在區塊下按「新增欄位」，填名稱、選型別。型別建立後不能更改，要改只能停用舊欄位、另建新欄位。

| 型別 | 用途與備註 |
|---|---|
| 文字、多行文字 | 可設長度上限；多行文字不能篩選、排序 |
| 整數、小數、金額、百分比 | 小數、金額、百分比可設小數位數；沒有「金額」權限的人看不到金額欄位 |
| 日期、日期時間、時間 | 日期時間一律以 +08:00 儲存 |
| 是否 | 開關 |
| Email、電話、網址 | 會檢查格式 |
| 下拉、多選 | 建立欄位後再加選項；多選不能排序 |
| 使用者 | 從使用者清單挑人 |
| 公式 | 由其他欄位算出，不能手動輸入，見 [§3](#3-公式與自動編號) |
| 自動編號 | 新增記錄時配號，不能手動輸入，見 [§3](#3-公式與自動編號) |
| 參照 | 指向另一個模組的記錄，或指向既有實體（目前只有客戶）的資料，見 [§6](#6-關聯) |

每個欄位可以設定：

- **必填、唯讀**：所有人都適用；權限與規則還能再加限制（見 [§4.4](#44-優先順序)）。
- **列表顯示**：出現在列表的欄位。
- **佔滿整列**：表單與明細頁上這個欄位自己佔一整列，不和其他欄位並排。新建多行文字欄位時預設開啟。
- **可篩選、可排序**：開了才會出現在列表的篩選與排序選單。
- **預設值**：新增記錄時帶入。下拉與多選要先加選項才能設預設值。
- **預設今天**（只有日期欄位）：新增記錄時帶入今天。表單用電腦本機的日期，沒送值時伺服器用台灣時間的今天。
- **帶表頭的值**（只有明細模組的欄位）：選表頭模組裡同型別的欄位，新增明細列時帶入表頭那個欄位目前的值，例如明細的交期帶表頭的交期。只在新增一列時帶，之後改表頭不會更新既有的明細列。

預設值、預設今天、帶表頭的值三者只能選一種；設了其中一種，另外兩種就不能設。

點欄位那一列開啟編輯；列右側可上移、下移、停用（手機寬度收在「⋮」）。停用的欄位從表單與列表消失，但已存的資料保留，重新啟用後就回來。被公式引用的欄位不能停用。

### 2.4 選項

下拉與多選欄位存檔後，在編輯欄位的對話框加選項，每個選項可設顏色。停用選項後，新增記錄不能再選它，但已經存著這個選項的舊記錄照樣能編輯，列表篩選也還找得到這些記錄。

### 2.5 記錄標題

設計器上方的「記錄標題欄位」決定明細頁標題，以及列表的標題欄。只能選啟用中的文字或自動編號欄位。

標題要由幾個欄位組成時（例如模具的「編號 名稱」），在下方的「標題樣板」設定：

1. 按「插入欄位」挑欄位，樣板裡會加上 `{12}` 這樣的欄位代碼（大括號內是欄位的內部編號）；欄位之間可以打空白、連字號、括號等文字。下方提示顯示標題會長什麼樣子，例如「標題會像：模具編號 名稱」。
2. 離開輸入框就存檔，既有記錄的標題立刻照新樣板重組。清空樣板，標題就回到記錄標題欄位。
3. 能放進樣板的欄位：文字、電子郵件、電話、網址、自動編號、日期、單選下拉（顯示選項名稱）。數字、參照、多選、附件、公式等不能放；樣板最長 200 字，每個欄位算 1 字（不論寫成 `{12}` 還是 `{no}`）。
4. 沒有值的欄位顯示成空的，標題頭尾的空白會去掉。改了樣板用到的下拉選項名稱，既有記錄的標題也跟著改。
5. 模組裡只要有一筆記錄已經固定（處於唯讀狀態，或已經產生連動記錄），就不能再改樣板、換記錄標題欄位或改樣板用到的選項名稱，以免改到已固定單據的標題；應用程式關閉或分錄模組也一樣不能改。

組出來的標題用在所有顯示標題的地方：列表的標題欄、明細頁標題、別的模組參照它時顯示的文字、參照挑選器的搜尋（用任何一段都找得到，例如輸入編號或名稱）、匯入時的參照比對（要填完整標題，例如 `MD-01 上蓋模`），以及報表依參照分組時的標籤。有樣板時，列表的標題欄欄名是「標題」，按欄名排序（或在「排序」裡選這一欄）就依組好的標題排序。

樣板用到的欄位跟記錄標題欄位一樣：不能停用、不能刪除、不能設成對某個群組隱藏。應用程式套件也能帶標題樣板（格式 6 起，寫欄位代號，例如 `"titleTemplate": "{no} {name}"`）。

### 2.6 啟用與停用

模組在「草稿」狀態時，一般使用者看不到。按「啟用」後左側選單出現這個模組。之後改欄位、規則、權限都即時生效，不用重新啟用。按「停用」會讓模組從選單消失，資料保留，「重新啟用」即恢復。

### 2.6.1 刪除模組、欄位、區塊

停用只是收起來，資料還在。真的要拿掉，設計器提供刪除，需要設計器的「刪除」權限，沒有這個權限的人看不到刪除入口。刪除是永久的，沒有垃圾桶。

**只有同時符合三個條件才能刪：未啟用、沒有資料、沒被引用。** 不符合時對話框會列出原因和來源，先處理再回來刪。

| 對象 | 入口 | 未啟用 | 沒有資料 |
|---|---|---|---|
| 模組 | 設計器上方「刪除模組」（草稿或停用的模組才有） | 模組不是啟用中 | 沒有未刪除的記錄 |
| 欄位 | 已停用欄位旁的垃圾桶 | 欄位已停用 | 沒有未刪除的記錄在這個欄位有值 |
| 區塊 | 區塊列的垃圾桶 | 區塊內的欄位都已停用 | 區塊內每個欄位都沒有資料 |

- **「沒有資料」只看未刪除的記錄。** 記錄刪除是軟刪除，資料其實還在資料庫裡；只剩已刪除的記錄時，視為沒有資料，可以刪。這時對話框會用警告色寫明「永久刪除」，並告訴你將一併清除幾筆已刪除的記錄、索引與異動歷程，要輸入模組代碼（欄位與區塊是勾選）才能確認。你確認的是畫面上那組筆數；確認的瞬間筆數若變了，會顯示新數字要你重新確認。
- 欄位的空值是：沒填、空白、空陣列。數字 0 與「否」算有值。公式與彙總欄位的值是算出來的，不算資料，但引用它們的東西仍會擋下。自動編號已經發給記錄，算資料。
- **被引用**指下列任一個指向它：參照欄位（含明細關係）、彙總欄位、公式、「預設帶表頭值」、規則、檢視（欄位、篩選、排序）、報表（含報表的排序鍵），以及儀表板卡片的排序鍵（指派給大家的儀表板、使用者自己的儀表板、使用者對指派版的個人版都算）。對話框會列出是哪個儀表板，個人版標示為「儀表板個人版」。停用中的公式、規則也算，因為重新啟用時會壞掉。刪整個模組時，模組自己內部的引用不算。
- 記錄標題欄位不能刪；模組至少要留一個區塊。
- 刪模組會一併清除它的區塊、欄位、選項、規則、檢視、權限設定、資料範圍與自動編號流水號；刪欄位會同時從已刪除的記錄裡拿掉這個欄位的值。
- 整個刪除在同一個交易裡：任何一步失敗就全部不動。沒有「一鍵清空全站」，要清掉一個模組的資料，請在列表一筆一筆刪除記錄（刪完才符合「沒有未刪除的記錄」）。

### 2.6.2 有單據簽核中時

模組有單據正在簽核時，設計器會擋下兩類修改，回「xxx 正在簽核中……請等簽核結束或撤回後再改」，訊息列出最多 5 張單據的標題與總張數。判斷只看有沒有單據簽核中，不看你是誰，系統管理員也一樣。

- **會改變簽核中單據內容的修改**：新增公式或彙總欄位；改公式或彙總的設定；改欄位的「帶值」對應；改數字欄位的小數位；重新啟用公式或彙總欄位；換記錄標題欄位或標題樣板、改標題樣板用到的下拉選項名稱；刪除欄位或區塊時要連已刪除記錄的值、索引或異動歷程一起清除（欄位曾有值又清空，只剩異動歷程也算），以及刪除在記錄上仍有值的公式或彙總欄位。範圍包含這個模組、以它為來源的彙總所在的上層模組，以及它是明細時的表頭模組：例如改明細的小計公式，只要有採購單簽核中就被擋。
- **會拆掉簽核中單據要走的轉移與狀態**：刪除狀態機；存狀態機時移除簽核中單據的「來源 → 目標」轉移、把它改成不需簽核、移除這兩個狀態、換狀態欄位，或移除流程設定的退回狀態轉移；停用這兩個狀態，或流程設定的退回狀態的下拉選項。

照常可以改的有：改欄位標籤、新增一般欄位、停用公式欄位、刪除沒有值的欄位、新增不相關的轉移。要改被擋的項目，請等簽核結束，或請發起人撤回（[§21.4](#214-撤回)）。已核准的單據不算簽核中，改公式時會依 [§21.5](#215-核准後的鎖頭) 保留原值。

### 2.6.3 有單據停在簽核鎖定狀態時

單據核准後會停在「簽核鎖定」狀態（[§21.5](#215-核准後的鎖頭)）。只要還有未刪除的單據停在鎖定狀態，設計器會擋下下面幾類修改，回 409 或 400。判斷只看單據目前的狀態，不看你是誰，系統管理員也一樣。

- **整批解鎖**（409，訊息「有 N 筆記錄停在會被解除鎖定的狀態……」）：刪除狀態機，或存狀態機後某個原本鎖定的狀態不再鎖定（關掉需簽核轉移、把延伸到的鎖定狀態標成可編輯、拿掉狀態、換狀態欄位），而且有單據停在那個狀態。要改，先把那些單據退回可編輯的狀態，或保留需簽核設定。新增需簽核轉移後鎖定範圍會變大，原本不需簽核、停在新增鎖定狀態的單據也會立即被鎖（不擋）；沒有單據停在被解鎖狀態時不受影響。
- **刪除鎖定欄位的值**（409）：刪欄位或區塊會清掉記錄上的值；被刪的欄位是鎖定欄位（任何版本的流程條件的上游、簽核人可編輯的欄位、所有附件欄位），而停在鎖定狀態的單據在那個欄位有值時擋下。明細模組在表頭鎖定、明細列一起鎖時，明細的任何欄位都算鎖定，包括只用來顯示的公式。公式與彙總欄位停用後直接刪除，沒有單據簽核中時第一個碰到的就是這一道（它們不受「欄位有資料」限制）；一般欄位有值時則先被「欄位有資料」擋下。
- **改公式、彙總或帶值使可編輯欄位落進條件閉包**（400）：簽核人可編輯的欄位不能是流程條件或簽核人來源的上游。改公式、改彙總、改帶值對應、重新啟用公式或彙總欄位後會重檢，只報這次修改新增的違規，已存在的違規不連坐；擋下時不會重算任何記錄。
- **鎖定帶值指向可編輯欄位**（400）：新增或修改參照欄位時，「鎖定」模式的帶值目的欄位不能是目前流程版本任何一關的可編輯欄位；改用「預設」模式不受限。進行中的簽核實例會先擋下改帶值（409）。

照常可以改的有：停用狀態欄位的選項（不改變鎖定範圍）、刪除不是鎖定欄位的空欄位。

### 2.7 預覽

設計器的「預覽」分頁用目前的設定畫出新增表單，草稿模組也能看，不必先啟用。頂端提示「預覽使用目前的草稿設定，不會存檔」。

- 預覽以系統管理員的權限呈現：看得到全部欄位，欄位權限與群組權限不影響預覽。
- 規則照樣作用：可以在預覽裡填值，確認欄位顯示、必填、選項限制是否符合預期；按「儲存」會檢查必填等錯誤，通過後只跳出「預覽不會存檔」，不會建立記錄。
- 改了欄位或規則後，切回預覽分頁就會重新載入。
- 表頭的預覽只列已啟用的明細模組；明細模組還在草稿時，預覽裡看不到它的表格。

### 2.8 模組範本

範本是一份 JSON，裡面有一或多個模組的區塊、欄位、選項、規則、共用檢視和群組權限建議。模組清單上方的「匯入範本」只有能新增模組的人看得到，「從範本建立」還要能修改模組（套用時會逐步修改剛建的模組）；設計器上方另有「匯出範本」。實際走過的情境見[第 8 階段驗收](acceptance/phase8.md)。

**從範本建立**

1. 按「從範本建立」，選一個範本。清單標示「內建」或「已匯入」；內建範本有四個：
   - 訂單：訂單＋訂單明細。
   - 故障報修：模具報修單，含狀態流程與規則。
   - 模具保養＋客戶擴充：替既有的模具、客戶加欄位，並有保養紀錄與更換零件模組。
   - 品質異常：異常單以一般參照指向訂單。這個範本需要庫裡已經有代碼為 `order` 的訂單模組，沒有的話套用會失敗；請先套用「訂單」範本。
2. 每個模組一張卡片，可以改代碼與名稱。預設代碼是範本裡的代碼（例如 `order`、`order-line`），已經有同代碼的模組時，建立會失敗並顯示錯誤，改代碼再按一次即可。
3. 「要建立的欄位」預設全選，取消勾選的欄位不會建立：
   - 標「（必要欄位）」的不能取消，例如記錄標題欄位、明細的參照欄位。
   - 取消一個欄位時，引用它的公式、彙總、帶表頭欄位會一起取消；重新勾回時，它引用的欄位也一起勾回。
   - 引用了被取消欄位的規則不會建立。例如訂單取消「取消原因」，規則就少了「取消時顯示取消原因」「取消時必填取消原因」兩條。
4. 按「建立」。所有模組在同一個交易裡建出，任何一步失敗就整批不建；成功後是草稿狀態，畫面跳到第一個模組的設計器。檢查過後照 [§2.6](#26-啟用與停用) 啟用。

範本只帶群組的動作權限與資料範圍。欄位權限、選項範圍、個人權限要建好後到權限分頁補（所以單獨套用「品質異常」時，沒有「重大只有品保能選」「責任單位對業務唯讀」「不良率對現場人員隱藏」這些設定，要到權限分頁自己加）；範本提到的群組在這個資料庫不存在時直接略過。內建「訂單」範本的建議是：業務可讀取、新增、修改並有金額權限，資料範圍本人；業務主管再加刪除、列印匯出，資料範圍全部；現場人員只能讀取、沒有金額權限，資料範圍全部，所以看不到單價、金額與各項合計。

**匯出範本**

在設計器按「匯出範本」，下載 `{代碼}.template.json`。內容是這個模組，加上以它為表頭的所有明細模組。

- 只匯出啟用中的欄位與選項、共用檢視（不含個人檢視）、群組權限。
- 範本內表達不了的東西直接略過，寫在檔案的 `warnings`：彙總了範本外的模組、引用停用欄位的公式或規則；明細的「帶表頭的值」指向範本外的欄位時，只拿掉這個設定。畫面上不會另外提示，匯出後可以打開檔案看 `warnings`。

**匯入範本**

按「匯入範本」選 JSON 檔（最大 1 MB）。系統先檢查格式：代號、欄位引用、公式循環、規則引用的欄位與選項；有錯就列出全部錯誤，不匯入。通過後跳出「已匯入範本：名稱」，之後「從範本建立」的清單就有它。

- 範本代碼（檔案裡的 `key`）不能和內建或已匯入的範本重複，重複回「範本代碼已存在」。拿匯出檔到同一個資料庫再匯入時，要先改 `key`。
- 匯入的範本不能刪除或覆蓋，要換內容就改代碼另外匯入。
- 格式檢查不看各型別的設定內容（例如自動編號格式），這類錯誤要到「從範本建立」時才會擋下。

哪些範本功能沒有在畫面上實際操作過、只靠自動測試，見[第 8 階段驗收的「未實機驗證」](acceptance/phase8.md#未實機驗證)。

## 3. 公式與自動編號

### 3.1 公式

欄位型別選「公式」後，填運算式、結果型別（數字、金額、日期）與小數位數。

- 用 `{欄位編號}` 引用同一筆記錄的數字或日期欄位。欄位編號就是設計器欄位清單上 `f_` 後面的數字，也可以用「插入欄位」下拉插入。
- 可用 `+ - * /`、括號，以及以下函式：

| 函式 | 說明 |
|---|---|
| `ROUND(x, n)` | 四捨五入到 n 位 |
| `IF(條件, a, b)` | 條件成立取 a，否則取 b；比較運算子只能用在這裡的第一個參數 |
| `DATEDIFF(a, b)` | 回傳 a − b 的天數 |
| `DATEADD(d, n)` | 日期 d 加 n 天 |
| `TODAY()` | 今天 |

- 百分比欄位以「值 ÷ 100」參與運算，例如 5% 算成 0.05。
- 運算式有錯時，存檔會在運算式下方顯示原因，例如「公式不正確：欄位 99 不存在或未啟用」。
- 公式在記錄存檔時由伺服器計算，表單上看到的是上次存檔的結果。含 `TODAY()` 的公式不會每天自動重算，要等記錄再次存檔。
- 修改運算式、重新啟用公式欄位時，既有記錄會全部重算，但已固定的記錄保留原值：簽核中、核准後停在簽核鎖定狀態、處於唯讀狀態、已記帳（有連動事件事實）的單據，以及它們的明細列。在欄位對話框存檔（新增或修改公式、彙總）時，畫面會提示「有 N 筆已固定的記錄保留原值，沒有跟著重算」；這個 N 只算被修改的那個模組：改明細模組的公式時，N 是明細列數，不是單據張數；連帶重算的上層模組不計。沒有記錄被保留時不顯示提示；重新啟用欄位不會提示。
- 公式引用的任何一個欄位，只要某人看不到，這個公式對他也會隱藏。

### 3.2 自動編號

欄位型別選「自動編號」後填編號格式，下方會即時顯示範例。

- 變數：`{yyyy}`、`{yy}`、`{MM}`、`{yyyyMM}`，以及恰好一組 `{0000}`。`0` 的個數就是流水號位數。
- 格式含月份就每月從 1 重新編號，只含年份就每年重新編號。
- 例：`REP-{yyyyMM}-{0000}` 在 2026 年 11 月依序產生 `REP-202611-0001`、`REP-202611-0002`。
- 只在新增記錄時配號，之後不會變。加入這個欄位之前已存在的記錄不會補號。

自動編號很適合當記錄標題（[§2.5](#25-記錄標題)）。

## 4. 規則

規則讓欄位依其他欄位的值變化：出現或隱藏、變必填、變唯讀、檢查資料、限制下拉選項。在設計器的「規則」分頁設定，每個模組最多 100 條。

### 4.1 新增規則

1. 按「新增規則」，選種類。
2. 設條件：選「全部符合」或「任一符合」，再逐條加條件（欄位、運算子、值）。不加任何條件就是「永遠成立」。
3. 選目標，然後按「儲存」關閉對話框。
4. 回到規則清單後按「儲存規則」，整份清單才會寫入。沒按就離開，剛才的修改不會保存。

點規則那一列開啟編輯；列右側可上移、下移、停用、刪除（手機寬度收在「⋮」）。同一個目標有多條規則時，合併方式見下表。

| 種類 | 條件成立時 | 可選的目標 | 多條規則作用同一目標 |
|---|---|---|---|
| 顯示 | 顯示目標；不成立就隱藏 | 欄位、區塊 | 全部成立才顯示 |
| 必填 | 目標變必填 | 欄位 | 任一成立就必填 |
| 唯讀 | 目標變唯讀 | 欄位、區塊、整筆記錄 | 任一成立就唯讀 |
| 驗證 | 代表資料正確；不成立就報錯 | 欄位 | 各自檢查 |
| 選項限制 | 下拉欄位只剩勾選的選項 | 一個下拉欄位 | 取交集 |

- **驗證**要填驗證訊息，這段文字會顯示在目標欄位下方。
- **選項限制**要先選下拉欄位，再勾允許的選項，至少勾一個。
- 區塊當目標時，作用在區塊裡的每個欄位；區塊內欄位全部被隱藏時，整個區塊不顯示。

### 4.2 條件怎麼判斷

- **空值**：條件欄位沒填時，只有「是空的」「不等於」「不包含於」成立，其他運算子一律不成立。
- **比較另一個欄位**：運算子是等於、不等於、大於、大於等於、小於、小於等於時，「比較對象」可以切成「另一個欄位」，下拉只列同一類（數字、日期或文字）的欄位。
- **跨欄位驗證要允許空值**：例如「需求日不得早於申請日」要寫成「任一符合：需求日是空的、需求日 大於等於 申請日」，否則需求日沒填也會報錯。
- **文字比較**：區分大小寫，值前後的空白會先去掉。
- **相對日期**（未來 N 天內、過去 N 天內）：以台灣時間（+08:00）的今天為準。
- 條件群組可以巢狀；遇到巢狀群組時，編輯器改成直接編輯 JSON。

### 4.3 唯讀規則看的是「已存檔的值」

唯讀規則依記錄存檔時的值判斷，不看表單上剛改的值，所以：

- 新增記錄時，唯讀規則一律不生效。
- 在表單把狀態改成「已結案」，不會當場鎖住，可以正常存檔。下次打開編輯時，整張表單才變唯讀，頂端顯示「此記錄目前不可修改」，也沒有儲存鈕。
- 記錄被整筆鎖住後，任何修改都會被伺服器擋下，回同一句訊息。

### 4.4 優先順序

權限 > 規則 > 欄位設定：

- 權限設成看不到或唯讀的欄位，規則不能讓它變可見、可編輯。
- 規則可以在欄位設定之上再加必填或唯讀。
- 被規則隱藏的欄位不檢查必填，但如果它的值有改，照樣會送出存檔。
- 使用者改不了的欄位（權限唯讀、欄位唯讀、規則唯讀），不檢查選項是否在可選範圍。

### 4.5 注意事項

- **條件含公式或自動編號欄位**時，編輯規則的對話框會提示：表單上不會即時套用，存檔時才由伺服器判斷。新增記錄時伺服器也還沒配號，所以引用自動編號的條件在新增時看到的是空值。
- **條件引用某些人看不到的欄位**時，這條規則不會送給那些人，他們的表單不會即時反應，但伺服器存檔時照樣判斷。設計時盡量別讓一般使用者的規則依賴他們看不到的欄位（spec §15 第 24 條）。
- **下拉連動的舊值**：上層欄位改了以後，下層欄位留著的舊選項若不在新的允許範圍，存檔時會顯示「選項不在可選範圍」，要重選下層欄位。
- 錯誤若發生在目前沒顯示的欄位，會出現在表單頂端，格式是「欄位名稱：訊息」。

## 5. 權限

設計器的「權限」分頁有四塊，改完按「儲存權限」。新建的模組預設除了系統管理員以外沒有人有權限。

### 5.1 群組權限與資料範圍

每個群組各有 7 項動作權限：讀取、新增、修改、刪除、列印匯出、金額、核准。

- 沒有「讀取」就完全看不到這個模組，選單也不出現。
- 沒有「金額」的群組看不到所有金額欄位，連帶看不到引用金額的公式。
- **資料範圍**決定看得到哪些記錄：本人（擁有者是自己的記錄）、同群組（擁有者和自己同群組的記錄）、全部。新增記錄時，擁有者就是建立的人。同一個人屬於多個群組時，取範圍最大的那個。

### 5.2 個人權限

按「新增使用者」可以替特定使用者另外加權限。有效權限是個人權限與群組權限逐項合併，任一邊有就算有。

### 5.3 欄位權限

可以替每個群組把個別欄位設成「唯讀」或「隱藏」，沒設就是「預設」。同一個人屬於多個群組時，任一群組設成隱藏就隱藏（限制優先）。

### 5.4 選項範圍

限制某些群組只能選下拉欄位的部分選項。沒有指定群組的選項，所有人都能選。

### 5.5 共用主檔的權限

共用主檔（見 [6.7](#67-共用主檔)）的權限由使用它的各應用程式授予，再加上管理員在這裡的調整，合併規則是：

- 同一個群組被幾個應用程式授權時，動作取聯集，**資料範圍逐動作取最寬**。例如一個應用程式給「讀取／全部」、另一個給「讀取＋修改／本人」，結果是讀取全部、修改本人，不會變成修改全部。
- 群組權限表的「資料範圍」欄在主檔上變成逐動作設定：按下去列出這個群組已勾選的每個動作，各選一個範圍；各動作範圍相同時顯示該範圍，不同時顯示「依動作不同」。
- 列印與匯出（單筆列印、列表匯出、報表匯出）要同時符合讀取和列印匯出的範圍。例如讀取全部、列印匯出本人，畫面看得到別人的記錄，但只能列印、匯出自己的。
- 金額權限的範圍要至少和讀取（或修改等當下的動作）一樣寬才看得到金額。例如讀取全部、金額本人時，金額欄位與金額公式一律不顯示，連自己的記錄在檢視時也看不到；把金額改成全部才會顯示。
- 存檔只記下你改了什麼：多給的動作或放寬的範圍記成手動授予；拿掉的動作，下次應用程式開啟或關閉時也不會長回來。原封不動存檔不會改變任何權限。應用程式關閉期間暫時收回的寫入權限，不會因為你存檔而被當成拿掉。
- 欄位權限區下方多一塊「其他應用程式貢獻欄位的可見群組」：每個貢獻欄位一列，勾選要另外開放的群組。應用程式給的群組標示「（來自 ○○）」且不能取消；要不讓某個群組看到，在上方欄位權限設成「隱藏」，隱藏優先於可見授予。群組被刪除時，它的授權一起移除。

## 6. 關聯

### 6.1 參照欄位

新增欄位時選「參照」，要設定：

- **目標種類**：「動態模組」或「既有實體」。動態模組的目標必須是一般模組（不是擴充模組），可以選自己這個模組（例如「上層設備」）；既有實體目前只有客戶。
- **目標被刪除時**（只有目標是動態模組時才有）：目標記錄被刪除時，參照它的記錄要怎麼處理。

| 目標被刪除時 | 意思 |
|---|---|
| 禁止刪除（預設） | 還有記錄參照，目標就不能刪除，並列出是誰在參照 |
| 清空欄位 | 目標刪除後，參照它的記錄這個欄位變空白；不能用在必填欄位 |
| 連帶刪除 | 目標刪除後，參照它的記錄一起刪除，最多連鎖 5 層 |

其他限制：

- 目標一旦建立就不能改，要改只能停用舊欄位、另建新欄位；「目標被刪除時」之後還可以改。
- 參照欄位不能設預設值、長度、格式與排序，不能用在公式，也不能當記錄標題。
- 參照欄位一律建索引，所以不必另外開「可篩選」；篩選可用「等於」「不等於」「是其中之一」「不是其中之一」「是空的」「不是空的」。

### 6.2 在表單與明細裡使用

- 表單上的參照欄位是一個挑選框，按下去開搜尋視窗，輸入關鍵字（比對標題）後挑一筆，「清除」可以清空。只列得出你有權讀取、且在你資料範圍內的記錄。
- 明細與列表顯示目標的標題；目標是動態模組時，標題是連結，點了到目標的明細頁。
- 目標已被刪除，或既有實體已失效，顯示「已失效」，沒有連結。你沒有目標模組的讀取權限、目標不在你的資料範圍，顯示「無權限檢視」，同樣沒有連結。
- 存檔時，新選的目標不存在或你選不到，會顯示「參照的資料不存在或無權選取」。已經存好的舊值就算之後失效，只改別的欄位照樣存得進去。

### 6.3 反向關聯分頁

記錄的明細頁，會替每個「指向這個模組、且你有權讀取」的參照欄位多一個分頁（分頁名稱是「模組名稱 · 欄位名稱」），列出參照這筆記錄的來源記錄，依建立先後由新到舊，只列你資料範圍內的。你有來源模組的新增權限、且能寫入那個參照欄位時，分頁上有「新增」鈕，帶你到來源模組的新增表單，參照欄位已經填好這筆記錄。

### 6.4 刪除被擋時

刪除一筆被參照的記錄，若某處設定的是「禁止刪除」，整筆刪除都不會執行（包含連帶刪除的部分），並跳出對話框：「還有其他資料參照這筆記錄，不能刪除」，列出最多 10 筆參照來源（模組、欄位、記錄標題；你沒有讀取權的記錄不顯示標題）與總數。先處理掉這些參照再刪除。連帶刪除超過 5 層時也會擋下，要先手動刪除下層資料。

### 6.5 擴充模組

擴充模組替「既有實體」的資料加自訂欄位，不另外維護一份主檔。

1. 新增模組時選「擴充模組」，再選要擴充的既有實體（目前只有客戶）。同一個實體只能有一個擴充模組；種類與實體建立後不能改。
2. 擴充模組沒有標題欄位，也不能設定；記錄標題取自既有資料（例如 `C-001 嵐岳精密`），新增時存下當時的標題。
3. 新增擴充資料時，表單最上面先挑既有資料；存檔後不能再換。
4. 每筆既有資料只能有一筆擴充資料，重複新增會顯示「這筆既有資料已經有擴充資料」。刪除後可以再建。
5. 其他模組的參照欄位不能指向擴充模組，要透過既有實體參照。

### 6.6 表頭與明細、彙總

**把模組設成明細**

1. 先建好表頭模組（例如訂單），再建明細模組（例如訂單明細）。
2. 在明細模組加一個參照欄位，目標選表頭模組，「關聯方式」選「明細」。這個欄位自動必填、表頭刪除時一起刪除；建立後不能改回一般參照，也不能停用。一個模組只能有一個明細欄位。
3. 明細模組不會出現在左側選單，也不能單獨打開；它的記錄只在表頭的表單與明細頁裡出現。模組清單會標示「明細：表頭名稱」。
4. 自動編號欄位在明細模組裡可以打開「在表頭內編號」：每張表頭的項次從 1 開始，格式不能含日期。刪掉的項次不會重用。

**明細的權限**

明細模組沒有自己的群組與個人權限：能看、能改表頭，就能看、能改它的明細；明細列的擁有者跟著表頭。權限分頁只能設定欄位例外與選項範圍。

**在表單裡編輯明細**

- 表頭表單下方，每個明細模組一張表格：「新增一列」加列、每列右側的按鈕刪列。存檔時表頭與明細一起送出，一個明細模組最多 200 列。
- 驗證錯誤顯示在出錯的那一格；改過那一格錯誤就消失。
- 規則逐列判斷，例如某列符合唯讀條件，那一列就不能改。表頭整筆唯讀時，明細表格也全部唯讀。
- 明細頁在欄位下方以唯讀表格列出明細。

**彙總欄位**

欄位型別選「彙總」，設定：

- **來源欄位**：其他模組指向本模組的參照欄位，明細或一般參照都可以（例如維修紀錄的「申請單」）。
- **函數**：加總、計數、最小、最大。計數不用選彙總欄位。
- **彙總欄位**：來源模組的數字、金額或日期欄位；彙總欄位本身、引用彙總欄位的公式不能選。
- **條件**（選填）：只計入符合條件的子記錄，例如「狀態 等於 已完成」。

結果型別與小數位數由伺服器依彙總欄位決定。沒有子記錄時，加總與計數是 0，最小與最大是空白。彙總只算一層：被彙總的欄位不能再是彙總。

**什麼時候重算**

- 子記錄新增、修改、刪除（含連帶刪除、清空參照、改指向另一筆）時，重算受影響的父記錄。
- 子記錄所在模組的公式重算時、彙總欄位新增、修改設定或重新啟用時，整個模組重算一次（已固定的記錄除外，見 [§7.6](#76-核准後哪些欄位不能改)）。
- 重算不改修改者與修改時間；值有變才更新記錄版本，所以有人正在編輯父記錄時，存檔可能收到「資料已被其他人修改」。
- 表單上不即時計算，存檔後才看到新的合計。
- 彙總計入所有子記錄，不看你能看到哪些；結果是金額的彙總，沒有金額權限的人看不到。
- 明細模組若另有一個一般參照也指向同一個表頭模組，靠這個參照做的彙總在存表頭時不重算，要等整個模組重算（例如修改彙總設定）時才更新。

範例（[第 6 階段驗收](acceptance/phase6.md)）：訂單明細的金額 `{數量} * {單價}`；訂單的未稅合計是加總金額、稅額 `ROUND({未稅合計} * {稅率}, 0)`（百分比欄位已是小數，不用再除以 100）、含稅總額 `{未稅合計} + {稅額}`。

### 6.7 共用主檔

共用主檔（例如往來對象）是幾個應用程式一起用的模組。應用程式可以在主檔上加自己的區塊與欄位，這些叫**貢獻欄位**。主檔的表單先排主檔自己的區塊，後面接各應用程式的區塊，依應用程式代號排序。

**內建的兩份主檔**

- **往來對象**：客戶與供應商共用的公司資料。基本欄位有編號、名稱、角色（客戶、供應商、客戶與供應商）、統一編號、電話、Email、地址、負責人、銷售與採購付款條件、啟用。列表有「客戶」「供應商」兩個檢視，各自列出該角色與「客戶與供應商」的公司。角色可以空白，但單據的客戶、供應商欄位只收對應的角色：例如 CRM 的客戶欄位選到供應商，存檔時會被擋下。
- **聯絡人**：姓名、目前公司（必填）、職稱、電話、Email，下面有「任職經歷」明細，記錄這個人待過哪些公司、職稱與起訖日期。目前公司與任職經歷各自維護，不會互相同步：人換公司時，改目前公司，再在任職經歷補一列。公司頁的聯絡人分頁列出目前在這家公司的人；以前待過的人目前不會列在公司頁，要從聯絡人的任職經歷看。

**CRM 與銷售怎麼用它們**

- CRM 沒有自己的客戶與聯絡人模組。開啟 CRM 時，往來對象與聯絡人自動開啟，往來對象表單多一個「CRM」區塊，放「產業」與「來源潛在客戶」。
- 商機、互動紀錄、報價單、訂單的「客戶」都指向往來對象，只能選角色是客戶或客戶與供應商的公司。
- 「互動紀錄」（原名「活動」）只記已經發生的電話、拜訪、郵件、會議，沒有「已完成」欄位；要追蹤待辦請用任務（[§15](#15-任務)）。CRM 另有「行銷活動」模組，建立時自動派工，見 [§17](#17-任務規則)。
- 已經開啟過 CRM 的舊資料庫不會升到 1.1.0，系統不提供升級腳本：「活動」不會自動改名，「已完成」欄位不會自動移除，「行銷活動」模組與它的派工規則也不會出現。要用新版請重建資料庫；只想改名與拿掉欄位，可在設計器自行改名，把「已完成」停用後刪除。
- 「設計案」是客製設計需求的追蹤單，用在訂製品或 ODM：業務主管建案並指派負責業務，業務與「CRM 產品設計」群組的設計人員依狀態來回，設計人員上傳設計圖，業務記下客戶意見，最後由主管確認結案（完整操作劇本見 [§22](#22-demo-劇本crm-設計案與簽核)）。狀態變成設計中、客戶確認中時系統自動派任務，案子取消或結案時未完成的任務自動取消。
- 設計案有兩個已知限制。第一，主管同意（待主管確認）之後不能取消，也不能退回修改，只能結案，要改請另開新案；之後的版本會補上退回修改。第二，設計人員對客戶、負責業務、設計負責人、需求說明這四欄是唯讀，同時屬於業務與產品設計兩個群組的人，也會被當成唯讀：畫面上這四欄就改不了，只有直接呼叫 API 時會回成功但值不變（伺服器端擋下）。業務兼設計的人不要加進產品設計群組，開啟 CRM 時也不要把兩個群組對到同一個既有群組。
- 已經開啟過 CRM 的舊資料庫也不會升到 1.2.0，不會出現設計案與「CRM 產品設計」群組，要用新版請重建資料庫。同理，已經開啟過 CRM 的資料庫不會自動多出 1.3.0 的設計案簽核流程：要在簽核流程設計器建立流程，並在狀態機分頁把「客戶確認中 → 待主管確認」設成需簽核（否則仍可直接改狀態），或重建資料庫。簽核 a5 之前產生的 Demo 資料已經有這個流程，不必再建。
- 潛在客戶「轉客戶」會建立一筆往來對象，角色固定是客戶（在轉換對話框改成別的角色，存檔時仍會設回客戶），之後就能在訂單、報價單的客戶欄位選到它。
- CRM 業務、CRM 業務主管對往來對象與聯絡人的權限由 CRM 授予，不含刪除與核准（留給主檔管理員）；CRM 關閉時，這兩個群組的新增、修改權限一起暫時收回。

**MES 與進銷存怎麼用它們**

- MES 沒有自己的客戶資料，也不再擴充既有實體「客戶」。開啟 MES 時往來對象自動開啟（聯絡人不會，MES 用不到），表單多一個「MES」區塊，放「信用等級」與「網站」。原本客戶資料的付款條件、業務窗口、電話、Email 改填往來對象的「銷售付款條件」「負責人」「電話」「Email」。
- MES 自帶的報價單、訂單在左側選單的名稱是「報價單（模具廠）」「訂單（模具廠）」（「業務」區塊），與 CRM 的「報價單」「訂單」（「銷售」區塊）區分；這是過渡期的命名，之後兩者並存時由覆蓋機制收掉 MES 那組。已存在的資料庫不會自動改名，新開啟 MES 才套用新名稱。
- MES 的報價單、訂單、出貨單的「客戶」指向往來對象，只能選角色是客戶或客戶與供應商的公司。
- MES 業務可以讀與修改往來對象（不能新增），MES 業務主管可以新增與修改；生管、現場人員、品保只能讀，所以在單據上看得到客戶名稱。生管、現場人員、品保看不到「信用等級」「網站」，跟改版前只有業務看得到一樣；但往來對象的基本欄位（例如銷售付款條件）是所有讀得到主檔的人都看得到的。
- 有往來對象修改權限的群組，可以改所有基本欄位，包括角色與另一個方向的付款條件（例如 MES 業務也能改採購付款條件）。要限制請在主檔的欄位權限另外設定。
- 進銷存沒有自己的供應商與出貨客戶模組。開啟進銷存時往來對象與聯絡人都會自動開啟，往來對象表單多一個「進銷存」區塊，放「出貨地址」。
- 採購單、進貨單的「供應商」只能選角色是供應商或客戶與供應商的公司，出貨單的「客戶」只能選客戶或客戶與供應商。原本供應商的「付款條件」改填往來對象的「採購付款條件」。
- 原本供應商、客戶上的「聯絡人」文字欄位拿掉了，改在聯絡人主檔建一筆，「目前公司」選那家往來對象。
- 進銷存採購、進銷存主管可以新增與修改往來對象與聯絡人，進銷存倉管只能讀；進銷存查詢看不到往來對象。
- 不論 MES、進銷存，對往來對象與聯絡人的權限都不含刪除與核准（留給主檔管理員）；應用程式關閉時，它給的新增、修改權限一起暫時收回。
- CRM、MES、進銷存不論用什麼順序開啟，往來對象表單的區塊順序都是「基本資料、CRM、進銷存、MES」（依應用程式代號排序，沒開的不出現）。
- 已經開過舊版 MES 或進銷存的資料庫不會自動轉成用往來對象，要重建資料庫。

**主檔跟著使用它的應用程式**

- 開啟一個需要主檔的應用程式時，主檔會自動開啟（已關閉的會重新開啟），並加上這個應用程式的區塊與欄位。
- 主檔不能在「應用程式」頁直接開啟、關閉或重開，也不在可開啟的清單裡。最後一個使用它的應用程式關閉時，主檔一起關閉；任一個重新開啟，主檔就跟著開。

**應用程式關閉後，它的欄位只能看**

應用程式關閉後，主檔還開著的話，它貢獻的欄位仍然看得到、仍會出現在報表，但任何人都不能修改，系統管理員也不能：

- 表單上這些欄位顯示為唯讀，區塊上方提示「『○○』應用程式已關閉，它的欄位只能檢視」，區塊預設收起。
- 送出不同的值（包括透過匯入、單據轉換、事件）會整筆失敗，訊息是「欄位『X』屬於已關閉的應用程式『Y』，不能修改」。值沒變則照常存檔，其他欄位照常寫入。
- 這些欄位的公式不重算，保留關閉前的值，重新開啟後下一次存檔才更新。新增記錄時也不套用它們的預設值。
- 刪除一筆記錄若要清空這類欄位（例如它指向被刪的聯絡人），整筆刪除失敗。
- 這個應用程式給各群組的新增、修改、刪除、核准權限暫時收回，讀取類權限保留；重新開啟後恢復。

**貢獻欄位誰看得到**

貢獻欄位預設只有貢獻它的應用程式的群組（開啟時對應到的群組）與系統管理員看得到。其他群組即使能讀主檔，也只看到主檔自己的欄位；之後新建的群組也一樣。要讓別的群組看到，見 [5.5](#55-共用主檔的權限)。

**刪除應用程式時，它的欄位怎麼處理**

應用程式要先關閉才能刪除。主檔本身保留，不會被刪：

- 沒有值的貢獻欄位直接刪除，區塊空了也刪除。
- 參照這個應用程式自己模組的欄位（例如「來源潛在客戶」）連同值一起清除，因為它指向的模組會一起刪掉。刪除確認的筆數是「軟刪除的記錄筆數＋清除的欄位值筆數」，預覽會列出要清除哪些欄位、各幾筆。
- 其他有值的欄位改為停用，值保留在主檔記錄上。停用欄位不顯示在表單，管理員之後可以在設計器重新啟用，或清空後安全刪除。重新啟用後只有系統管理員與另外授予的群組看得到。
- 這個應用程式擁有的單據轉換與事件一起刪除，即使目標是主檔。
- 如果有應用程式以外的東西用到它的貢獻欄位（例如你自己在主檔上建的公式、報表、檢視），刪除會被擋下並列出來源，先移除那些引用。
- 它是最後一個使用主檔的應用程式時，主檔保持關閉並保留資料，刪除完成會提醒「共用主檔『X』已沒有應用程式使用，仍有 N 筆資料，已保留」。要完全移除主檔，等沒有任何應用程式使用它之後，再到「應用程式」頁刪除主檔。

**同一個應用程式再開啟時接回**

刪除後再開啟同一個應用程式，它留下的停用欄位、選項與區塊會接回：欄位恢復啟用，舊值回來，不會多出第二個同名欄位，可見群組也恢復。新版套件把欄位改成不同型別時不接回：另建一個新欄位，舊欄位留成停用，開啟預覽會警告。

**在主檔上用設計器加欄位**

主檔模組的設計器只有系統管理員能改（加改刪欄位、選項、區塊、規則、權限，以及在主檔上設定狀態機、分錄、列印範本、連動事件、跨記錄檢查，或建立來源、目標是主檔的轉換），其他有設計器權限的人會收到「沒有權限」。新加的東西歸誰，看它加在哪個區塊：

- 加在主檔自己的區塊（包括你在主檔上新建的區塊）：屬於主檔，是基本欄位，所有能讀主檔的群組照一般權限看得到，隨主檔匯出。
- 加在某個應用程式的區塊（例如「CRM」）：屬於那個應用程式，跟它貢獻的欄位一樣，預設只有它的群組與系統管理員看得到，應用程式關閉時一起變唯讀，隨它匯出、刪除。
  - 限制也和貢獻欄位相同：不能是自動編號、複選、附件、彙總，不能設必填；參照欄位只能指向該應用程式自己的模組（刪除時要「清空」）或共用主檔，不能設「一起刪除」；公式只能引用主檔自己的欄位和同一個應用程式的欄位。不符合時新增或存檔會失敗並說明原因。
  - 應用程式關閉期間，它的區塊不能再加欄位或選項，要加先重新開啟它。
- 歸屬建立時就定了，不能改：把欄位移到另一個擁有者的區塊會失敗，訊息是「欄位和目標區塊屬於不同的擁有者……不能跨區塊移動」。同一個擁有者的區塊之間可以移。
- 已刪除應用程式留下的區塊（裡面是停用欄位）不能再加欄位或選項，也不能把欄位移進去或移出來，訊息會提示改加在主檔的基本區塊。
- 新加的欄位、選項、區塊有系統產生的固定代號（`u` 加 8 碼英數，例如 `u7k2m9qx`），匯出、再匯入都用它，所以同一份主檔在幾個資料庫之間來回匯不會變出重複的欄位。

**匯出與匯入共用主檔**

應用程式與主檔的匯出目前沒有畫面，由系統管理員呼叫 `GET /api/v3/dynamic/apps/{代碼}/export` 下載（警告在回應標頭 `X-Export-Warnings`）；匯入在「應用程式」頁按「匯入套件」。

- 匯出應用程式：檔案裡有它自己的模組，加上它在主檔上的區塊與欄位（含你用設計器加在它區塊裡的、停用的），以及它給主檔的權限；主檔自己的欄位與別的應用程式的欄位不在裡面。用到的主檔列在 `requires.masters`。
- 匯出主檔：只有主檔自己的區塊、欄位、選項（含你加的、停用的）與主檔自己的群組權限。已刪除應用程式留下的停用欄位不匯出，匯出時會提示「往來對象的『信用等級』是已刪除應用程式留下的停用欄位，未匯出，資料仍保留在資料庫」。
- 把匯出檔搬到另一個資料庫：先匯入主檔與應用程式，再開啟應用程式；先開哪一個都可以。開啟對話框會列出要一起開啟的主檔和它的群組（例如往來對象管理員），照建議對應或新建。
- 匯出檔裡的群組代號取自群組代碼（開啟時新建的群組，代碼是系統產生的），同一個群組在一份檔案裡只有一個代號。
- 再匯入一份已存在的主檔不會被拒絕，而是**合併**，完成時提示「已合併進既有的共用主檔」，並逐條列出警告：
  - 還沒有應用程式開過這個主檔：把檔案裡多出來的區塊、欄位、選項加進目前的定義，之後第一個應用程式開啟時照合併後的內容建立。
  - 主檔已經開過：只補檔案裡有、資料庫裡沒有的欄位、選項與承載它們的區塊。既有的不刪、不改名稱或設定，也不改啟用狀態；檔案裡少了的欄位照樣留著。補上的欄位一律不是必填（主檔可能已有資料）；檔案標停用的新欄位補上後就是停用。
  - 代號相同但型別不同：保留既有的，警告「『電話』（phone）的型別和匯入的不同，保留既有的」。
  - 新欄位或選項的代號剛好和某個應用程式貢獻的代號相同：改用加 `_2` 的代號並警告；之後引用原代號的應用程式套件開啟時會對不上。
  - 群組、規則、檢視、權限、欄位例外與報表不合併，保留既有的並警告。
  - 檔案裡某個選項的代號已經是同一個模組另一個欄位的選項：不合併，並在警告列出。
  - 主檔已關閉（用它的應用程式都關了）也可以合併：照樣補主檔自己的欄位（包括公式），應用程式貢獻的欄位不動、仍是唯讀。
- 客戶刪過主檔的基本欄位後匯出，檔案就少那個欄位；在新的資料庫開啟還引用它的應用程式時會被擋下，列出對不上的代號（例如 `bp/partner.phone`）。

## 7. 使用模組

**首頁**：登入後看到的第一個畫面，左側選單最上方的「首頁」或點左上角的產品名都能回來。內容由上而下是：

- 歡迎區：你的姓名與產品名。
- 我的任務：「今天到期」「已逾期」兩個數字，點下去是「我的任務」頁對應的篩選（見 [§15](#15-任務)）。
- 最近開過：你最近打開的模組，最多 5 個，記在這個瀏覽器裡、依使用者區分；換瀏覽器或裝置會重新累積，瀏覽器不讓網站存資料時這一區不顯示。已停用或沒有讀取權限的模組不會列出。
- 我的應用：你有權限的模組卡片，分區方式與左側選單相同，點卡片進入模組。完全沒有可用模組時會說明並請你聯絡系統管理員。
- 報表：連到「我的報表」。
- 系統管理：只有對應權限的人看得到，項目與左側選單「系統管理」相同。

模組啟用並授權後，左側選單會出現這個模組。沒有設定選單分區的模組放在「自訂功能」底下；有分區的依分區名稱分組，「自訂功能」排最前面，其餘分區依名稱排序。

### 7.1 列表

- **搜尋標題**：依記錄標題做關鍵字搜尋，不分大小寫。
- **篩選**：按「篩選」，選「全部符合」或「任一符合」，再逐條加條件。可用的運算子依欄位型別而定；「包含於」「不包含於」以逗號或換行分隔，最多 50 個值。
- **排序**：點表頭依序切換升冪、降冪、取消；要多欄排序用排序編輯器。空值一律排最後。
- **顯示欄位**：勾選要顯示的欄位，並可上移、下移調整順序。
- **檢視**：把目前的篩選、排序、欄位存成檢視，可勾「共用給所有人」或「設為預設檢視」。個人檢視只有自己看得到；共用檢視所有人都能套用，但只有建立的人能更新與刪除。進入列表時自動套用自己的預設檢視。
- 檢視裡的欄位如果之後被停用，或不再開放篩選、排序，列表會提示「此檢視有 N 個欄位已停用或不再開放篩選、排序，已略過」。

### 7.2 新增、編輯、明細、刪除

- 列表按「新增」開表單；存檔後到明細頁，公式與自動編號的結果在這裡出現。
- 列表點整列進明細頁（第一欄是連結樣式，手機寬度列右側有箭頭）；沒有「編輯」按鈕。
- 系統管理與設計器的清單也是點列開啟編輯：使用者、群組、單據轉換、模組清單（點列進設計器），以及設計器的欄位、規則、任務規則、跨記錄驗證、連動事件分頁。列上保留停用、重設密碼、刪除等動作；沒有編輯權限時列不可點；手機寬度的動作收在「⋮」。
- 明細頁按「編輯」修改、按「刪除」刪除（刪除前會再確認）。
- 規則在表單上即時作用：欄位依條件出現或消失、標上必填記號、下拉只剩允許的選項、驗證錯誤送出前就顯示。
- 兩個人同時編輯同一筆時，後存的人會看到「資料已被其他人修改，請重新載入」，重新載入後再改。
- 下拉選單都能直接打字篩選選項；沒有符合時顯示「沒有符合的選項」。
- 附件欄位上傳檔案算一次「記錄更新」：模組設定的「記錄更新時」連動事件、跨記錄驗證與任務規則都會跟著跑，所以上傳可能觸發事件或任務，也可能因為驗證不過而被拒絕（這時剛上傳的檔案不會留下）。設計者請檢查既有規則的條件，確認不會因為只多了一個附件就觸發。簽核中、核准後與已記帳的單據不能增減附件，見 [§21.5](#215-核准後的鎖頭)。
- 用 API 上傳時如果帶 `Idempotency-Key`，重送時只比對檔名與檔案大小；同一把 key 重送同名同大小、內容不同的檔案，會回放第一次的結果，不會存第二份。換檔名或大小回 422。

### 7.3 歷程

明細頁最下面的「歷程」卡片列出這筆記錄的變更，最新的在最上面，每頁 20 筆：

- **新增、刪除**：一列「建立了這筆記錄」「刪除了這筆記錄」。
- **修改**：每個有變的欄位一列，顯示修改前與修改後的值。下拉顯示選項名稱、參照顯示對方的標題、使用者顯示名稱。一次存檔什麼都沒變，不會留下歷程。
- **明細列**：表頭的歷程也包含它的明細列，前面標「明細模組名稱 › 列標題：」，例如「訂單明細 › 甲：數量」。刪掉的明細列，歷程照樣看得到。
- **清空參照**：刪除被參照的記錄、而參照欄位設成「清空欄位」時，被清空的那筆記錄多一列修改，修改者是發起刪除的人。

幾點要注意：

- 公式、彙總、自動編號欄位由系統計算，它們的變化不記；設計器改公式觸發的重算也不記。
- 你看不到的欄位，它的歷程也看不到。例如沒有金額權限的人，看不到單價改了幾次。
- 參照的標題是看歷程當下查的：對方改名後，舊歷程也顯示新名稱；對方被刪除後顯示「（已刪除）」。

### 7.4 匯出

列表右上角「匯出」選 CSV 或 Excel，下載目前篩選、排序、搜尋後的全部記錄（不分頁）。需要「列印匯出」權限，沒有這個權限就看不到「匯出」按鈕。

- 欄位是你看得到的啟用欄位，依區塊與欄位順序；第一列是欄位名稱，不含記錄 id、擁有者與修改時間，所以匯出檔可以直接拿去匯入。
- 值和畫面一樣：下拉是選項名稱、是否欄位是「是」「否」、日期是 `2026-11-05`、參照是對方的標題。
- 沒有金額權限的人，匯出檔沒有金額相關的欄位（整欄不含，不是空白）。
- CSV 是含 BOM 的 UTF-8，Excel 直接打開不會亂碼。數字、百分比以外的欄位（文字、下拉、使用者、參照標題等）以 `=`、`+`、`-`、`@` 開頭時，前面加一個 `'`，避免 Excel 當成公式執行；匯回時會自動去掉。參照標題來自別的模組裡使用者輸入的文字，所以也要防。
- 一次最多 10000 筆，超過時會提示「匯出最多 10000 筆，請加篩選條件」。
- 檔名是「模組代碼-日期-時間」，例如 `p7-order-20261104-1549.csv`。

### 7.5 匯入

列表右上角「匯入」，選一個 CSV 檔。需要「新增」權限；擴充模組不能匯入。

1. 選好檔案後先預覽，不會寫入任何資料：
   - **檔案欄位與對應欄位**：表頭先比對欄位代碼（例如 `f_12`，設計器的欄位設定裡看得到），再比對欄位名稱（任一語系、不分大小寫）。略過的欄位會寫原因：「系統計算的欄位」（公式、彙總、自動編號）、「唯讀欄位」、「找不到這個欄位」；名稱同時對到好幾個欄位時是「對到多個欄位，請改用欄位代碼」，把表頭改成欄位代碼即可。兩欄對到同一個欄位時整個檔案退回，訊息是「欄位「名稱」重複」。
   - **共 N 筆，M 筆可匯入**，下面列出有錯的列：行號就是檔案裡的行號（表頭是第 1 行），可以直接對照檔案修改。
2. 有任何一列錯誤時，「確認匯入」不能按，畫面提示「修正檔案後重新選擇」。改好檔案再選一次。
3. 全部通過後按「確認匯入」，伺服器會重新檢查整個檔案，全部通過才一起新增；完成後顯示「已匯入 N 筆」。

值的寫法：

- 和匯出檔相同：下拉填選項名稱、使用者填帳號或名稱、參照填對方的標題（完全相同才算找到，同名多筆會報錯）、是否欄位填「是」「否」（也接受 true／false、yes／no、1／0）。
- 數字可以有千分位逗號（必須每三位一個，`1,234.5` 可以，`1,5` 會看到「請輸入數字」），百分比可以帶 `%`；日期可以是 `2026-11-05` 或 `2026/11/5`。
- 空白格視同沒填，欄位有預設值時套用預設值。
- 每筆的自動編號、擁有者（匯入的人）與歷程，都和手動新增一樣。
- 匯出再匯回不一定完全相同的情況：日期時間只到分鐘，秒數會變成 0；文字原本就以 `'=` 這類開頭時，匯回會少掉 `'`；選項名稱含 `;` 的多選會被拆開；同名的使用者用名稱對不到（改填帳號）；參照顯示「（無權限）」「（已刪除）」的格子匯回會找不到。

檔案限制：

- 必須存成 UTF-8 的 CSV。繁中 Windows 的 Excel「另存 CSV」預設是 Big5，會看到「請把檔案存成 UTF-8 的 CSV」；請改選「CSV UTF-8」格式。
- 檔案最大 1 MB、最多 1000 筆；空白列不算。
- 匯入只新增，不會更新既有記錄，也不含明細列。

### 7.6 核准後哪些欄位不能改

狀態機裡有「需簽核」的轉移時，單據核准後會進入「簽核鎖定」的狀態。在這些狀態裡：

- 簽核流程的條件、簽核人用到的欄位，以及這些欄位的公式、彙總、帶值來源，還有簽核人可編輯的欄位，都不能再改。
- 備註這類不影響簽核的欄位照常可以改。
- 模組有附件欄位時，附件一律鎖定：核准後不能再增減，簽核中與已記帳的單據也一樣（見 [§21.5](#215-核准後的鎖頭)）。
- 公式與彙總欄位保留核准當時的值：改備註這類存檔不會重算它們；設計者修改公式、或新增、修改、重新啟用彙總欄位時的整批重算，也會跳過簽核中與已核准的單，連同它們的明細列，保留核准當時的值。例外：其他模組的彙總更新到這張單時，這張單的公式會用目前的定義重算（見 [§9 已知限制](#9-已知限制)）。
- 如果鎖定欄位還用到本單明細的彙總，明細列也一起固定，不能新增、刪除或修改。
- 想改鎖定欄位時，先把單據轉回可編輯的狀態並存檔，再改欄位。同一次存檔又轉回可編輯、又改鎖定欄位會被擋下，要分兩次存。轉回可編輯之後才執行的連動事件寫入，不受鎖定影響；事件如果在轉回之前、或同一筆寫入裡就改鎖定欄位，一樣會被擋下。

被擋下時，表單會顯示「這個欄位已經過簽核，要修改請先退回可編輯的狀態」，後面括號帶欄位名稱（明細列被動到時帶明細的名稱）。連動事件、整合或其他模組的寫入如果會改到鎖定欄位，整次動作都會取消。其他模組的彙總更新到這張單的彙總欄位，仍然允許。

## 8. 範例：模具維修申請

這是[第 4 階段驗收](acceptance/phase4.md)實際走過的情境，截圖都在 `docs/acceptance/phase4/`。

1. 設計器新增模組 `repair-request`（模具維修申請）。
2. 欄位：
   - 申請人（文字，必填）
   - 申請日、需求日（日期）
   - 故障類別（下拉：模具損壞、機台異常、外包）
   - 故障細項（下拉：模仁崩裂、頂針斷裂、油壓異常、加熱失效、委外修復）
   - 外包廠商（文字，必填）
   - 預估費用（金額）
   - 狀態（下拉：草稿、已結案）
3. 加公式欄位「距需求日天數」：`DATEDIFF({需求日的編號}, {申請日的編號})`，結果型別為數字、小數位數 0。
4. 加自動編號欄位「申請單號」：`REP-{yyyyMM}-{0000}`，並設成記錄標題。
5. 規則分頁新增：
   - 顯示：故障類別 等於 外包 → 外包廠商。外包廠商本身設了必填，但被隱藏時不檢查，所以只有選外包時才必填。
   - 驗證：任一符合「需求日是空的、需求日 大於等於 申請日（另一個欄位）」→ 需求日，訊息「需求日不得早於申請日」。
   - 選項限制 3 條：模具損壞 → 模仁崩裂、頂針斷裂；機台異常 → 油壓異常、加熱失效；外包 → 委外修復。
   - 唯讀：狀態 等於 已結案 → 整筆記錄。
   - 必填：預估費用 大於 1000 → 外包廠商。
6. 按「儲存規則」，再到「權限」分頁給「現場人員」讀取、新增、修改，不給金額，資料範圍全部。
7. 啟用模組，登出後用不同帳號登入實際操作：
   - 選外包才出現外包廠商；故障細項只剩對應的選項。
   - 需求日早於申請日時，送出前就擋下。
   - 存檔後明細顯示 `REP-202611-0001` 與天數。
   - 狀態改成已結案存檔，再打開編輯時整張唯讀。
   - 切到現場人員，表單沒有預估費用，其他規則照樣作用；引用預估費用的必填規則不會送給他。

## 9. 已知限制

目前刻意不處理、或正式上線前要再確認的事，完整清單見設計文件 §15。和操作直接相關的：

- 沒有寄信重設密碼，忘記密碼只能由管理員重設。
- 沒有公司帳號（AD、SSO）登入，也沒有雙因素驗證與自助註冊。
- 舊資料庫裡的使用者沒有密碼，無法登入；要由 `admin` 逐一重設密碼，或直接刪庫重建。
- 列表的「使用者」欄位仍顯示帳號，不是姓名。
- `Demo__LoginEnabled` 絕不能在正式站開啟，開了就等於不驗密碼就能登入。
- 設計者改了已核准單據的公式後，單據上的公式欄位只保留到「別的模組的彙總又更新到這張單」為止：例如採購單核准後，設計者把「折扣後總額」改成含稅，之後新增一筆付款單、採購單的「已付金額」彙總跟著重算時，「折扣後總額」會一併用新公式重算。要避免，改公式前先確認沒有這類彙總會流進已核准的單據。
- 登入失敗的計數用程序內的鎖保護，假設每家客戶只跑一個後端 instance；多個 instance 並行時要改成資料庫層的原子更新。
- Docker 部署要把資料庫目錄（預設 `/app/data`）掛成 volume，登入用的金鑰才會保留；沒掛的話，每次重建容器所有人都要重新登入，資料也會一起清空。
- Swagger 只在 Development 環境開放，正式站沒有。
- 直接呼叫 API 仍可把記錄指派給已停用的使用者；畫面上選不到。
- 在 Render 上，反向代理後 cookie 帶 `secure; samesite=lax; httponly`（2026-11-05 實測）。

- 前端的「今天」用電腦本機日期，後端用台灣時間；不在 UTC+8 的電腦，跨日前後可能和伺服器差一天（§15 第 26 條）。
- 自動編號在 SQLite 上不會重號；換成 SQL Server 時要另外處理同時取號（§15 第 23 條）。
- 修改公式會在一次交易內重算整個模組的記錄，期間有人正在編輯的話，會看到「資料已被其他人修改」（§15 第 21 條）。
- 同時被規則隱藏、又受選項限制的下拉欄位，若留著超出範圍的舊值，會卡住存檔，要先把上層欄位改回去並清掉它（§15 第 27 條）。
- 既有實體（目前只有客戶）不檢查權限，任何登入的人都挑得到（§15 第 28 條）。
- 連帶刪除只看你對發起刪除的那筆有沒有刪除權，不檢查被連帶刪除的來源模組（§15 第 29 條）。
- 刪除被參照的記錄時，若同時有人新增參照或修改來源記錄，SQLite 上不會出事，換成 SQL Server 要另外處理（§15 第 31 條）。
- 彙總計入所有子記錄，不看讀者的資料範圍，只看得到本人資料的人可以從合計推測別人的記錄（§15 第 32 條）。
- 子記錄存檔會重算並更新父記錄，正在編輯父記錄的人存檔會收到「資料已被其他人修改」（§15 第 33 條）。
- 逐列編輯明細時，金額與合計要存檔後才更新（§15 第 34 條）。
- 公式、彙總、自動編號的變化，以及系統重算，都不寫歷程（§15 第 38 條）。
- 歷程裡的參照標題是現在的名稱，不是當時的名稱；對方刪除後顯示「（已刪除）」（§15 第 39 條）。
- 匯入只新增、不更新，不含明細列；擴充模組不能匯入（§15 第 40 條）。
- 匯出上限 10000 筆、匯入上限 1000 筆（§15 第 41 條）。
- 沒有金額權限時，匯出檔整欄不含金額欄位，而不是留空（§15 第 42 條）。
- 設計器預覽看不到還在草稿的明細模組（§15 第 44 條）。
- 選單分區可以填四種語系，切換語系時顯示該語系的名稱，沒填的語系顯示繁中。分組一律依繁中名稱，不同應用程式的同名分區會合成一組。升級前就開過的內建套件，分區不會自動補上譯名，要在設計器補填或重新開啟套件。
- 範本只帶群組權限，欄位權限、選項範圍、個人權限要建好後自己補（§15 第 47 條）。
- 匯入的範本不能刪除或覆蓋，同代碼再匯入會被拒（§15 第 48 條）。
- 範本改了，已經從範本建出的模組不會跟著更新（§15 第 49 條）。
- 匯出範本時表達不了的引用直接略過，只寫在檔案的 `warnings`（§15 第 50 條）。
- 匯入範本只檢查結構，型別設定的錯誤要到從範本建立時才發現（§15 第 51 條）。
- 「預設今天」在表單用電腦本機日期，伺服器用台灣時間（§15 第 52 條）。
- 「帶表頭的值」只在新增明細列時帶入，改表頭不會更新既有明細（§15 第 53 條）。
- 從範本建立是逐條重播設計器指令，新模組的版本號一開始就大於 1（§15 第 54 條）。
- 產生 Demo 資料期間（本機約數十秒），整個 SQLite 資料庫由一個寫入交易鎖住，其他人的寫入要等它結束，等太久會逾時（見 [§10](#10-系統管理demo-資料)）。
- 「已產生」只看四組範本的模組代碼是否都存在，沒有另外的標記；部分存在時整批不做，也不提供補齊或清除。
- 品質異常範本需要庫裡已有 `order` 模組，沒有時套用失敗。
- 欄位層權限（重大只有品保能選、責任單位對業務唯讀、不良率對現場人員隱藏）與選項範圍是 Demo 產生器補的；單獨「從範本建立」這三個新範本時沒有，和訂單範本一致。
- Demo 的反向關聯只示範在更換零件、訂單的品質異常、報修單的關聯報修單。
- Demo 資料的稽核時間是模擬的，最晚到昨天；「建立時間」不是真實產生的時間。

## 10. 系統管理：Demo 資料

系統管理員可以一鍵產生一批像真的業務資料，用來示範、試用或教育訓練。入口是左側選單「系統管理 → Demo 資料」。各情境怎麼示範見 [Demo 腳本](demo.md)。

**會產生什麼**：訂單、故障報修、模具保養（含 MES 自己的模組 mes-mold「模具資料」）、品質異常四組模組，加上共用主檔的往來對象與聯絡人（CRM 的十家客戶、MES 的八家客戶、進銷存的三家供應商與四家客戶；CRM 十位聯絡人裡有幾位換過公司、任職經歷有兩到三列，進銷存每家供應商與客戶各一位聯絡人），共數百筆記錄；CRM 另有三筆設計案，含虛構的設計圖與留言附件，Demo 站雖然停用上傳，這些檔案由產生器在伺服器端寫入，可以看、可以下載（劇本見 [§22](#22-demo-劇本crm-設計案與簽核)）。不是 Demo 站、但自己把上傳關掉（`Attachments__UploadEnabled=false`）的環境也一樣：按「產生 Demo 資料」仍會寫入這 8 個內容固定的示意圖檔（約數十 KB），要有設計者權限才能觸發；磁碟唯讀或不允許存檔的環境請不要產生含設計案的 Demo 資料；記錄的建立者、日期與變更歷程都是模擬的，日期以產生當天為基準往前展開，所以任何時候打開都有逾期與本週到期的資料。同一天產生兩次內容相同。

**狀態**

| 狀態 | 畫面 | 按鈕 |
|---|---|---|
| 尚未產生 | 「尚未產生」 | 可按 |
| 產生中 | 「產生中（已完成／總步數）」 | 停用，轉圈 |
| 已產生 | 「已產生」 | 停用 |
| 已有同代碼的模組 | 列出衝突項目，例如「模組代碼 order 已存在」 | 停用 |
| 產生失敗 | 紅字顯示失敗原因 | 可再按 |

剛開始總步數還是 0，這時只顯示「產生中」，不顯示已完成與總步數。

**操作**

0. 登入頁要列出 Demo 帳號，需要 `Demo__LoginEnabled=true`（只限 Demo 站，見 [§9](#9-已知限制)）。
1. 以 `admin` 開「系統管理 → Demo 資料」，按「產生 Demo 資料」。
2. 看進度到「已產生」。整批在同一個交易裡，任何一步失敗就整批回滾，不會留下殘缺資料。
3. 左側選單出現四組模組：訂單、故障報修、模具保養紀錄與品質異常，MES 自己的模組 mes-mold「模具資料」，以及「主檔」分區的往來對象與聯絡人。

**注意**

- 要有設計器的新增與修改權限才能按；沒有時按鈕顯示但停用。
- 只在三個內建應用程式的模組代碼都不存在、三個應用程式都還沒開啟時才產生；共用主檔還沒開啟的話，它的模組代碼（`master-partner`、`master-contact`、`master-employment`）也不能已被別的模組用掉。任何一項不符就整批不做，並列出衝突項目，例如「模組代碼 master-partner 已存在」，不覆寫既有資料。
- 部署時設環境變數 `Demo__SeedOnStartup=true`，站台啟動後會在背景自動產生（本機預設關閉）。失敗只寫 log，不影響站台啟動。Render 改用 `poc/Dockerfile.demo`，在建置映像時執行 `--generate-demo-data` 產生好資料，失敗就建置失敗、舊版繼續運作；代價是資料日期停在建置那天。
- 沒有清除或重設按鈕：本機停止服務後刪 `poc/backend/data/poc.db`；Render 重啟就回到映像裡的 Demo 資料。

Demo 登入：設環境變數 `Demo__LoginEnabled=true`（Render 設定檔已開啟，預設關閉，啟動時 log 會印 Warning）。登入頁會多列一份帳號清單，點一下就以該身分登入，不驗密碼；換人要先登出再點另一個帳號。清單只列啟用中的 Demo 帳號加上 `admin`。Demo 資料還在產生時，清單只有 `admin`，並顯示「正在產生 Demo 資料，完成後這裡會出現可用的帳號」。Demo 模式下 `admin` 不會被強制改密碼。Demo 帳號沒有密碼，不能用密碼登入。

## 11. 系統管理：使用者

本節的「重設密碼」、編輯既有使用者與「已鎖定」標示未實機驗證（走查時沒有在畫面上操作）；新增使用者（含加入兩個群組）已實機驗證。停用使用者是用 API 驗證，沒有在畫面上按停用鈕。

左側選單「系統管理 → 使用者」，只有系統管理員看得到，伺服器端也會檢查，否則回 403。可以有多位系統管理員。

欄位有帳號、姓名、群組（可多個）、狀態（啟用或停用）、系統管理員，另外會標示已鎖定的帳號。

- **新增**：填帳號、姓名、初始密碼與群組。帳號存小寫，格式是 2 到 50 個英數字或 `.`、`_`、`-`，建立後不能改，因為記錄、歷程與檢視都用它關聯。新使用者第一次登入必須改密碼。帳號重複會顯示錯誤。
- **編輯**：點使用者那一列（手機是整張卡片）開啟編輯，可改姓名、群組、是否為系統管理員。列上保留停用、啟用與重設密碼按鈕，按它們不會開啟編輯。
- **重設密碼**：管理員輸入新的臨時密碼，同時解除鎖定、要求改密碼，並讓這個人既有的 session 失效。
- **停用與啟用**：不提供刪除。停用後不能登入，既有 session 在下一個請求就失效，也不再出現在使用者欄位的下拉選項與權限畫面的挑選清單；舊記錄與歷程仍正常顯示名稱。
- **防呆**：不能停用或取消最後一位啟用中的系統管理員，也不能停用自己，兩者都由伺服器擋。

一個人可以同時屬於多個群組，他的模組權限是各群組授權的合併。權限本身不在這裡設，沿用各模組的權限分頁。匯入 CSV 時，使用者欄位只接受啟用中的帳號。

## 12. 系統管理：群組

本節只實機驗證了新增群組，改名、維護成員、刪除群組的影響對話框與擋下，都未實機驗證（由前端單元測試與後端測試涵蓋）。

左側選單「系統管理 → 群組」，權限同上。欄位是名稱與成員數。

- **新增**：只填名稱，內部代碼由系統產生（`g-` 加短亂碼），不可改。
- **編輯**：點群組那一列開啟同一個編輯對話框，名稱與成員都在這裡改，按一次儲存。名稱只編輯目前語系，其他語系沒填就用既有的備援。成員也可以從使用者那邊改，兩邊是同一份資料。列上只留刪除。
- **刪除**：按下後先列出影響，包括成員數、有授權的模組、欄位例外與資料範圍的筆數。若有欄位的選項範圍還指定這個群組，會直接擋下並列出是哪個模組的哪個欄位選項，要先到模組權限移除。這是因為選項範圍一移除，該選項可能變成所有人都能選，等於放寬權限。其他情況確認後，成員對應、模組授權、欄位例外與資料範圍會在同一個交易裡一起刪除。
- 刪除帶有「隱藏」或「唯讀」欄位例外的群組，也可能放寬權限；對話框會寫明「成員會失去這個群組的授權與限制」，但不擋。
- 範本用群組代碼指定權限建議；全新安裝沒有這些群組時，會略過並顯示警告，不影響建立。

## 系統管理：政策設定

左側選單「系統管理 → 政策設定」，只有系統管理員看得到。這裡集中調整「上限、預設值」這類業務政策，不必改程式或設定檔。目前登記的政策依分類列出（任務、通知、附件、地區與語系、維運、簽核），每一項顯示名稱、說明、出廠值、允許範圍。

- **改值**：改完按該列的「儲存」；存檔時伺服器會檢查允許範圍，不合法的值會在該列下方顯示訊息，輸入保留讓你修改。
- **恢復出廠值**：已經改過的項目才會出現「恢復出廠值」，按下後回到出廠值。
- **可模組覆寫**：有這個標籤的項目，模組設計者可以在該模組的設計頁另外設定；沒有標籤的項目只有全系統一個值。
- **改嚴只管之後**：把上限調低，不會動到已存在的資料。例如每個模組的任務規則數上限改成 1，已有 3 條規則的模組，既有規則照常可以修改，只是不能再新增。
- 目前接上的政策：每個模組的任務規則數上限（出廠 20）、每條規則產生的任務數上限（出廠 20）、一個套件內的任務規則總數上限（出廠 50，匯入或開啟應用程式套件時檢查）；到期前幾天提醒（出廠 1，範圍 1 到 30）、提醒逾期（出廠開）；新留言、任務完成、任務取消各自通知誰（見[§16](#16-站內通知)）；通知保留天數（出廠 90，範圍 1 到 3650，只能全系統設定）；一週從星期幾開始（出廠星期一，只能全系統設定）。
- **維運政策**（分類「維運」，都只能全系統設定）：慢請求門檻（毫秒，出廠 2000，範圍 200 到 60000；請求超過這個時間會在系統 log 記一則警告）、收集前端錯誤（出廠開；開啟時，使用者畫面上發生的程式錯誤會記進系統 log，供管理員與廠商排查；錯誤原文可能帶到畫面上的少量文字，log 請視同敏感資料保管）。這兩項改值後**最多 60 秒生效**。
- **附件政策**：單檔大小上限（位元組，出廠 10485760，也就是 10 MB，範圍 1 到 52428800）、每個附件欄位的檔案數上限（出廠 20，範圍 1 到 100）、每則任務留言的附件數上限（出廠 5，範圍 1 到 10），這三項可由模組覆寫；允許的副檔名只能全系統設定（出廠 pdf、png、jpg、jpeg、webp、txt、csv、docx、xlsx、pptx，最多 40 個，每個 1 到 10 個小寫英文或數字，大小寫不分、可帶前導點）。
  - **部署設定檔的值是該環境的出廠值**：設定檔 `Attachments` 節的 `MaxBytes`、`MaxFilesPerField`、`AllowedExtensions` 有寫，就當作這個環境的出廠值（畫面上的「出廠值」顯示的就是它），在政策設定改過之後以畫面為準，「恢復出廠值」回到設定檔的值；超出允許範圍的設定值會在啟動時記一則 Warning 並夾到範圍內。見[部署說明](deploy.md)。
  - **危險副檔名一律不收**：網頁、腳本與可執行檔（html、htm、xhtml、svg、js、mjs、exe、msi、bat、cmd、com、scr、ps1、sh、jar、vbs、dll、app、dmg、php、asp、aspx、jsp）寫死不開放。白名單裡放了這些會存不了，畫面會列出被拒的副檔名；部署設定檔裡的這類項目會被丟掉並記 Warning。需要收這類檔案要改程式，不是改設定。
  - **改嚴只管之後**：縮小副檔名清單不影響已上傳的檔案，仍可下載；把檔案數上限調到比現有數量還低，已有的檔案照常可看、可刪，但不能再上傳，要刪到低於上限才能再傳。單檔大小與留言附件數看的是「任務（或記錄）所屬模組」的生效值，沒有所屬模組的個人任務用全系統值。
- **簽核政策**（分類「簽核」，出廠值等於政策化之前的固定值，沒人改設定時行為不變）：
  - 每個流程的關卡數上限（出廠 10，範圍 1 到 20）、每一關的簽核人數上限（出廠 20，範圍 1 到 50）、每一關的逾期時數上限（出廠 8760，範圍 1 到 8760）、主管來源的層數上限（出廠 5，範圍 1 到 10）、發起人可以簽核自己的單（出廠關）、找不到簽核人時的備援對象（出廠為全部系統管理員，見下方「收件人政策」）；這六項可由模組覆寫（見下方「模組的『政策』分頁」）。
  - 簽核意見的字數上限（出廠 1000，範圍 1 到 1000，因為資料庫欄位只有 1000 字，只能調低）、簽核異常通知對象（出廠為全部系統管理員）、系統管理員可以略過狀態轉移的群組限制（出廠開）只能全系統設定。後者只管「狀態轉移」上設定的限定群組，系統管理員的其他權限不受影響；關掉後，限定群組的轉移連系統管理員也要在群組內才能走，包括送出簽核、送出前預覽與可選的目標狀態。事件與簽核完成後的自動轉移不受影響。
  - **改嚴只管之後**：關卡數、人數、逾期時數、主管層數調低後，已存的流程照常可用、原樣再存也不會被擋；只有「超過新上限、而且比目前版本更多」的新增或修改才會被擋（例如上限調成 3，既有 5 關的流程改名可以存，加到 6 關不行）。意見字數調低只影響之後送出的意見。
  - **執行時的上限**：每一關的簽核人數，關卡本身的來源（群組、主管、使用者欄位與發起人自選挑的人）依「該關啟動當下」的設定檢查，超過時簽核動作回 409 並說明上限；來源是固定指定使用者的關卡，存檔時已檢查過，執行時只受技術上限 50 人限制，不會因為之後調低設定而卡住進行中的單據。頂替的備援簽核人（流程的備援名單，或政策預設的備援對象）不計入每關人數的當下上限，只受技術上限 50 人限制，但整關合計（關卡來源加頂替的備援，去重後）仍不超過 50 人，超過時簽核動作回 409：例如自選關卡選滿 20 人、上限也是 20，其中一人被停用而由 2 位備援頂替，這一關仍能啟動。發起人自選的關卡，送出時就先檢查人數：上限取「存檔的上限」與「當下的上限」中較小的一個，超過回 400 並標在自選欄位上；若存檔的最少人數大於有效上限，最少人數也改用有效上限。例如自選關卡存的是最少 12、最多 15 人，之後上限調成 10：畫面顯示選 10 位，選 10 位可以送出，選 11 位回 400。已送出的單據若之後才進入自選關卡，而上限在這段期間又調低，該關啟動時仍依當下上限檢查，超過回 409，要由發起人撤回後重選。主管層數執行時只受技術上限 10 層限制。
  - **收件人政策**：「找不到簽核人時的備援對象」與「簽核異常通知對象」的值是一組收件人，每項是「全部系統管理員」、一個群組或一位使用者，最少 1 項、最多 20 項，畫面用可搜尋的多選欄位選取。存檔時系統會檢查群組與使用者存在、使用者仍啟用，找不到或已停用的項目會被拒絕並列出；之後若有人被停用，政策頁會把該項顯示為「找不到或已停用」。備援對象只在流程自己沒設備援簽核人時使用，也只影響之後產生的待簽，已建立的任務不變；解析出來沒有人（例如指定的使用者都被停用）時，這一關和一般找不到簽核人一樣回 409。異常通知對象解析為空時，為了不讓異常沒人知道，會改通知全部系統管理員並在系統 log 記一筆警告。被這兩項政策（含模組覆寫）引用的群組不能刪除，刪除時會列出引用的政策代碼；被模組覆寫引用時另附模組 key。部署設定檔層的出廠值不在檢查範圍。異常通知的標題含單據標題，所以通知對象若不是管理員，會看到單據標題（只有系統管理員能設定這項）。收件人政策不會出現在一般使用者讀得到的生效值 API。
  - **發起人自簽**：關閉時（出廠），發起人會自動從關卡簽核人名單中移除；開啟後發起人若在名單內，要自己按「同意」，流程才算他那一票，不會自動同意。關卡名單與備援簽核人名單的規則相同：開啟時兩者都保留發起人，關閉時兩者都移除。主管來源仍是往上找發起人的主管，不受這一項影響。

**模組的「政策」分頁**

設計器的模組編輯頁有「政策」分頁（明細模組沒有），列出可覆寫的政策。每項二選一：「沿用全系統（目前值）」會跟著系統設定變動；「覆寫為」則只在這個模組用自己的值，可以比全系統寬，也可以比全系統嚴。簽核類可覆寫的有六項：關卡數、每關人數、逾期時數、主管層數、發起人自簽、找不到簽核人時的備援對象。之後調整全系統值，不會改到已經覆寫的模組；改回「沿用全系統」才會再跟著走。有設計器編輯權限的人可以改，共用主檔模組另需系統管理員；只有讀取權限的人看得到但不能存。

## 13. 報表

左側選單「報表 → 我的報表」列出自己建立的與別人分享給我的報表。報表依觀看者自己的權限計算，所以同一張報表，不同人打開看到的數字可能不同。

### 一列代表什麼

每張結果上方都寫「每列代表：一筆訂單」或「一筆訂單明細」。沒有合併子模組時，一列是一筆主模組記錄；合併了子模組，一列是一筆子記錄（例如一筆訂單明細）。沒有子記錄的主記錄仍保留一列，子欄位是空的；但條件如果設在子欄位上，會先篩子記錄，沒有符合子記錄的主記錄（包含本來就沒有子記錄的）那一列會消失。

### 建立報表（五個步驟）

1. **選資料**：選主模組，可選擇合併一個子模組（主模組的明細模組，或有參照欄位指回主模組的模組；有多個參照欄位時要指定用哪個）。明細模組不能當主模組。同時合併兩個子模組會互相相乘，所以不提供。
2. **選欄位**：分成主模組欄位、沿參照帶出的欄位、子模組欄位。只列你看得到的欄位。
3. **設條件**：每個條件是「欄位、運算子、值」，條件之間一律是「而且」（沒有「或」）。參照欄位用記錄挑選器選值。另外可指定「主要日期欄位」與日期區間（今天、本週、上週、本月、上月、今年、去年、近 N 天／週／月）。區間以基準日換算，不是瀏覽器的日期；一週從星期幾開始依「政策設定」的「一週從星期幾開始」，出廠是星期一，改了之後報表與儀表板的本週、上週、近 N 週結果會跟著變（依週別分組的標籤仍採 ISO 週，格式如 2026-W45，不受影響）。設了日期區間就必須有主要日期欄位。
4. **分組與彙總**：分組欄位、數值與彙總方式（加總、平均、最小、最大、主記錄筆數、子記錄筆數、條件占比）。不設分組就是明細報表。加總與平均只限數字型別，最小與最大也可用在日期。條件占比是符合條件的筆數除以總筆數，適合做達成率。
5. **預覽與儲存**：看結果、切換呈現方式（表格、指標、折線、長條、環圈）、命名、儲存。

分享要先儲存才有對象可分享，所以在儲存後的結果頁按「分享」，不在設計器裡。分享對話框列出所有群組的名稱，任何登入的使用者都看得到群組名稱（只有名稱，沒有成員與權限）；載入失敗時對話框會顯示錯誤與「重試」，不會是空的。

結果頁的「重新預覽」會用目前的設定再算一次。

### 合併後的數字：去重與「明細列相加不等於總計」

合併子模組之後，一筆訂單會有多列明細。主模組的欄位（例如訂單的稅率、訂單金額）在彙總時，每筆主記錄在每個分組內只算一次，用記錄的 `Id` 判斷。例如一張訂單分三次出貨，合併後訂單金額加總仍是原金額，不會變三倍。

這有一個必須知道的代價：列相加或下鑽列數對不上總計時，結果下方會顯示「總計每筆記錄只算一次；同一筆可能出現在多列或多個分組，所以各列相加不一定等於總計」。依子模組欄位分組時，同一筆訂單可能落在多個分組，每組各算一次，所以**各組相加可能大於總計**；總計一律獨立去重重算，不是把各組加起來。把下鑽的明細列加起來，同樣不會等於這個數字。

會出現這段說明的情況：

- 合併了子模組，且彙總了主模組欄位（加總、平均）或用了主記錄筆數。
- 依多選欄位分組，且用了加總、平均或筆數：一筆記錄有兩個選項就算進兩組。彙總的是主模組或子模組欄位都一樣。

最小、最大與條件占比不是相加出來的，不會顯示。

筆數分「主記錄筆數」與「子記錄筆數」，要依想問的問題選。

### 權限

- **模組**：要有該模組的讀取權限。非明細的子模組與參照目標各自授權。
- **記錄**：只算你資料範圍內的記錄；你看不到的子記錄不計入。
- **欄位**：報表任何地方（欄位、分組、彙總、條件、排序、帶出欄位）用到你看不到的欄位，整張報表顯示「無權限檢視：隱藏欄位」，不回部分結果。這包含條件：否則可以用篩選條件猜出隱藏欄位的值。條件用到你讀不到的帶出欄位、或參照目標模組讀不到時，也一樣整張擋下。
- **金額**：金額權限只管「金額」型別的欄位與結果為金額的公式；型別設成「小數」的金額不受控（既有行為）。沒有金額權限時，用到金額的報表整張無權限。
- **彙總欄位不能用**：彙總欄位存的是全域值，不看讀者的範圍，所以不列入報表欄位，引用彙總欄位的公式也一樣。要這個數字，請改成合併子模組自己加總。
- **規則隱藏不算權限**：表單規則造成的隱藏，報表不套用，和列表一致。

### 看到別人的報表

打開別人分享的報表只能看，不能改。

- **隱藏條件**：報表的條件用到你看不到的欄位，或你沒有模組讀取權限時，條件列表只顯示「隱藏條件」，不顯示欄位和值。看得到有條件，但看不到內容；擁有者自己也一樣。
- **不能另存**：看不全定義的人不能「另存為我的報表」，畫面顯示「這張報表用到你看不到的欄位，無法另存」。另存不會悄悄移除你看不到的條件，那樣會改變報表的意思。
- **系統管理員**：看得到並可以刪除所有共用報表，但**不能編輯、不能改別人的分享**；要改只能另存或刪除。
- **擁有者被停用**：報表留著，分享照常。

### 下鑽與匯出

點結果表格的某一列（或圖表的某個分組）會開「明細」，用同一套範圍與欄位過濾，最多 500 列。沒有分組的明細報表畫面上最多顯示 1,000 列，並提示總列數；總計依全部列計算，要看全部的列請用匯出，匯出不受這個上限影響。「匯出 Excel」要有所有涉及模組的列印匯出權限，沒有的人，「匯出 Excel」按鈕會停用並提示沒有匯出權限（是否有權限由後端判斷，與實際匯出時的檢查相同）；匯出檔含總計與上述說明，比例與百分比用 Excel 的百分比格式，用意是不讓報表變成繞過匯出權限的路。

### 資料量上限

有兩個上限，超過都不回部分結果：

- **合併後 5 萬列**（`Reports:MaxRows`，預設 50000）：合併且套用條件之後的列數超過就停止，顯示「資料太多，請縮小條件」。這裡縮小條件有用。
- **載入 20 萬筆**（`Reports:MaxLoadRows`，預設 200000）：單一來源模組（主模組或子模組）在你範圍內的記錄超過就停止，顯示「來源資料超過系統的載入上限，縮小條件也無法改善，請聯絡管理員」。條件要載入後才能套用，所以這個上限縮小條件也過不了；它只用來防止記憶體用盡。

### 資料基準日

報表的「今天」是基準日。一般情況用台灣時間的今天。Demo 站（`Demo__LoginEnabled`）的資料日期停在映像建置那天，所以報表以產生日當基準日，當它和今天不同時，結果旁標示「資料基準日 yyyy-MM-dd」，「近 90 天」這類區間也是從那天往前算。

### 幣別

系統沒有幣別欄位，「幣別」只是一般下拉，與金額欄位沒有關聯，報表無從判斷。第一版金額直接相加。**混用幣別時，請依幣別欄位分組，或用條件篩出單一幣別**，否則會算出沒有意義的數字。

### 欄位或模組被改之後

報表定義存的是欄位 ID，欄位改名不影響。欄位被停用或沒有權限時，結果顯示「欄位已不存在：X」，在設計器裡也會標示「不可用」，要先把它移除才能繼續與儲存。模組停用則顯示「模組已停用」。公式的結果型別改變，讓已存的量值或條件對不上（例如數字改成日期後的加總），結果顯示「欄位型別已變更：X」，不會算出空結果或假數字；到設計器重選欄位或條件值即可。

### 已知限制與路線圖

- 載入上限：來源模組超過 `Reports:MaxLoadRows` 的報表跑不出來，縮小條件也一樣；之後要放大時，方向是先用索引縮小記錄。
- 帶出實體標題的條件用挑選器比對鍵，不能用文字搜尋標題。
- 圖表模式的三條 y 軸（比例、日期、一般數字）並存時，手機寬度下繪圖區會變窄。
- 之後要做：**幣別綁定**（讓金額欄位指定幣別欄位，混幣別時自動分組）、**結果快取**（放大資料量時，先用索引縮小記錄再快取結果）。

## 14. 儀表板

儀表板是一組卡片，每張卡片是一張報表的一種呈現。左側選單「報表 → 儀表板」進入；只要有儀表板，首頁也會直接顯示（上次開的那張，沒有紀錄就是第一張），沒有任何儀表板時首頁維持原樣。卡片依**觀看者**的權限計算：同一張儀表板，業務主管與業務看到的數字不同，現場人員沒有金額權限的卡片只顯示「無權限檢視」，其他卡片不受影響。

### 兩種儀表板

- **指派版**：系統管理員建立並指派給群組，所屬群組的成員都看得到，依管理員排的順序列在前面。
- **我的儀表板**：自己建立，只有自己看得到。卡片只能放你看得到的報表（自己的或分享給你的）。

### 編輯版面

按「編輯版面」進入編輯狀態：拖曳卡片標題移動、拉邊角調整大小、「新增卡片」放上報表、卡片右上角的設定與關閉。每次放開滑鼠或確認設定就立刻存檔，沒有「儲存」鈕。版面是 12 欄的格子，一張儀表板最多 40 張卡片。手機寬度（小於 600px）卡片排成單欄、由上到下，不能拖曳；清單預設收合。

### 卡片設定

| 設定 | 作用 |
|---|---|
| 標題、呈現方式 | 預設用報表名稱與報表的呈現方式，改了只影響這張卡片 |
| 日期區間 | 設了就以卡片為準（見下方「日期的優先順序」） |
| 只顯示前 N 名 | 1 到 100。不會把其餘合成「其他」；總計仍是**全部**分組的合計，所以前 N 名相加可能小於總計 |
| 排序依據、由大到小 | 覆蓋報表原本的排序 |
| 累計占比 | 只有長條圖。依第一個量值由大到小排序，每一格顯示累計占比；分母是全部分組的合計，不受前 N 名影響 |
| 與前幾期比較 | 只有指標卡，1 到 12 期。拿前面「同樣長度」的區間算平均，顯示變動百分比；前期平均為 0 時只顯示平均 |
| 點擊後前往的儀表板 | 目標儀表板觀看者看不到時，不顯示連結 |

點圖表或表格的某一組會開明細，與報表的下鑽一樣。

### 日期的優先順序

卡片的區間 > 儀表板上方的暫時日期篩選 > 報表自己的區間，**只取一個，不會交集**。例如報表是「近 90 天」，儀表板篩選選「本月」，沒設區間的卡片就算本月；設了「近 30 天」的卡片仍算近 30 天，並註明「這張卡片有自己的日期區間，不受上方日期篩選影響」。暫時篩選只在目前畫面，不存檔，也不算「調整」。

### 個人調整版與還原最新版

指派版的成員也可以編輯版面。第一次調整時系統替你另存一份個人版，其他人不受影響，儀表板旁標示「已調整」。之後管理員更新了指派版，你的個人版不會被覆蓋，而是顯示「已更新」與「還原為最新版」；按下並確認後，捨棄你的調整、改用管理員的最新版。

### 卡片的特殊狀態

- 「報表已不再分享給你」：你自己放上的卡片（自己的儀表板，或在指派版的個人調整版上靠分享加入的卡片），報表被取消分享。指派版給的卡片不看分享，照樣執行，但仍依你的權限計算；即使管理員之後把那張報表從指派版移除，你的個人版保留的卡片仍可顯示。
- 「報表已被刪除」：卡片引用的報表不在了，可以把卡片移除。
- 刪除報表時，如果有儀表板引用，系統會列出哪些儀表板並擋下；只有擁有者自己儀表板上的卡片會隨報表一起移除。
- 單張卡片載入失敗只影響那一張，有「重試」。

### 系統管理：儀表板指派

管理員在「系統管理 → 儀表板指派」新增、改名、刪除指派版，用上下移調整順序，勾選要指派的群組，編輯版面（這裡的卡片只顯示報表名稱與呈現方式，不執行查詢）。存檔時帶版本號，若別的管理員剛更新過會顯示衝突訊息，重新選取後再改。取消指派後成員看不到該儀表板，個人調整版保留，重新指派時恢復。刪除群組前的影響清單會列出已指派給它的儀表板。

## 15. 任務

任務是平台共用的待辦：可以掛在任何模組的一筆記錄上（記錄任務），也可以不掛記錄（個人任務）。任務不是動態模組，欄位固定。

**欄位**

- 標題（必填，200 字以內）、說明、負責人、到期日、狀態。
- 狀態有「待辦」「進行中」「已完成」「已取消」，任何狀態之間都能直接切換。在清單上取消勾選已完成的任務，一律改回「待辦」。

**建立**

- 記錄任務：在記錄詳細頁的「任務」區塊按「新增任務」，負責人預設是自己，可以改成任何啟用中的使用者。看得到這筆記錄的人就能新增。
- 個人任務：在左側選單「我的任務」頁新增，不掛記錄。
- 指派給別人時，新負責人會收到「指派給你」通知；指派給自己不通知。

**誰看得到、誰能改**

- 看得到：看得到那筆記錄的人，加上任務的參與者（建立者、負責人、被 @ 的人）。個人任務只有參與者看得到。系統管理員看得到全部。
- 被 @ 的人只看得到這個任務，不會因此看到記錄：相關記錄顯示「相關記錄（無權限查看）」，不顯示記錄標題與欄位值。
- 能改：建立者、負責人、對那筆記錄有修改權限的人、系統管理員。
- 刪除：自己建立的任務，建立者與系統管理員可以刪除。規則產生的任務不能刪，只能改成「已取消」。

**留言、@ 與附件**

- 任務詳細的下方是留言串，留言與系統記錄（建立、改負責人、改到期日、改狀態）排在同一條時間軸。
- 留言時輸入 `@` 會跳出使用者清單（全部啟用中的使用者），選定後送出；被 @ 的人加入參與者，收到「你被提到」通知。自己 @ 自己不通知。停用的使用者顯示名稱加「（已停用）」。
- 留言不能編輯。作者可以撤回自己的留言，系統管理員可以撤回任何人的留言；撤回後顯示「此留言已撤回」，附件一起不再顯示、不能下載。
- 一則留言最多附幾個檔案、單檔大小與允許的副檔名由「政策設定」決定（出廠最多 5 個檔案、單檔 10 MB；任務所屬模組可在「政策」分頁覆寫前兩項，個人任務用全系統值），檔名規則與附件欄位相同；可以只有附件、沒有文字。停用上傳的環境（例如 Demo 站）附件鈕停用，並說明「此環境已停用附件上傳」。看得到任務的人就能下載附件。

**記錄被刪除、應用程式關閉時**

- 記錄被刪除時，它上面未完成的任務自動改成「已取消」，留系統記錄「相關記錄已刪除，任務已取消」；已完成的不動。
- 記錄所屬的應用程式關閉時，任務跟記錄一樣只能看，不能改、不能留言；這段期間也不發到期與逾期提醒。

**我的任務**

- 分頁：「指派給我」「我建立的」「提到我的」。
- 篩選：「未完成」（預設）「已逾期」「今天到期」「本週到期」「全部」。依到期日排序，逾期的標紅。「今天」以台灣時間的營業日為準；「本週」是從今天到本週最後一天，一週從星期幾開始依政策設定（出廠星期一，所以出廠時本週最後一天是週日）。

**模組的「啟用任務」開關**

每個模組可以關閉任務功能。開關在設計器的模組編輯頁，標題列的「啟用任務」；明細模組沒有任務區塊，不顯示開關。有設計器權限的人可以切換，共用主檔模組另需系統管理員。

- 新建的模組預設開，包括設計器新增、從範本建立、開啟應用程式時建立的。內建的共用主檔（往來對象、聯絡人）預設關。
- 關閉後：記錄詳細頁不顯示「任務」區塊；不能在這個模組的記錄上新增任務（API 回「這個模組未啟用任務」）；這個模組的任務規則不觸發，也不能手動套用。規則本身仍可新增、修改，方便先設好再開啟。
- 既有任務保留：我的任務、通知、到期提醒照常，參與者可以照常修改、留言、完成。限制是看得到記錄但不是參與者的人，關閉後看不到這些任務。
- 重新開啟後不補做關閉期間錯過的觸發：關閉時建立的記錄不會補產生「記錄建立時」的任務。
- 應用程式的任務規則掛在任務已關閉的模組上時（例如掛在往來對象），開啟應用程式會自動打開那個模組的任務。開啟前的預覽會列出這些模組，開啟後也會附警告。
- 既有資料庫升級後，所有模組（包括已經開啟的主檔模組）都維持開；要關請在設計器自行關閉。

## 16. 站內通知

右上角的鈴鐺顯示未讀數，點開列出最新 20 則通知，每則顯示建立時間。點一則會先標為已讀，再前往那個任務（簽核通知見 [21.8 通知](#218-通知)，點了會開啟那筆單據）；「全部標為已讀」一次清掉未讀數。通知保留天數依政策設定（出廠 90 天）；縮短之後，下次打開通知時會清掉超過天數的舊通知，清掉的無法還原。

| 通知 | 收件人（出廠值） | 可在政策設定調整 |
|---|---|---|
| 指派給你的任務 | 新負責人 | 否 |
| 你被提到 | 被 @ 的人 | 否 |
| 任務有新留言 | 負責人與建立者 | 是 |
| 任務已完成 | 建立者 | 是 |
| 任務已取消 | 建立者 | 是 |
| 任務即將到期 | 負責人 | 否 |
| 任務已逾期 | 負責人 | 否 |

留言、完成、取消三種的收件角色（負責人、建立者，可複選、可全不選）可在「政策設定」調整，也可以由模組設計者在該模組的「政策」分頁覆寫；收件角色看任務所屬的模組，沒有所屬模組的任務用全系統值。

- 自己做的事不通知自己：自己指派給自己、自己 @ 自己、自己觸發規則又是負責人，都不會收到通知。
- 同一則留言已經因為 @ 收到「你被提到」的人，不會再收到「任務有新留言」。
- 「即將到期」是到期日正好是「今天加提醒天數」那一天（政策「到期前幾天提醒」，出廠 1，也就是明天到期），「已逾期」是到期日已過且該模組開啟「提醒逾期」（出廠開，關掉就不補逾期提醒），都只對未完成（待辦、進行中）的任務。「即將到期」只在到期日前第 N 天（N＝提醒天數）當天打開通知時補上；那天沒打開就不會補，提醒天數是 1 時也一樣。系統沒有背景排程，提醒在你打開通知清單時補上，同一個任務同一種提醒一天最多一則；所以要登入後才看得到，不會準時推送。
- 只有站內通知，沒有 Email 或推播。

## 17. 任務規則

任務規則讓記錄在特定時機自動產生一批任務，例如行銷活動一建立，就派出規劃、佈置、回饋三件工作。

每個模組的規則數上限、每條規則的任務數上限由「政策設定」決定（出廠各 20，模組可在設計頁的「政策」分頁覆寫），見[系統管理：政策設定](#系統管理政策設定)。

**在哪裡設定**

設計器的模組編輯頁有「任務規則」分頁，由有設計器權限的人新增、修改（點規則那一列）、停用、刪除；共用主檔模組另需系統管理員。明細模組不能設定任務規則。條件設定器與「連動事件」分頁相同。

**一條規則的內容**

- 代碼：小寫英文、數字、連字號，全站唯一（不同模組也不能重複）。
- 觸發方式：
  - 記錄建立時。
  - 記錄變成符合條件時：由不符合變成符合的那一次，建立時就符合也算；這種觸發的條件必填。
  - 欄位變成某個值時：例如「階段」變成「簽約」；建立時就是那個值也算。
  - 手動：記錄詳細頁的任務區塊出現「套用任務範本」按鈕，由人決定何時套用。
- 觸發次數：「只產生一次」（預設，每筆記錄只觸發一次）或「每次符合都產生」。記錄建立時只會發生一次，不能選後者。
- 條件（選填）：整條規則的篩選。
- 產生的任務（一到多筆），每筆有：代碼（規則內唯一）、標題（繁體中文必填，可填四種語系）、說明、負責人（記錄上的一個使用者欄位）、到期日（記錄上的日期或日期時間欄位加減天數，正數往後、負數往前；也可以不設）、個別任務的條件（選填，例如只有展覽才產生「展場佈置」）。

**產生出來的任務**

- 建立者記為系統，標示「由規則產生」。標題依觸發那個人的語系存成一種文字。
- 負責人欄位是空的：任務照樣產生，顯示「未指派」。到期基準欄位是空的：沒有到期日。
- 個別任務的條件在觸發後持續判斷：之後存檔變成符合，補產生（例如研討會改成展覽，補「展場佈置」）；未完成的任務變成不符合，自動取消並留系統記錄「條件不再成立，任務已取消」，再變回符合時恢復成「待辦」。已完成、人手動取消的不動。
- 記錄的負責人欄位或到期基準欄位改了：這筆記錄上由規則產生、未完成的任務跟著改；人改過的那一項（負責人或到期日）不再跟著記錄變。新負責人收到「指派給你」通知。
- 匯入、單據轉換、連動事件寫入的記錄，跟在畫面上存檔一樣會觸發規則。

**每次符合都產生**

- 每次由不符合變成符合，就產生新的一批任務；手動規則每按一次就是一批，按鈕不會變灰。
- 上一批還有未完成的任務時，這次不產生，在上一批未完成的任務留言串寫一筆「規則再次觸發，但上一輪任務尚未完成，這次略過」。手動套用遇到這種情況，按鈕停用並說明上一輪還沒完成。
- 只有最新一批的任務會持續判斷條件與同步，舊批次不再自動變動。

**套用任務範本（手動規則）**

- 「只產生一次」的手動規則套用後，按鈕變灰並顯示「已套用」。
- 記錄目前不符合規則的條件時，按鈕停用。
- 記錄所屬應用程式關閉、或模組關閉任務時，沒有這個按鈕。

**規則改了、停用、刪了**

- 已經產生的任務不回頭改。規則停用或刪除後，任務不再同步；刪除規則時任務保留，標示「產生這個任務的規則已刪除」。
- 規則用到的欄位（觸發欄位、負責人、到期基準、規則或任務條件裡的欄位）不能停用，也不能刪除：停用時回「欄位被任務規則『代碼』使用」，刪除盤點會列出這條規則。先改規則或刪掉規則再處理欄位。刪除整個模組時，掛在上面的規則一起刪除。
- 刪除應用程式時，規則引用的欄位被清除，規則自動停用，規則清單顯示「引用的欄位已刪除」的警告。

**跟著應用程式走**

應用程式套件（格式 7）可以帶任務規則，掛在套件自己的模組或它用到的共用主檔模組上；開啟、關閉、匯出、刪除應用程式時跟著走。應用程式關閉時它的規則不觸發，已產生的任務保留。

**範例：CRM 的行銷活動派工**

CRM 與銷售內建「行銷活動」模組（名稱、類型、開始日、結束日、地點、狀態、規劃負責人、佈置負責人、回饋負責人、說明），業務與業務主管可以讀寫。規則「行銷活動派工」在建立時觸發：

| 任務 | 負責人 | 到期日 | 條件 |
|---|---|---|---|
| 規劃活動內容 | 規劃負責人 | 開始日前 62 天 | — |
| 展場佈置 | 佈置負責人 | 開始日前 1 天 | 類型是展覽 |
| 活動回饋 | 回饋負責人 | 結束日後 12 天 | — |

以 2027/02/01 開展、展期三天為例，三個任務分別在 2026/12/01、2027/01/31、2027/02/15 到期。研討會、線上活動不產生「展場佈置」。

## 18. 應用程式管理

應用程式是一組打包好的模組、欄位、規則、權限與報表（例如「CRM 與銷售」）。在「應用程式」頁把它開啟，這些模組就建進你的系統。入口是左側選單「系統管理 → 應用程式」，由系統管理員使用，且要有設計器權限。

### 誰能做

- 選單要「系統管理員」和「設計器讀取權限」兩個條件同時成立，缺一個就看不到選單。系統管理員身分不會自動帶設計器權限，設計器權限要由群組授予。
- 匯入、開啟、關閉、重新開啟，後端同樣要求系統管理員，再加設計器的新增權限（匯入、開啟）或修改權限（關閉、重新開啟）；畫面上這四種按鈕在同時有設計器的新增與修改權限時才出現，沒有的人只能看清單。
- 其他人（不是系統管理員，或沒有設計器讀取權限）沒有選單，直接開網址顯示無權限。清單、套件內容、開啟前檢查、匯出套件這些讀取操作，後端同樣要求系統管理員加設計器讀取權限。
- 共用主檔（往來對象、聯絡人）不在清單裡，由使用它的應用程式自動開啟與關閉，見 [6.7](#67-共用主檔)。

### Demo 站

Demo 站（任何訪客以 admin 登入）對應用程式沒有額外限制：匯入、開啟、關閉、重新開啟都照常可用，權限規則同上；做了就改動所有訪客共用的資料。這一點與「外觀預設」不同（見 [§19](#19-外觀主題與風格)）。

### 清單

每個套件一列：名稱與版本、說明、模組數、「需要 ○○」（要先開啟的其他應用程式）、「被 ○○ 依賴」（已開啟且用到它的應用程式）。右側的標籤是目前狀態：

| 狀態 | 意思 | 可按的按鈕 |
|---|---|---|
| 未開啟 | 套件在清單裡，還沒建進系統 | 開啟 |
| 使用中 | 已開啟，模組可正常使用 | 關閉 |
| 已關閉 | 資料保留，只能看 | 重新開啟 |

清單上方的說明提醒了兩件事：開啟後模組歸你所有，之後套件的新版不會自動合併；關閉只停止寫入，資料與引用仍可查閱。

### 匯入套件

按右上角「匯入套件」，選一個 `.json` 套件檔（內建套件附在 `poc/backend/apps/`）。成功顯示「已匯入套件」，套件出現在清單裡；失敗顯示「匯入失敗」與原因。

- 檔案上限 1 MiB，必須是 UTF-8。套件格式不對、語系鍵不是繁中／English／ไทย／Tiếng Việt，或應用程式之間的「需要」形成循環，都會被拒絕。
- 套件若附有警告，會以不自動消失的提示列出，看完按關閉。
- 匯入的是共用主檔的套件、而系統裡已有同一個主檔時，訊息是「已合併進既有的共用主檔」，內容見 [6.7](#67-共用主檔)。
- 匯入只是把套件放進清單，不會建任何模組；要按「開啟」才會建。

### 開啟

1. 在「未開啟」的套件按「開啟」。畫面先跑檢查，顯示「開啟『○○』」對話框，什麼都還沒寫入。
2. 檢查有問題時，對話框列出「目前無法開啟：」與原因，「開啟」鈕停用。常見原因：
   - 「模組『○○』的代號 ○○ 已被使用」：系統裡已有同代號的模組。
   - 「缺少依賴 ○○」：它需要的應用程式還沒開啟、已關閉，或對方的模組被刪除或停用。先把依賴的應用程式開起來（這裡不會自動連帶開啟，要依相依順序一個一個開）。
3. 檢查通過時，對話框列出套件的群組要怎麼處理：「對應現有群組」（系統裡有代號相同的群組就用它）、「建立新群組」、「略過」（沒有對應的群組就不給任何人權限）。一起開啟的共用主檔也列出它的群組。這是系統依現況給的建議，目前在對話框裡不能改成別的做法。
4. 按對話框的「開啟」確認。成功顯示「已開啟」，狀態變「使用中」，模組出現在左側選單（分區名稱、群組名稱用你開啟當下的介面語言建立）；失敗顯示「開啟失敗」，整批回滾，不會留下半個應用程式。

開啟後要注意：

- 模組的權限依群組對應的結果授予，其他群組要自己到權限分頁授權（見 [§5](#5-權限)）。新建的群組是空的，要到「群組」頁加成員。
- 同一個套件不能開第二份；已經開過（不論使用中或已關閉）再開會被擋，已關閉的請用「重新開啟」。
- 開啟後模組、欄位、規則、權限都是你的，可以直接在設計器修改。套件之後出新版，不會也不能套用到已開啟的應用程式。
- 套件帶的任務規則、報表隨應用程式一起建立；任務規則的細節見 [§17](#17-任務規則)。
- 套件帶的簽核流程也隨應用程式一起建立，見下一節。

### 套件帶的簽核流程

套件可以帶簽核流程（套件格式 8）：開啟時流程建成第 1 版，狀態機轉移的「需簽核」、狀態的「可編輯（退回重送）」照套件設定。開啟後流程屬於你，可以在模組設計頁的「簽核流程」分頁修改、停用或刪除（見 [21.9](#219-設計簽核流程)）。

- **內建應用程式帶的流程**（開啟後可改、可停用、可刪，門檻與時數都在流程設計器裡改）：
  - 「CRM 與銷售」（1.3.0 起）：設計案「客戶確認中 → 待主管確認」需簽核，流程「設計案主管確認」一關，簽核人是負責業務的直屬主管。
  - 「進銷存」（1.1.0 起）：採購單「草稿 → 已確認」需簽核，依採購單的「未稅小計」決定（不含稅，稅率改了不影響簽幾關）。「採購單（大額）」未稅小計 100,000 以上，兩關：第 1 關「採購主管」（發起人往上第 1 層主管，24 小時內處理）、第 2 關「總經理」（往上第 2 層主管，48 小時）；「採購單（一萬以上）」未稅小計 10,000 以上，一關「採購主管」。不到 10,000 沒有流程符合，送出簽核時直接轉為「已確認」，不建簽核實例。兩個流程找不到簽核人時（例如送簽的人沒有部門）交給備援：進銷存主管群組。要改門檻，到採購單的模組設計頁「簽核流程」分頁改流程條件。「已取消」狀態在套件裡標成「可編輯」，意思只是它不算簽核鎖定狀態（好讓草稿能直接取消），不是能改內容：已取消仍是唯讀狀態，取消後不能修改。從草稿或已確認取消仍是一般的狀態轉移，不需簽核，取消時備註必填。
  - 已經開啟過 CRM 或進銷存的資料庫不會自動多出這些流程（套件開啟後不更新）：要在簽核流程設計器自己建，並在狀態機分頁把轉移設成需簽核，或重建資料庫。簽核 a5 之前產生的 Demo 資料已經有設計案流程。
- **群組被略過時流程照樣建立**（目前開啟對話框只套用系統建議的「對應現有群組」或「建立新群組」，不會建議略過，這種情況只在直接呼叫 API 時會遇到）：用到那個群組的關卡，改由備援簽核人頂替那個群組；會簽要湊滿的人數不會變少，原本設成「跳過這一關」的關卡改成交給備援。頂替的是流程的備援簽核人；流程沒設備援，或備援用的群組本身被略過，改用簽核政策的預設備援簽核人。使用者欄位、發起人自選的候選群組有任何一個被略過，整個來源都改由備援頂替。
- 開啟對話框下方的灰字清單逐條列出每一個頂替，例如「簽核流程「採購單（大額）」關卡「董事會」的簽核人來源「董事會」已略過，改由流程的備援簽核人頂替」。
- 這些情況「目前無法開啟」：
  - 流程的關卡數、每關人數、逾期時數、主管層數超過目前的簽核政策上限。
  - 「流程代碼已被使用」：系統裡已有同代碼的流程（流程代碼全站唯一）。
  - 「略過後「○○ → ○○」沒有任何群組，簽核流程「○○」無法退回，請對應這個群組」：流程退回要走的那條轉移，只開給被略過的群組。
- 流程用到的欄位（條件、使用者欄位、可編輯欄位）與狀態欄位不能排除；開啟對話框沒有取消勾選欄位的畫面，這條只在直接呼叫 API 時會遇到。
- 流程掛在沒有需簽核轉移進入的狀態上時，只警告「狀態「○○」沒有需簽核的轉移進入，這個流程不會被用到」，照樣開啟。
- 已開啟的應用程式不會從新版套件補上流程。

### 關閉

在「使用中」的應用程式按「關閉」，確認對話框寫著：關閉後資料仍可查閱，但不能新增、修改或刪除；隨時可以重新開啟。

- **有別的應用程式依賴它**：對話框列出「這些應用程式依賴它：○○。需要連帶關閉。」，確認鈕變成「連帶關閉」，依賴它的應用程式一起關閉，成功顯示「已關閉 N 個應用程式」。
- **你自己建的模組有欄位參照它**：對話框提示「自建模組 ○○ 有欄位參照它，關閉後無法再新增指向這裡的資料。」只是提醒，不擋關閉。

關閉之後：

- 它的模組在左側選單移到最下面的「已關閉的應用程式」分組，仍可點進去，頁面是唯讀。
- 不能新增、修改、刪除記錄，也不能匯入；不能建立或修改列表檢視；其他模組不能新增指向它的參照值。系統管理員也一樣。
- 照樣可以看列表、明細、歷程、匯出 CSV 與 Excel，報表與儀表板照常執行；其他模組裡既有的參照仍顯示標題。
- 它給各群組的新增、修改、刪除、核准權限暫時收回，讀取保留（共用主檔的欄位怎麼處理見 [6.7](#67-共用主檔)）。
- 它的任務規則不觸發，已產生的任務保留（見 [§15](#15-任務)）。
- 簽核中的單據停在原關卡：簽核中心照樣列出、標「應用程式已關閉」，但不能同意、退回或撤回；重新開啟後從原關卡接著簽。
- 在設計器裡，會連帶改寫既有記錄值的變更（換記錄標題欄位、新增或改動公式與彙總、刪除仍有值的欄位或區塊）會被擋；公式、彙總欄位在記錄上有值時也一樣不能刪（沒有值的照常可刪）。要改請先重新開啟。另外，分錄模組只要已有記錄，同樣不能刪有值的欄位（包括公式與彙總），這一點與應用程式是否關閉無關。

### 重新開啟

在「已關閉」的應用程式按「重新開啟」，沒有確認對話框，成功顯示「已重新開啟」。資料與設定在關閉期間都沒動過，所以只是把狀態翻回去，被收回的權限也恢復。

- 它依賴的應用程式必須是使用中，否則失敗，提示列顯示「它依賴的應用程式或模組還沒有開啟」，不列出缺少哪些項目（要知道缺什麼，看清單上這個應用程式的「需要 ○○」）。這句固定是繁體中文，不隨介面語言換。「重新開啟失敗」只在伺服器沒給任何原因時才出現（例如連不上）。
- 之前被「連帶關閉」的應用程式不會自動重開，要一個一個重新開啟。

### 目前沒有畫面的功能

- **刪除應用程式**：清單沒有刪除入口。規則是應用程式要先關閉，且模組沒有未刪除的記錄、沒有被應用程式以外的東西引用、沒有其他應用程式依賴它；刪除不會移除開啟時建立的群組。簽核流程、各版本、已刪除記錄留下的簽核紀錄一起清除。
- **匯出套件**：沒有畫面，見 [6.7](#67-共用主檔) 的說明。簽核流程匯出目前版本（停用的也匯出），不含歷史版本、簽核中的單據與簽核紀錄；換一個資料庫開啟後是第 1 版。共用主檔不匯出流程。以下情況整份不能匯出，回應列出原因：
  - 「簽核流程「○○」關卡「○○」指定了具體使用者，帳號屬於這個資料庫，套件不收」（備援簽核人指定使用者也一樣）：請改成群組或主管。
  - 「簽核流程「○○」關卡「○○」有開啟套件時略過的群組，請先在設計器移除或補上群組」。到該流程的編輯對話框，在那一關的簽核人來源下方按「移除」並儲存即可，見 [§21.9](#219-設計簽核流程)；移除之前，含這類群組的應用程式匯不出去。
  - 「模組「○○」的狀態機未匯出，簽核設定無法單獨匯出」：狀態機用到停用的選項，連帶簽核設定也匯不出去。
  - 流程引用了停用或未匯出的欄位、狀態、選項（包括條件裡比對的選項值），或已不存在的群組。
- **開啟後調整群組對應**：開啟時的對應不能在畫面上改，之後要在權限分頁手動調整。
- **整合狀態**：應用程式之間的整合與覆蓋狀態，目前只能從 API 查看。

## 19. 外觀：主題與風格

外觀分兩項，各自獨立：**模式**（明暗）與**風格**（版面密度、顏色、圓角與字級）。系統管理員設全站預設，每個使用者可以自己覆寫。

### 模式

| 選項 | 效果 |
|---|---|
| 淺色 | 固定淺色 |
| 深色 | 固定深色 |
| 依系統 | 跟著作業系統或瀏覽器的明暗設定，系統切換時畫面立即跟著換，不必重新整理 |

圖表、報表與儀表板也跟著明暗模式變色。

### 風格

共有 8 種，名稱與畫面上的說明如下：

| 風格 | 說明 |
|---|---|
| 資料工作台 | 密度最高，適合長時間看大量資料（出廠預設） |
| 簡潔留白 | 留白多、字較大，看起來舒服 |
| 正式企業 | 深藍頂列與麵包屑，正式穩重 |
| 現場工業 | 粗框大字，遠距離也看得清楚 |
| 霧面玻璃 | 選單與工具列半透明，背景有柔和色塊 |
| 便當格 | 色塊分區、大圓角，重要數字放最大 |
| 指令台 | 低彩度細線、等寬編號，密度最高 |
| 植感活力 | 深綠選單、淡綠底、扶桑紅與襯線標題 |

模式與風格任意搭配都能用。風格只改外觀與密度，不影響資料、權限與功能；選「正式企業」時，頁首下方會多一列麵包屑。

### 個人設定

1. 按頁首的「外觀」（調色盤圖示；手機寬度只顯示圖示）。
2. 對話框裡選「模式」與「風格」。每個風格旁有範例色塊，可先比較。
3. 選了立即生效並自動儲存，沒有儲存鈕，關閉對話框即可。儲存失敗時顯示「外觀儲存失敗，已回到上一個設定」，畫面退回上一次成功的值。

兩個選項最上面都有「跟隨全站預設（目前：○○）」。選了它，該項就隨管理員的預設變動；只改模式、風格仍跟隨預設也可以。個人設定跟著帳號，換瀏覽器或電腦登入也一樣。

### 全站預設（系統管理員）

左側選單「系統管理 → 外觀預設」，只有系統管理員看得到，其他人開網址會顯示無權限。

1. 選預設的「模式」與「風格」（這裡沒有「跟隨」選項）。
2. 按「儲存」。與個人設定不同，這裡選了不會立即存，要按儲存才送出，因為影響所有人。成功顯示「已儲存，其他人下次載入時生效」。

規則：

- 實際套用的值，模式與風格分開算：個人設定 > 全站預設 > 出廠預設（依系統、資料工作台）。
- 沒有自己設定的使用者，下次載入畫面時改用新預設；已有自己設定的人不受影響。
- 登入頁（還沒登入）使用全站預設。

### Demo 站

Demo 站任何訪客都能不用密碼登入，所以外觀不存到帳號：對話框顯示「Demo 站的選擇只存在這個瀏覽器」，每個瀏覽器各一份，訪客之間互不影響。「外觀預設」頁在 Demo 站唯讀，並說明「Demo 站不能修改全站預設：任何訪客都能以 admin 登入，改了會影響所有人」。

### 已知限制

- 不能自訂顏色、字型、Logo，也不能依模組或群組設定不同外觀；只能在上面的模式與風格之間選。
- 單筆列印與匯出不隨風格改變：列印預覽是獨立的頁框，版面由伺服器產生的範本決定；CSV、Excel 由伺服器產生，不帶外觀。
- 用瀏覽器直接列印一般畫面（列表、報表等）時，不論模式與風格一律白底黑字、無陰影與背景圖、字型改回系統字型；但間距、圓角、列高等仍依目前風格，各風格印出來的版面不保證完全相同。

## 20. 語言切換

介面有四種語言：繁體中文、English、ไทย、Tiếng Việt。

### 怎麼切

- 登入頁與登入後的頁首右上角，各有一個「語言」圖示（地球儀樣式的翻譯圖示）。點開列出四種語言，名稱用各語言自己的寫法，不隨目前語言翻譯。
- 選了立即生效，不必重新整理。選單、按鈕、訊息、日期選擇器、表格分頁等內建文字一起換。
- 被強制改密碼時看不到頁首選單，請先在登入頁選好語言。

### 記住的方式

- 第一次開啟固定是繁體中文，選過之後記在這個瀏覽器，下次沿用。
- 語言設定只存在瀏覽器，不跟帳號走：換瀏覽器、換電腦、清除網站資料或用無痕視窗，都會回到繁體中文。同一台瀏覽器上換帳號登入，語言不變。
- 瀏覽器不允許儲存時，切換照常生效，只是下次又回到繁體中文。

### 哪些文字會跟著換

- 系統介面與內建應用程式的文案，四種語言都有；某個語言缺的文案顯示繁體中文。ไทย 與 Tiếng Việt 目前是機器翻譯，對客戶上線前需要母語人士校對。
- 你在設計器自己填的名稱與顯示文字（模組、欄位、選項、選單分區等）可以填四種語言，繁中必填，沒填的語言顯示繁中，見 [2.1](#21-新增模組)。
- 你輸入的記錄內容（例如客戶名稱、說明）不會翻譯，原樣顯示。
- 開啟應用程式時建立的群組名稱與選單分區，用開啟當下的介面語言（見 [§18](#18-應用程式管理)）。
- 任務規則產生的任務標題，用觸發那個人的語言存成一種文字（見 [§17](#17-任務規則)）。

### 日期與數字格式

- 日期與時間不隨語言換：日期欄位、列表與明細的「修改時間」、歷程與留言時間，一律是 `YYYY-MM-DD`、`YYYY-MM-DD HH:mm`。日期選擇器的月份、星期名稱會換成該語言。
- 金額欄位（currency）以及用金額當結果型別的公式、彙總，千分位與小數點跟著語言：例如繁中、English、ไทย 是 `1,234.50`，Tiếng Việt 是 `1.234,50`（依瀏覽器的格式規則）。
- 整數、小數、百分比欄位在列表與明細裡照原值顯示，不加千分位，也不隨語言換。
- 報表與儀表板的數字、比例、百分比，千分位與小數點跟著語言。
- 匯出的 CSV 數字固定不加千分位、小數點為 `.`，日期時間固定 `YYYY-MM-DD HH:mm`；Excel 的數字欄是真正的數值，顯示格式由 Excel 依你電腦的地區設定決定。是／否、選項名稱、參照標題這類文字，會用匯出當下的介面語言。

## 21. 簽核

單據要轉到「需簽核」的狀態（例如採購單轉為「已核准」）時，不能直接改狀態，要先送出簽核，由流程裡的簽核人依序同意。簽核流程（需簽核的轉移、流程、關卡）由設計者在模組設計頁設定，見 [§21.9](#219-設計簽核流程)；§21.1 到 §21.8 說明單據怎麼送簽與處理。

### 21.1 送出簽核

- 打開單據的詳情頁，狀態區會出現「送出簽核：已核准」（冒號後面是目標狀態）這顆按鈕，而不是直接轉移。只有能送出的人看得到；單據已經在簽核中、或這個轉移不需簽核時不會出現。
- 編輯頁的狀態下拉不列需簽核的目標狀態；要改成那個狀態，請回詳情頁按「送出簽核」。
- 按下去會開對話框，先列出這張單適用的流程與每一關的時間軸。實際簽核人依送出當時的組織決定。
- 有些關卡標示「由你選擇」：要自己挑簽核人，人數範圍寫在欄位旁（例如「選 1 到 2 位」），範圍由流程決定。有些關卡標示「依條件決定」，送出後才知道要不要簽。
- 「意見（選填）」可以寫給簽核人看；意見有字數上限（出廠 1000 字，由「政策設定」決定），超過時送出會被擋下並提示。
- 沒有符合條件的流程時，對話框說「沒有符合條件的簽核流程，請聯絡管理員」，不能送出。流程設成「條件都不符合就直接轉移」時，對話框說「這張單不需簽核，會直接轉為…」，按送出就直接轉狀態。
- 送出後：回到詳情頁，標題旁出現徽章「簽核中（第 1 關／關卡名稱）」。網路中斷後再按一次送出不會重複送簽；成功之後再開對話框是一次新的送出。

### 21.2 簽核中的單據

- 簽核中的單據對所有人唯讀，包括發起人，編輯與刪除按鈕會隱藏，編輯頁顯示「簽核中，記錄唯讀；要修改請先撤回」。
- 詳情頁的「簽核」區塊用時間軸列出每一關：誰是簽核人、目前進度、動作時間與意見；找不到簽核人而改由備援簽核人處理時，會在歷程裡說明；流程沒設備援簽核人時，由政策「找不到簽核人時的備援對象」決定給誰（出廠為全部系統管理員，可依模組覆寫）。單據被退回後再送出，舊的簽核收合在「先前的簽核」下面。
- 關卡設了期限時，時間軸顯示期限，逾期標「逾期」。

### 21.3 同意與退回

簽核人（任務還在處理中）在詳情頁看得到動作列。手機上動作列固定在畫面底部，最多顯示同意、退回兩顆（轉交收在「更多」選單裡），捲到最底時最後一個區塊不會被蓋住。

- **同意**：開對話框，意見選填。如果這一關設了可編輯欄位，對話框上方會出現「這一關可修改」區段，欄位預填目前的值；只有你改過的欄位會隨同意一起送出，沒改就不送。欄位的值有誤時，錯誤顯示在該欄位下。可編輯欄位只能在按同意時改，沒有「先存起來」。
- **退回**：兩種，意見必填。「退回發起人」結束這次簽核，單據轉到流程指定的退回狀態（沒指定就維持原狀態），發起人修改後可以重新送出，那是一次新的簽核，從第一關開始。「退回上一關」回到最近一個已同意的關卡重新簽；前面沒有已同意的關卡時，這個選項停用並說明。
- 單據在你處理之前被改過（例如其他系統動作改了內容）時，流程可能重新比對。同意之後如果看到「單據內容已變，流程改為「…」重新開始，你的同意未計入」，表示你這次的同意沒有算數，新的簽核從頭開始，頁面會換成新的時間軸；如果新流程需要發起人自選簽核人，訊息會說明要由發起人重新送出。

#### 轉交

簽核人在動作列按「轉交」（手機在底部列的「更多」裡），把自己這個任務交給另一個人：選「轉交給」，意見選填，送出後對方接手這一關，你就不能再查看或處理這筆待簽（單據原本就有讀取權的人照舊看得到）。

- 對象只能是啟用中的帳號，不能是自己，也不能是這一關還有票的人（同一關的其他簽核人、已同意或已退回的人，以及代理任務背後的本人）；之前轉出去的人不算，所以可以轉給對方、再轉回來。
- 發起人能不能當對象，和「發起人自簽」政策（`approval.allowSelfApproval`）一致：出廠設定下不能轉給發起人，系統管理員在政策頁對該模組打開之後才可以。下拉選單已經先排除不能選的人，直接用 API 送出會得到 400。
- 新任務沿用這一關原本的期限，不重新起算；會簽的席位照舊，新負責人同意就算那一席的票。
- 時間軸上新任務標「轉交」與「原簽核人 某某」，歷程記一筆「轉交」；對方的鈴鐺收到「轉交給你」。
- 轉交不是同意或退回，不影響發起人撤回。

### 21.4 撤回

發起人在目前這一關還沒有任何人同意或退回時，可以按「撤回」，意見選填。撤回後簽核結束，單據的狀態不動，回到可編輯，要再簽核需重新送出。目前這一關已有人處理（會簽只要有一人同意）就不能撤回，按鈕停用並說明「目前關卡已有人處理，不能撤回」。前面關卡通過與否不影響撤回，只看目前這一關。

#### 管理員終止與改派

對該模組有「簽核」動作權（含資料範圍）的簽核管理員，包含系統管理員，在進行中單據的動作列按「更多」，會看到「終止」與「改派」（所有寬度都在選單裡；沒有待簽任務的管理員也看得到動作列）。模組已關閉時兩者都不能做。

- **終止**：意見必填。終止後這次簽核結束，所有還沒處理的待簽與排隊中的關卡一起關閉，單據停在送簽前的狀態（送簽前可編輯的話就回到可編輯），發起人要重新送出。原本還沒處理的簽核人與發起人（管理員自己除外）的鈴鐺收到「已終止」，時間軸記一筆「終止」附上意見；那些簽核人立刻不再能靠臨時讀取查看這筆單據。已核准後鎖定的單據送作廢時被終止，單據仍停在原本的狀態與鎖定。
- **改派**：選「要改派的待簽」（目前關卡只有一個待簽時預選）與「改派給」，意見選填。對象規則同轉交（啟用中帳號、不是這一關還有票的人、發起人看「發起人自簽」政策），但管理員可以把待簽改派給自己。原負責人停用或離職也能改派，這是搬走他的待簽的方法。新任務沿用原期限，對方收到「轉交給你」，原負責人收到「管理員已改派你的待簽」（只有單號與接手者姓名，沒有連結，因為他已不能讀取這張單），時間軸記一筆「改派」。
- 時間軸的「轉交」「改派」都顯示「→ 對象姓名」。

### 21.5 核准後的鎖頭

簽核通過、單據進入「簽核鎖定」狀態後，被鎖定的欄位在編輯頁唯讀，欄位上方有鎖頭與說明「已經過簽核，要修改請先退回可編輯的狀態」；詳情頁的欄位標籤旁有小鎖頭。鎖哪些欄位、怎麼改回，見 [§7.6](#76-核准後哪些欄位不能改)。其他不影響簽核的欄位（例如備註）照常可以改。

目前已生效的保護有三項：表頭與明細的欄位寫入（含系統動作、整合與連動事件）、附件（見下一節），以及設計者改公式或彙總後的整批重算。整批重算會跳過簽核中的單據、停在簽核鎖定狀態的單據，和這些單據的明細列，它們保留原值，所以改公式不會動到已核准的金額（例外：其他模組的彙總更新到這張單時，這張單的公式會用目前的定義重算，見 [§9 已知限制](#9-已知限制)）；跳過幾筆會在欄位對話框存檔後提示（只算被修改的那個模組）。跳過的單據之後要套用新公式，要先退回可編輯的狀態再存檔。有單據簽核中時，改寫記錄值的定義變更與拆掉簽核中轉移的狀態機變更直接被擋，見 [§2.6.2](#262-有單據簽核中時)。

**附件**：簽核中、核准後（簽核鎖定狀態）、已記帳的單據，附件都不能增減。這幾種狀態下，附件欄位在畫面上不顯示上傳與移除按鈕，所以一般操作碰不到擋下的訊息。只有兩種情況會看到：頁面開著時單據剛好被送簽或核准（舊頁面還留著上傳按鈕），以及直接用 API 上傳。這時上傳會被擋、不收進檔案，訊息分別是「簽核中，不可修改」、「這筆記錄已經過簽核，附件不能再增減；要修改請先退回可編輯的狀態」、「已記帳的單據不能再增減附件」。用 API 或舊頁面以修改單據的方式把附件清掉或換掉也一樣：核准後的單據回 400 欄位錯誤，簽核中回 409「簽核中，不可修改」。分錄模組是例外：它的編輯頁只看有沒有事件事實，可能還顯示上傳按鈕，按下去會看到「已記帳的單據不能再增減附件」。把單據轉回可編輯的狀態之後就能再增減。已有「附件」欄位的模組，核准後這個欄位也算鎖定欄位，設計器的鎖定欄位清單會列出它。任務留言的附件不受簽核鎖定：留言是溝通紀錄，不是核准內容，簽核中或核准後仍可在任務留言附檔。

### 21.6 簽核中心

主選單「簽核」進入簽核中心，網址 `/approvals`。所有登入的人都看得到這一項。

| 分頁 | 內容 |
|---|---|
| 待我簽核 | 輪到你處理的單據，期限最近的在前；逾期的標「逾期」 |
| 我已處理 | 你同意、退回過的單據，最近處理的在前 |
| 我送出的 | 你發起的簽核，最近送出的在前 |
| 全部 | 在某個模組的權限頁勾了「核准」、而且那個模組已經有簽核單的人才看得到這個分頁，列出那些模組的所有簽核 |

- 每一筆顯示單據標題、模組、目前關卡（不在簽核中的顯示「已核准」「已退回」等狀態）、發起人、送出時間與期限。沒有標題的單據顯示「模組名稱 #編號」。所屬應用程式已關閉的單據標「應用程式已關閉」。
- 篩選：模組、狀態、送出日期（起迄）。「待我簽核」沒有狀態篩選，因為都是簽核中。篩選條件記在網址裡，重新整理或從通知回來都還在。手機上篩選收進「篩選」按鈕開的全螢幕視窗，按「套用」才生效。
- 每頁 20 筆。點整列（或鍵盤 Enter、空白鍵）進單據詳情頁；手機與平板寬度以卡片顯示。
- 「全部」分頁受資料範圍限制，只看得到你有權限的模組與範圍。

### 21.7 沒有模組讀取權的簽核人

簽核人不一定能讀整個模組（例如財務沒有費用報支的讀取權）。只要他在某一筆單據上有處理中的任務，就能從簽核中心、通知或網址打開那一筆：

- 看得到單據內容與簽核區塊，可以同意、退回，頁面頂端有說明他是以簽核人身分臨時查看。金額欄位照樣看得到，因為金額是簽核內容的一部分。
- 看不到：列印、編輯、刪除、關聯、任務、歷程、帳本、轉單、連動紀錄，也看不到同一模組的其他單據。
- 同意或退回之後任務結束，臨時權限一併收回，同一個頁面會變成「只看簽核歷程」：標題、簽核時間軸，沒有任何動作，也不是錯誤畫面。
- 發起人與處理過的人，之後即使失去模組權限，也一樣只能看這份簽核歷程。
- 沒有任務的人打開同一筆，仍是「無權限」。

臨時讀取目前不含列印預覽，之後和代理、轉交一起補。

### 21.8 通知

鈴鐺會收到簽核通知，標題前面有種類文字，點通知會標為已讀並開啟那一筆單據。

現在會收到的種類：「待你簽核：」「已核准：」「已退回：」「退回上一關：」「已撤回：」「流程已重來：」，簽核異常（例如簽核中狀態機被改、要走的轉移已不存在）會通知「簽核異常通知對象」政策指定的人（出廠為全部系統管理員）。加簽、逾期兩種要等那些功能上線才會出現。

| 通知 | 收件人 |
|---|---|
| 待你簽核 | 該關的簽核人 |
| 已核准、已退回 | 發起人 |
| 退回上一關 | 發起人與上一關的新簽核人 |
| 已撤回 | 目前還沒處理的簽核人 |
| 轉交給你 | 接手的人（轉交與管理員改派相同） |
| 已終止 | 原本還沒處理的簽核人與發起人 |
| 管理員已改派你的待簽 | 被改派走的原負責人 |
| 簽核異常 | 「簽核異常通知對象」政策指定的人（出廠為啟用中的系統管理員） |

做動作的人自己不會收到通知。

### 21.9 設計簽核流程

設計簽核在模組設計頁完成，需要模組的設計權限；只有讀取權的設計者看得到內容，但沒有任何新增、編輯、儲存的入口。模組要有狀態機（模組設計頁的「狀態機」分頁，見 [§2](#2-建立模組)）才能設簽核。

**建議順序：先建流程，再打開「需簽核」。** 需簽核的轉移，目標狀態至少要有一個簽核流程才能儲存狀態機；所以先到「簽核流程」分頁為目標狀態建好流程，再回「狀態機」分頁打開轉移的「需簽核」。

#### 狀態機分頁

- **需簽核**：每條轉移有「需簽核」開關。打開後多一個「條件都不符合時」：「擋下（預設）」表示沒有流程符合就不能送出；「直接轉移」表示沒有流程符合時單據直接轉狀態，畫面會警告「條件都不符合的單據會直接轉移，不經任何人同意」。
- **目標狀態已掛 N 個流程**：轉移旁顯示目標狀態掛了幾個流程（含停用的），點下去跳到「簽核流程」分頁並標示該目標狀態；該狀態還沒有流程時，會直接開新增流程。目標狀態沒有流程時不能儲存，並說明「「{狀態}」還沒有簽核流程，需簽核的轉移不能儲存。請到「簽核流程」分頁建立。」
- **可編輯（退回重送）**：狀態清單有「可編輯（退回重送）」開關，標示單據被退回後哪些狀態可以修改。起始狀態固定可編輯；需簽核轉移的目標狀態以鎖定為準，開關會停用並說明「需簽核轉移的目標狀態以鎖定為準」。
- **鎖定標示**：進入需簽核目標狀態後會被鎖定的狀態標「簽核鎖定」，表格下方列出鎖定狀態中不能修改的欄位（附件欄位一律鎖定）。這些標示**以上次儲存的狀態機為準**：你改了轉移但還沒儲存時，表格上方會註明「鎖定標示與鎖定欄位依上次儲存的狀態機；儲存後重新計算」，儲存後才會更新。
- **建議**：核准之後的狀態，建議設成唯讀狀態。
- 儲存被擋時，錯誤標在那條轉移或那個狀態上。手機（390 寬）上轉移與狀態改成卡片，不會橫向捲動。

#### 簽核流程分頁

- 流程依「目標狀態」分組，每組列出入口轉移；組內由上而下依優先序比對，第一個符合的流程生效。目標狀態沒有需簽核的入口時，該組顯示警告「這個狀態還沒有需簽核的入口，流程不會被用到」。
- 每張卡片顯示流程名稱、啟動條件摘要（沒設條件是「一律符合」）、關卡數、版本、進行中張數，點卡片或按編輯開啟對話框（鍵盤可用 Enter 或 Space）。
- **啟用開關、上移、下移按了就存**，不必另外儲存，而且只影響之後送出的單。停用時會先確認：「停用後，之後送出的單不再比對這個流程；進行中的 {n} 張照原流程走完。」桌機可以拖曳排序，同一個目標狀態內有效；手機只有上移、下移。
- **被使用過的流程不能刪除，只能停用**，目標狀態也不能改，要改請另建流程。沒用過的流程才有刪除。
- 只改名稱、啟用或停用、優先序，不會產生新版本；只停用、定義沒改時，不會重跑定義驗證（定義裡的群組或欄位可能已被刪除，仍要讓你先把流程停下來）；停用的同時改了定義，或重新啟用時，照常驗證。

從應用程式套件建立的流程（見 [§18](#18-應用程式管理)）和自己建的一樣屬於你，可以改、停用；沒用過的也可以刪除。

#### 流程編輯對話框

對話框分「基本」「關卡」「試算」三段；寬度夠時分段在左側，手機（390 寬）全螢幕、分段在上方，儲存鈕固定在底部。取消直接關閉，不會詢問是否放棄變更。

- **基本**：流程代碼（建議以應用程式代碼當前綴，存檔後不能改）、流程名稱、目標狀態（列出所有非起始狀態，註明「已有需簽核的入口」或「還沒有需簽核的入口」）、啟動條件（空白代表一律符合）、退回後的狀態、備援簽核人。備援可「沿用模組預設備援」或「自訂」，自訂只能選指定使用者、群組或發起人的主管。
- **版本提示**：只有「流程已被使用過、而且你改了定義」時才出現「儲存會產生第 {next} 版，進行中的 {n} 張單照舊版本走完」（沒有進行中的單則是「儲存會產生第 {next} 版，已送出的單不受影響」）。新增流程，或編輯時改了目標狀態，顯示「只影響之後送出的單」；其他情況（例如只改名稱或啟用狀態，或流程還沒用過）都不顯示提示（卡片上的啟停與排序存檔後，會另外提示「已啟用／已停用／已調整優先序，只影響之後送出的單」）。
- **關卡**：每張卡片設名稱、關卡代碼、進入條件、簽核人來源、簽核方式（會簽或或簽，來源只可能出一個人時不顯示）、可編輯欄位、逾期時數、找不到人時。第一張前、每兩張之間、最後一張後都有「＋」可插入關卡。
  - **關卡代碼**新增時預填目前沒被用到的最小「stage-N」，可以改，**不會跟著名稱改**。已存過的關卡改代碼時會警告「改代碼會被當成新關卡，要符合目前的上限」；改成另一個已存關卡的代碼，則會沿用該關卡的設定比對。
  - **簽核人來源**共五種：指定使用者、群組、發起人的主管、使用者欄位、發起人自選。各來源的人數提示如下：
    - 指定使用者：存檔時最多 {max} 位（模組政策）。名單存檔後，執行時只受技術上限 {tech} 位限制。
    - 群組、主管、使用者欄位：每一關啟動時，解析出的人數不能超過當時的每關人數上限（目前 {max} 位）。
    - 發起人自選：最多人數不能超過 {max}。送出時實際上限取這裡的最多人數與當時政策上限的較小值；最少人數比實際上限大時，改用實際上限。
    - 備援：備援簽核人頂替找不到人的來源時，不計入每關人數上限；整關合計（含備援，去重後）不超過 {tech} 位。
  - **開啟套件時略過的群組**：應用程式套件開啟時，沒有對應到本機群組、被略過的簽核群組不會讓流程少簽，而是留在來源上。這樣的來源下方會出現提示：「開啟套件時略過的群組：{群組名稱}。執行時由備援簽核人頂替，會簽仍要湊滿這些席位。」；候選群組被略過時則是「開啟套件時略過了候選群組，這個來源執行時一律由備援簽核人頂替。」旁邊的「移除」會先確認：「移除後這一關少了這些席位，確定要移除嗎？」確認後提示消失，儲存才生效（流程被用過就產生新版本）。移除後這一關不再留這些席位，群組來源若因此沒有任何群組，儲存會被擋下，要先補上群組。候選群組被略過的來源，確認文字改成「移除後，這個來源只能從目前選的候選群組選人，不再由備援簽核人頂替，確定要移除嗎？」：使用者欄位要先選候選群組才能儲存（略過時畫面只顯示提示、不報錯）；發起人自選的候選群組若全被略過，「移除」會先擋下並說明「候選群組都被略過了。現在移除，任何人都能被選為簽核人；請先在上方選至少一個候選群組，再移除。」，選了候選群組後才能移除。備援群組被略過時，整份備援已改用政策預設，備援欄位不會出現這個提示。這類群組不移除，應用程式就匯不出去（見 [§18](#18-應用程式管理)）。
  - 關卡數、每關人數、逾期時數、主管層數的上限都來自政策設定（[系統管理：政策設定](#系統管理政策設定)），畫面上的數字就是目前的生效值；讀不到時不顯示數字，由儲存時的檢查擋下。**改嚴只管之後**：已存關卡的值超過目前上限時照樣顯示、可以儲存（選單標「沿用舊值」），只有新增或加多才受限。
  - 找不到人時預設交給備援簽核人；選「跳過這一關」會警告，因為整關所有來源都找不到人時才跳過，等於少一道核准。
  - **可編輯欄位**只列可以修改的欄位；跟條件或簽核人有關的欄位，儲存時會檢查，不合規會擋下並指出是哪一關。
  - 儲存失敗時，錯誤落在對應的關卡卡片或輸入框；任何編輯都會清掉錯誤標示。
- **試算**：選一位發起人（必填），可再選一筆記錄帶入欄位值，或直接輸入欄位值（只列會影響流程比對與簽核人的欄位），按「試算」看結果。選了記錄時，沒動的欄位用記錄的值，清空代表沒有值；你看不到的欄位也用記錄的值。
  - **試算用的是編輯中、還沒儲存的內容**，視為啟用、不會寫入任何資料；新流程還沒儲存也能試算。
  - 結果是時間軸：每一關的簽核人、備援標示、不需簽核（跳過）；「發起人自選」的關卡顯示「由發起人送出時選擇」。找不到簽核人或人數超過上限的關卡會標示「送出或推進到這一關時會失敗」。
  - 同一個目標狀態有優先序在前的流程先符合時，會說明「這筆會先符合流程「{名稱}」（優先序在前），不會走這個流程」並列出那個流程的時間軸；沒有流程符合時，依轉移設定顯示「沒有流程符合，送出會被擋下」或「沒有流程符合，會直接轉移」。
  - 編輯中的內容有錯誤時，列出錯誤、不顯示時間軸。選記錄時若你沒有這個模組的讀取權，會說明「你沒有這個模組的讀取權，請改用欄位值試算」。
  - 實際簽核人依送出當時的組織決定，試算只是依目前的組織預估。

### 21.10 還沒有的功能

- 同意並加簽、個人代理設定、逾期提醒。
- 模組列表頁的「簽核中」篩選。
- 批次同意（第一版不做）。

## 22. Demo 劇本：CRM 設計案與簽核

情境：業務主管接到客戶的客製需求，建一筆設計案並指派負責業務。業務把需求交給產品設計，設計人員上傳設計圖；業務拿圖給客戶確認，客戶要改就再交回設計，來回幾輪都可以。客戶確認後，業務送簽，由業務的直屬主管同意，最後主管把案子結案。客戶不登入系統，客戶的回饋由業務記在互動紀錄或任務留言。設計案這個模組的欄位與限制見 [§6.7](#67-共用主檔)，簽核的操作見 [§21](#21-簽核)。

下面的劇本同時適用 Demo 站與自己架的環境。要先有 Demo 資料（[§10](#10-系統管理demo-資料)）；Demo 資料要是含設計案的版本重新產生的，舊的 Demo 資料庫不會補上。劇本裡的簽核流程是 CRM 套件內建的「設計案主管確認」，Demo 資料產生器不另外建流程。

| 帳號 | 顯示名稱 | 在這個劇本做什麼 |
|---|---|---|
| `manager01` | 業務主管 | 建案、簽核、結案 |
| `sales01` | 業務一 | 負責業務：交設計、給客戶確認、記客戶意見、送簽 |
| `designer01` | 設計人員 | 畫圖、上傳、交回業務 |

登入頁點帳號即可，不用密碼；換人要先登出（見 [§10](#10-系統管理demo-資料) 末段）。

Demo 資料預先放了三筆設計案（左側「銷售 → 設計案」），客戶是 CRM 的虛構公司：

| 案名 | 目前狀態 | 用來示範 |
|---|---|---|
| 感測器外殼改版 | 結案 | 完整歷程 |
| 控制箱面板改版 | 客戶確認中（第二輪） | 現場送簽與主管同意 |
| 展示架結構設計 | 設計中 | 設計人員的待辦 |

Demo 站停用上傳，所以「畫圖、上傳」不能在 Demo 站現場做，改看產生器已經寫好的虛構設計圖與留言附件，可以看、可以下載。自己架的環境可以從頭跑一筆（C 段）。

### A. 看一筆走完的案子（約 5 分鐘）

1. 用 `sales01` 登入，開「銷售 → 設計案 → 感測器外殼改版」。案號是 `DC-年月-` 加三碼流水號。狀態是「結案」，詳情頁沒有「編輯」按鈕。直接開編輯網址會顯示「目前狀態為唯讀，只能變更狀態」，案名等欄位都不能改。
2. 「設計圖檔」有兩個檔案，點「感測器外殼-v2.png」下載，就是客戶最後確認的版本。
3. 明細「設計圖」有兩列：版本 1 的客戶意見是「指示燈窗改到右上角，側面加散熱槽」，版本 2 是「客戶確認此版」。
4. 「任務」區塊有五個已完成的任務：「確認需求並交設計」一個、「依需求繪製／修改設計圖」兩個、「將設計圖交客戶確認」兩個。每進入一次「設計中」或「客戶確認中」，系統就派一個，來回兩輪就各有兩個。
5. 點第一個「將設計圖交客戶確認」開任務：留言串有業務一的「@設計人員 客戶標註如附件」，附「客戶標註-v1.png」「修改說明.txt」，點檔名下載。
6. 回到設計案，看「簽核」區塊：一筆「已核准」，送出人業務一、意見「客戶已確認第二版」；簽核關卡「負責業務主管」，簽核人業務主管、意見「同意」。
7. 看「歷程」：狀態依序是 設計中 → 客戶確認中 → 設計中 → 客戶確認中 → 待主管確認 → 結案（建立時的初始狀態「需求確認」不會列成歷程項）。歷程除了狀態變更，還有設計圖與設計圖檔的變更列。

### B. 現場送簽、主管同意、結案（約 10 分鐘）

1. 用 `sales01` 登入，右上角鈴鐺有「指派給你的任務：將設計圖交客戶確認」，點開就是「控制箱面板改版」的任務。
2. 開設計案，看「設計圖檔」的第二版與明細版本 2。按「編輯」，在版本 2 的「客戶意見」填「客戶確認此版」，存檔。
3. 回到任務，把狀態改成「已完成」，按「儲存」後對話框不會自動關閉，要再按「關閉」；也可以直接勾設計案任務列的勾選框標完成。這一步要在送簽前做：送出簽核後記錄唯讀，任務與留言也跟著唯讀。另外，同一個狀態再次進入時，上一輪任務沒完成的話，系統不會再派新任務，只在留言串記一筆「規則再次觸發，但上一輪任務尚未完成，這次略過」。
4. 回設計案詳情頁，狀態區有「送出簽核：待主管確認」，按下去開對話框，標題同樣是「送出簽核：待主管確認」，列出「流程：設計案主管確認」與一關「負責業務主管」，該關下面會顯示簽核人姓名（預覽，例如「業務主管」），並註明實際簽核人依當時的組織決定。「意見（選填）」填「客戶已確認第二版」，按「送出」。送出後標題旁出現徽章「簽核中（第 1 關／負責業務主管）」，狀態仍是「客戶確認中」，記錄對所有人唯讀（[§21.2](#212-簽核中的單據)）。
5. 登出，用 `manager01` 登入。鈴鐺有「待你簽核：控制箱面板改版」；也可以開主選單「簽核」進簽核中心的「待我簽核」。打開這筆，按「同意」，意見填「同意」。
6. 設計案狀態變成「待主管確認」，「設計圖檔」欄位出現鎖頭，不能再增減檔案；其他欄位這時還能改。把狀態改成「結案」，之後詳情頁沒有編輯按鈕，編輯網址只顯示「目前狀態為唯讀，只能變更狀態」。
7. 登出，用 `sales01` 登入，鈴鐺有「已核准：控制箱面板改版」。

**退回分支**（第 5 步改這樣做）：按「退回」，選「退回發起人」，意見必填，例如「面板顏色再確認」。設計案回到「設計中」，記錄可以編輯。設計人員收到第三個「依需求繪製／修改設計圖」，業務一收到「已退回：控制箱面板改版」。改完後從第 2 步重來；舊的簽核收合在「先前的簽核」下面。

### C. 自架環境從頭跑一筆（含上傳）

上傳要開著才能做：本機用 `scripts/unattended/local-demo.sh` 啟動，或自架時不設 `Demo__LoginEnabled`，也可以設 `Attachments__UploadEnabled=true`。設計案的簽核流程由 CRM 套件內建，一般安裝也有，不必另外建立。

1. `manager01`：「設計案 → 新增」，填客戶、案名、負責業務「業務一」、設計負責人「設計人員」、需求說明，存檔（案號自動產生）。狀態是「需求確認」，業務一收到「確認需求並交設計」。
2. `sales01`：把任務標完成，設計案狀態改「設計中」。設計人員收到「依需求繪製／修改設計圖」。
3. `designer01`：開設計案，按「編輯」，在「設計圖檔」上傳一張 png 或 pdf；明細新增一列（版本 1、圖檔名稱、上傳人選自己），存檔。在任務留言「第一版完成」，標完成，再把狀態改「客戶確認中」。
4. `sales01`：收到「將設計圖交客戶確認」。下載設計圖交給客戶（系統外）。在「互動紀錄」記一筆客戶回饋；在明細版本 1 填客戶意見；在任務留言 `@設計人員`，附上客戶標註過的圖。標完成，狀態改「設計中」。
5. `designer01`：收到第二個任務與「你被提到」。上傳第二版、加明細版本 2、標完成，狀態改「客戶確認中」。
6. 接著照 B 段第 1 到 7 步。

### D. 設計人員看到的畫面

用 `designer01` 登入：鈴鐺與「我的任務」有「展示架結構設計」的「依需求繪製／修改設計圖」。設計案列表看得到三筆，沒有「新增」。打開任一筆，客戶、負責業務、設計負責人、需求說明這四欄在畫面上就是唯讀，改不了（只有繞過畫面直接呼叫 API 時，會回成功但值不變，伺服器端擋下）；「案名」可以改。「設計圖檔」在自架環境可以上傳；Demo 站停用附件上傳，編輯頁顯示「此環境已停用附件上傳」，既有附件仍可下載。

### 版型

手機（390）、平板（820）、筆電（1366）、桌機（1920）四種寬度都應能操作上面每一步，畫面不橫向捲動。

### 已知限制

- Demo 站停用上傳，設計圖與留言附件是預先產生的，可以下載，不能新增。
- 設計案在待主管確認時，只有「設計圖檔」欄位被鎖；需求說明與明細到結案才唯讀。簽核中與核准後，「設計圖檔」不能再上傳或刪除（[§21.5](#215-核准後的鎖頭)），要補圖請先撤回或退回設計。
- 設計者改公式後的整批重算會跳過簽核中與已核准的設計案（同 [§21.5](#215-核准後的鎖頭)）。
- 設計案的簽核流程「設計案主管確認」由 CRM 套件（1.3.0 起）內建，Demo 站與一般開啟的「CRM 與銷售」都有：「客戶確認中 → 待主管確認」需簽核，不能直接改狀態。流程開啟後屬於客戶，可以在簽核流程設計器修改或停用（見 [§18](#18-應用程式管理)「套件帶的簽核流程」）。
- 圖檔放在表頭的「設計圖檔」，靠檔名和明細的版本對應；明細列不能直接放附件，也不能點明細列下載。
- 簽核人是送出人（負責業務）的直屬主管，所以要由負責業務本人送簽，依欄位找主管之後才會支援。沒有部門的業務送簽，會由系統管理員頂替。
- 已經開過舊版 CRM 的資料庫不會自動多出設計案。

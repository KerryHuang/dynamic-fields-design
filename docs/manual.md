# Formwright 表匠操作手冊

這份手冊說明怎麼用 Formwright：在設計器建一個功能（模組）、加欄位、設公式與規則、分配權限，然後讓使用者在自動產生的列表與表單上操作。想先看實際畫面，可以直接開[線上 Demo](https://dynamic-modules-demo.onrender.com)。設計理由見[設計文件](superpowers/specs/2026-11-03-dynamic-modules-design.md)。

## 1. 開始之前

### 啟動

需要 .NET 8 SDK 與 Bun 1.4 以上。

```bash
cd poc/frontend && bun install && cd ../..   # 第一次才需要
poc/start.command                            # macOS；Windows 用 poc\start.cmd
```

後端在 `http://127.0.0.1:5180`、前端在 `http://127.0.0.1:9180`，就緒後自動開瀏覽器。macOS 按 Ctrl-C 停止；Windows 關掉兩個視窗即停止。

### 第一次安裝

全新資料庫只有一個管理員 `admin`，沒有任何示範使用者、群組、模具或客戶。`admin` 的初始密碼這樣決定：

- 設了環境變數 `Auth__InitialAdminPassword`，就用它（至少 8 碼，太短站台啟動失敗並說明原因）。
- 沒設，系統產生隨機密碼，只在啟動 log 以 Warning 印一次，沒抄到就得重來（見下面的緊急救援）。
- 本機用 `poc/start.command` 啟動時是 Development 環境，初始密碼為 `admin1234`。Windows 的 `poc\start.cmd` 沒有設定 Development，`admin1234` 不適用：請自己設 `Auth__InitialAdminPassword`，或到啟動 log 找系統產生的隨機密碼。

第一次用 `admin` 登入，系統會要求改密碼。引導只在「資料庫裡沒有任何啟用中且已設密碼的系統管理員」時執行，之後改環境變數不會覆寫既有密碼。

**緊急救援**：唯一的管理員忘記密碼時，在啟動環境設 `Auth__ResetAdminPassword`（至少 8 碼）再重啟。啟動時會重設 `admin` 的密碼，同時啟用帳號、解除鎖定、要求下次登入改密碼，並讓既有 session 全部失效，log 會留一筆 Warning。救回之後務必把這個設定移除，否則每次重啟都會再重設一次。

### 登入與改密碼

開網址會先到登入頁。輸入帳號與密碼；帳號不分大小寫，前後空白會被忽略，密碼則完全照打。

- 帳號不存在、密碼錯、已停用、已鎖定，畫面都只顯示同一句「帳號或密碼錯誤，或帳號暫時無法登入」，避免被人探測有哪些帳號。真正原因只寫在伺服器 log。
- 登入失敗依「帳號＋來源 IP」限流：同一組在 15 分鐘內輸錯 5 次，只擋那個來源；單一 IP 15 分鐘內失敗 20 次也會被擋。外人猜錯密碼不會讓本人登入不了。單一帳號 1 小時內累積 50 次失敗（多個來源輪流猜）時，該帳號改成每 10 秒只放行一次嘗試。**已知限制**：這時別人也可以搶在本人之前送出嘗試，所以被多個來源輪流針對的帳號，本人可能要多試幾次才登得進去（只變慢，不會被鎖死）。成功登入會清掉該來源的紀錄；站台重啟會歸零。
- 登入後停在首頁（網址 `/`），不會自動跳去別的頁面；若是從別的網址被帶來登入，登入後回到原本的網址。首頁的內容見 [§7](#7-使用模組)。
- 第一次登入與被管理員重設密碼後，會被導到改密碼頁。這段期間除了登入、登出、改密碼與取得目前使用者之外，所有 API 都回 403，不只是畫面導頁。
- 登入狀態存在 `HttpOnly` cookie 裡，8 小時內有操作會順延，關閉瀏覽器就失效。右上角選單有「變更密碼」與「登出」。被強制改密碼時看不到右上角選單，改密碼頁自己有「登出」按鈕，按了回到登入頁；自願改密碼時另有「回到系統」。登出失敗（例如斷線）時留在原頁並顯示錯誤，不會假裝已登出。
- 介面語言：登入頁與登入後右上角各有一個「語言」圖示（地球儀樣式的翻譯圖示），選單列出繁體中文、English、ไทย、Tiếng Việt。選了立即生效，不必重新整理；日期選擇器、表格分頁等內建文字也一起換。第一次開啟固定是繁中，選過之後記在這個瀏覽器，下次沿用；換瀏覽器或清除網站資料就回到繁中。被強制改密碼時看不到右上角選單，請先在登入頁選好語言。某個語言缺的文案會顯示繁中。
- 密碼至少 8 碼，沒有其他組成規則；改密碼要輸入舊密碼，新密碼不可與舊密碼相同。
- 系統不寄信，忘記密碼由管理員重設（見 [§11](#11-系統管理使用者)）。
- 停用、重設密碼、改密碼都會讓該使用者其他 session 在下一個請求立刻失效；自己改密碼時，目前這個 session 會換發新 cookie，不必重新登入。
- 後端若暫時回應異常（不是 401），會顯示公開的頁面，寫著「目前無法連線到伺服器，請稍後再試」，按「重試」重新載入原本的路徑；這種情況不會清掉登入狀態。

新建的模組只有系統管理員能用，其他群組要在權限分頁授權才看得到（見 [§5](#5-權限)）。使用者不屬於任何群組時沒有任何模組權限。

### 重設資料

停止服務後刪除 `poc/backend/data/poc.db`（旁邊的 `keys` 目錄是登入用的金鑰，可一併刪除），下次啟動會重建資料庫，只剩 `admin`，模組、使用者、群組都要重新建。

## 2. 建立模組

以系統管理員身分，從左側選單「系統管理 > 動態模組設計」進入設計器。

### 2.1 新增模組

1. 在模組清單按「新增模組」。
2. 填代碼與名稱。代碼是小寫英文開頭，可含數字與連字號，長 2 到 40 字，建立後就是網址的一部分（例如 `/dynamic/repair-request`），不能改。
3. 「選單分區」可留空。填了的話，模組在左側選單會放在這個分區底下；留空就放在「自訂功能」。建立後也能在設計器上方修改，最多 100 字。
4. 建立後系統自動配一組 ProgramCode（`DYN00001` 起），模組狀態是「草稿」，並附一個區塊和一個文字欄位，這個欄位預設是記錄標題。

名稱和其他顯示文字都有 4 個語系（繁中、English、ไทย、Tiếng Việt）；繁中必填，展開「其他語系」可填其他語言。

系統介面本身與內建應用程式（CRM 與銷售）的文案，ไทย 與 Tiếng Việt 目前是機器翻譯，對客戶上線前需要母語人士校對。

### 2.2 區塊

區塊是表單與明細頁上的分組。按「新增區塊」或區塊旁的「編輯區塊」，可設定名稱與「預設收合」；「編輯區塊」另可選「每列欄數」（1 到 3，預設 2）。欄位依順序由左到右、由上到下排；畫面寬度不到 600px 時一律 1 欄，3 欄的區塊在 600 到 1023px 寬時退成 2 欄。

### 2.3 欄位

在區塊下按「新增欄位」，填名稱、選型別。型別建立後不能更改，要改只能停用舊欄位、另建新欄位。

| 型別 | 用途與備註 |
|---|---|
| 文字、多行文字 | 可設長度上限；多行文字不能篩選、排序 |
| 整數、小數、金額、百分比 | 小數、金額、百分比可設小數位數；沒有「金額」權限的人看不到金額欄位 |
| 日期、日期時間、時間 | 日期時間一律以 +08:00 儲存 |
| 是否 | 開關 |
| Email、電話、網址 | 會檢查格式 |
| 下拉、多選 | 建立欄位後再加選項；多選不能排序 |
| 使用者 | 從使用者清單挑人 |
| 公式 | 由其他欄位算出，不能手動輸入，見 [§3](#3-公式與自動編號) |
| 自動編號 | 新增記錄時配號，不能手動輸入，見 [§3](#3-公式與自動編號) |
| 參照 | 指向另一個模組的記錄，或指向既有實體（目前只有客戶）的資料，見 [§6](#6-關聯) |

每個欄位可以設定：

- **必填、唯讀**：所有人都適用；權限與規則還能再加限制（見 [§4.4](#44-優先順序)）。
- **列表顯示**：出現在列表的欄位。
- **佔滿整列**：表單與明細頁上這個欄位自己佔一整列，不和其他欄位並排。新建多行文字欄位時預設開啟。
- **可篩選、可排序**：開了才會出現在列表的篩選與排序選單。
- **預設值**：新增記錄時帶入。下拉與多選要先加選項才能設預設值。
- **預設今天**（只有日期欄位）：新增記錄時帶入今天。表單用電腦本機的日期，沒送值時伺服器用台灣時間的今天。
- **帶表頭的值**（只有明細模組的欄位）：選表頭模組裡同型別的欄位，新增明細列時帶入表頭那個欄位目前的值，例如明細的交期帶表頭的交期。只在新增一列時帶，之後改表頭不會更新既有的明細列。

預設值、預設今天、帶表頭的值三者只能選一種；設了其中一種，另外兩種就不能設。

欄位右側可上移、下移、編輯、停用。停用的欄位從表單與列表消失，但已存的資料保留，重新啟用後就回來。被公式引用的欄位不能停用。

### 2.4 選項

下拉與多選欄位存檔後，在編輯欄位的對話框加選項，每個選項可設顏色。停用選項後，新增記錄不能再選它，但已經存著這個選項的舊記錄照樣能編輯，列表篩選也還找得到這些記錄。

### 2.5 記錄標題

設計器上方的「記錄標題欄位」決定明細頁標題，以及列表的標題欄。只能選啟用中的文字或自動編號欄位。

標題要由幾個欄位組成時（例如模具的「編號 名稱」），在下方的「標題樣板」設定：

1. 按「插入欄位」挑欄位，樣板裡會加上 `{12}` 這樣的欄位代碼（大括號內是欄位的內部編號）；欄位之間可以打空白、連字號、括號等文字。下方提示顯示標題會長什麼樣子，例如「標題會像：模具編號 名稱」。
2. 離開輸入框就存檔，既有記錄的標題立刻照新樣板重組。清空樣板，標題就回到記錄標題欄位。
3. 能放進樣板的欄位：文字、電子郵件、電話、網址、自動編號、日期、單選下拉（顯示選項名稱）。數字、參照、多選、附件、公式等不能放；樣板最長 200 字，每個欄位算 1 字（不論寫成 `{12}` 還是 `{no}`）。
4. 沒有值的欄位顯示成空的，標題頭尾的空白會去掉。改了樣板用到的下拉選項名稱，既有記錄的標題也跟著改。
5. 模組裡只要有一筆記錄已經固定（處於唯讀狀態，或已經產生連動記錄），就不能再改樣板、換記錄標題欄位或改樣板用到的選項名稱，以免改到已固定單據的標題；應用程式關閉或分錄模組也一樣不能改。

組出來的標題用在所有顯示標題的地方：列表的標題欄、明細頁標題、別的模組參照它時顯示的文字、參照挑選器的搜尋（用任何一段都找得到，例如輸入編號或名稱）、匯入時的參照比對（要填完整標題，例如 `MD-01 上蓋模`），以及報表依參照分組時的標籤。有樣板時，列表的標題欄欄名是「標題」，按欄名排序（或在「排序」裡選這一欄）就依組好的標題排序。

樣板用到的欄位跟記錄標題欄位一樣：不能停用、不能刪除、不能設成對某個群組隱藏。應用程式套件也能帶標題樣板（格式 6 起，寫欄位代號，例如 `"titleTemplate": "{no} {name}"`）。

### 2.6 啟用與停用

模組在「草稿」狀態時，一般使用者看不到。按「啟用」後左側選單出現這個模組。之後改欄位、規則、權限都即時生效，不用重新啟用。按「停用」會讓模組從選單消失，資料保留，「重新啟用」即恢復。

### 2.6.1 刪除模組、欄位、區塊

停用只是收起來，資料還在。真的要拿掉，設計器提供刪除，需要設計器的「刪除」權限，沒有這個權限的人看不到刪除入口。刪除是永久的，沒有垃圾桶。

**只有同時符合三個條件才能刪：未啟用、沒有資料、沒被引用。** 不符合時對話框會列出原因和來源，先處理再回來刪。

| 對象 | 入口 | 未啟用 | 沒有資料 |
|---|---|---|---|
| 模組 | 設計器上方「刪除模組」（草稿或停用的模組才有） | 模組不是啟用中 | 沒有未刪除的記錄 |
| 欄位 | 已停用欄位旁的垃圾桶 | 欄位已停用 | 沒有未刪除的記錄在這個欄位有值 |
| 區塊 | 區塊列的垃圾桶 | 區塊內的欄位都已停用 | 區塊內每個欄位都沒有資料 |

- **「沒有資料」只看未刪除的記錄。** 記錄刪除是軟刪除，資料其實還在資料庫裡；只剩已刪除的記錄時，視為沒有資料，可以刪。這時對話框會用警告色寫明「永久刪除」，並告訴你將一併清除幾筆已刪除的記錄、索引與異動歷程，要輸入模組代碼（欄位與區塊是勾選）才能確認。你確認的是畫面上那組筆數；確認的瞬間筆數若變了，會顯示新數字要你重新確認。
- 欄位的空值是：沒填、空白、空陣列。數字 0 與「否」算有值。公式與彙總欄位的值是算出來的，不算資料，但引用它們的東西仍會擋下。自動編號已經發給記錄，算資料。
- **被引用**指下列任一個指向它：參照欄位（含明細關係）、彙總欄位、公式、「預設帶表頭值」、規則、檢視（欄位、篩選、排序）、報表（含報表的排序鍵），以及儀表板卡片的排序鍵（指派給大家的儀表板、使用者自己的儀表板、使用者對指派版的個人版都算）。對話框會列出是哪個儀表板，個人版標示為「儀表板個人版」。停用中的公式、規則也算，因為重新啟用時會壞掉。刪整個模組時，模組自己內部的引用不算。
- 記錄標題欄位不能刪；模組至少要留一個區塊。
- 刪模組會一併清除它的區塊、欄位、選項、規則、檢視、權限設定、資料範圍與自動編號流水號；刪欄位會同時從已刪除的記錄裡拿掉這個欄位的值。
- 整個刪除在同一個交易裡：任何一步失敗就全部不動。沒有「一鍵清空全站」，要清掉一個模組的資料，請在列表一筆一筆刪除記錄（刪完才符合「沒有未刪除的記錄」）。

### 2.7 預覽

設計器的「預覽」分頁用目前的設定畫出新增表單，草稿模組也能看，不必先啟用。頂端提示「預覽使用目前的草稿設定，不會存檔」。

- 預覽以系統管理員的權限呈現：看得到全部欄位，欄位權限與群組權限不影響預覽。
- 規則照樣作用：可以在預覽裡填值，確認欄位顯示、必填、選項限制是否符合預期；按「儲存」會檢查必填等錯誤，通過後只跳出「預覽不會存檔」，不會建立記錄。
- 改了欄位或規則後，切回預覽分頁就會重新載入。
- 表頭的預覽只列已啟用的明細模組；明細模組還在草稿時，預覽裡看不到它的表格。

### 2.8 模組範本

範本是一份 JSON，裡面有一或多個模組的區塊、欄位、選項、規則、共用檢視和群組權限建議。模組清單上方的「匯入範本」只有能新增模組的人看得到，「從範本建立」還要能修改模組（套用時會逐步修改剛建的模組）；設計器上方另有「匯出範本」。實際走過的情境見[第 8 階段驗收](acceptance/phase8.md)。

**從範本建立**

1. 按「從範本建立」，選一個範本。清單標示「內建」或「已匯入」；內建範本有四個：
   - 訂單：訂單＋訂單明細。
   - 故障報修：模具報修單，含狀態流程與規則。
   - 模具保養＋客戶擴充：替既有的模具、客戶加欄位，並有保養紀錄與更換零件模組。
   - 品質異常：異常單以一般參照指向訂單。這個範本需要庫裡已經有代碼為 `order` 的訂單模組，沒有的話套用會失敗；請先套用「訂單」範本。
2. 每個模組一張卡片，可以改代碼與名稱。預設代碼是範本裡的代碼（例如 `order`、`order-line`），已經有同代碼的模組時，建立會失敗並顯示錯誤，改代碼再按一次即可。
3. 「要建立的欄位」預設全選，取消勾選的欄位不會建立：
   - 標「（必要欄位）」的不能取消，例如記錄標題欄位、明細的參照欄位。
   - 取消一個欄位時，引用它的公式、彙總、帶表頭欄位會一起取消；重新勾回時，它引用的欄位也一起勾回。
   - 引用了被取消欄位的規則不會建立。例如訂單取消「取消原因」，規則就少了「取消時顯示取消原因」「取消時必填取消原因」兩條。
4. 按「建立」。所有模組在同一個交易裡建出，任何一步失敗就整批不建；成功後是草稿狀態，畫面跳到第一個模組的設計器。檢查過後照 [§2.6](#26-啟用與停用) 啟用。

範本只帶群組的動作權限與資料範圍。欄位權限、選項範圍、個人權限要建好後到權限分頁補（所以單獨套用「品質異常」時，沒有「重大只有品保能選」「責任單位對業務唯讀」「不良率對現場人員隱藏」這些設定，要到權限分頁自己加）；範本提到的群組在這個資料庫不存在時直接略過。內建「訂單」範本的建議是：業務可讀取、新增、修改並有金額權限，資料範圍本人；業務主管再加刪除、列印匯出，資料範圍全部；現場人員只能讀取、沒有金額權限，資料範圍全部，所以看不到單價、金額與各項合計。

**匯出範本**

在設計器按「匯出範本」，下載 `{代碼}.template.json`。內容是這個模組，加上以它為表頭的所有明細模組。

- 只匯出啟用中的欄位與選項、共用檢視（不含個人檢視）、群組權限。
- 範本內表達不了的東西直接略過，寫在檔案的 `warnings`：彙總了範本外的模組、引用停用欄位的公式或規則；明細的「帶表頭的值」指向範本外的欄位時，只拿掉這個設定。畫面上不會另外提示，匯出後可以打開檔案看 `warnings`。

**匯入範本**

按「匯入範本」選 JSON 檔（最大 1 MB）。系統先檢查格式：代號、欄位引用、公式循環、規則引用的欄位與選項；有錯就列出全部錯誤，不匯入。通過後跳出「已匯入範本：名稱」，之後「從範本建立」的清單就有它。

- 範本代碼（檔案裡的 `key`）不能和內建或已匯入的範本重複，重複回「範本代碼已存在」。拿匯出檔到同一個資料庫再匯入時，要先改 `key`。
- 匯入的範本不能刪除或覆蓋，要換內容就改代碼另外匯入。
- 格式檢查不看各型別的設定內容（例如自動編號格式），這類錯誤要到「從範本建立」時才會擋下。

哪些範本功能沒有在畫面上實際操作過、只靠自動測試，見[第 8 階段驗收的「未實機驗證」](acceptance/phase8.md#未實機驗證)。

## 3. 公式與自動編號

### 3.1 公式

欄位型別選「公式」後，填運算式、結果型別（數字、金額、日期）與小數位數。

- 用 `{欄位編號}` 引用同一筆記錄的數字或日期欄位。欄位編號就是設計器欄位清單上 `f_` 後面的數字，也可以用「插入欄位」下拉插入。
- 可用 `+ - * /`、括號，以及以下函式：

| 函式 | 說明 |
|---|---|
| `ROUND(x, n)` | 四捨五入到 n 位 |
| `IF(條件, a, b)` | 條件成立取 a，否則取 b；比較運算子只能用在這裡的第一個參數 |
| `DATEDIFF(a, b)` | 回傳 a − b 的天數 |
| `DATEADD(d, n)` | 日期 d 加 n 天 |
| `TODAY()` | 今天 |

- 百分比欄位以「值 ÷ 100」參與運算，例如 5% 算成 0.05。
- 運算式有錯時，存檔會在運算式下方顯示原因，例如「公式不正確：欄位 99 不存在或未啟用」。
- 公式在記錄存檔時由伺服器計算，表單上看到的是上次存檔的結果。含 `TODAY()` 的公式不會每天自動重算，要等記錄再次存檔。
- 修改運算式、重新啟用公式欄位時，既有記錄會全部重算。
- 公式引用的任何一個欄位，只要某人看不到，這個公式對他也會隱藏。

### 3.2 自動編號

欄位型別選「自動編號」後填編號格式，下方會即時顯示範例。

- 變數：`{yyyy}`、`{yy}`、`{MM}`、`{yyyyMM}`，以及恰好一組 `{0000}`。`0` 的個數就是流水號位數。
- 格式含月份就每月從 1 重新編號，只含年份就每年重新編號。
- 例：`REP-{yyyyMM}-{0000}` 在 2026 年 11 月依序產生 `REP-202611-0001`、`REP-202611-0002`。
- 只在新增記錄時配號，之後不會變。加入這個欄位之前已存在的記錄不會補號。

自動編號很適合當記錄標題（[§2.5](#25-記錄標題)）。

## 4. 規則

規則讓欄位依其他欄位的值變化：出現或隱藏、變必填、變唯讀、檢查資料、限制下拉選項。在設計器的「規則」分頁設定，每個模組最多 100 條。

### 4.1 新增規則

1. 按「新增規則」，選種類。
2. 設條件：選「全部符合」或「任一符合」，再逐條加條件（欄位、運算子、值）。不加任何條件就是「永遠成立」。
3. 選目標，然後按「儲存」關閉對話框。
4. 回到規則清單後按「儲存規則」，整份清單才會寫入。沒按就離開，剛才的修改不會保存。

清單上每條規則都可以上移、下移、停用、編輯、刪除。同一個目標有多條規則時，合併方式見下表。

| 種類 | 條件成立時 | 可選的目標 | 多條規則作用同一目標 |
|---|---|---|---|
| 顯示 | 顯示目標；不成立就隱藏 | 欄位、區塊 | 全部成立才顯示 |
| 必填 | 目標變必填 | 欄位 | 任一成立就必填 |
| 唯讀 | 目標變唯讀 | 欄位、區塊、整筆記錄 | 任一成立就唯讀 |
| 驗證 | 代表資料正確；不成立就報錯 | 欄位 | 各自檢查 |
| 選項限制 | 下拉欄位只剩勾選的選項 | 一個下拉欄位 | 取交集 |

- **驗證**要填驗證訊息，這段文字會顯示在目標欄位下方。
- **選項限制**要先選下拉欄位，再勾允許的選項，至少勾一個。
- 區塊當目標時，作用在區塊裡的每個欄位；區塊內欄位全部被隱藏時，整個區塊不顯示。

### 4.2 條件怎麼判斷

- **空值**：條件欄位沒填時，只有「是空的」「不等於」「不包含於」成立，其他運算子一律不成立。
- **比較另一個欄位**：運算子是等於、不等於、大於、大於等於、小於、小於等於時，「比較對象」可以切成「另一個欄位」，下拉只列同一類（數字、日期或文字）的欄位。
- **跨欄位驗證要允許空值**：例如「需求日不得早於申請日」要寫成「任一符合：需求日是空的、需求日 大於等於 申請日」，否則需求日沒填也會報錯。
- **文字比較**：區分大小寫，值前後的空白會先去掉。
- **相對日期**（未來 N 天內、過去 N 天內）：以台灣時間（+08:00）的今天為準。
- 條件群組可以巢狀；遇到巢狀群組時，編輯器改成直接編輯 JSON。

### 4.3 唯讀規則看的是「已存檔的值」

唯讀規則依記錄存檔時的值判斷，不看表單上剛改的值，所以：

- 新增記錄時，唯讀規則一律不生效。
- 在表單把狀態改成「已結案」，不會當場鎖住，可以正常存檔。下次打開編輯時，整張表單才變唯讀，頂端顯示「此記錄目前不可修改」，也沒有儲存鈕。
- 記錄被整筆鎖住後，任何修改都會被伺服器擋下，回同一句訊息。

### 4.4 優先順序

權限 > 規則 > 欄位設定：

- 權限設成看不到或唯讀的欄位，規則不能讓它變可見、可編輯。
- 規則可以在欄位設定之上再加必填或唯讀。
- 被規則隱藏的欄位不檢查必填，但如果它的值有改，照樣會送出存檔。
- 使用者改不了的欄位（權限唯讀、欄位唯讀、規則唯讀），不檢查選項是否在可選範圍。

### 4.5 注意事項

- **條件含公式或自動編號欄位**時，編輯規則的對話框會提示：表單上不會即時套用，存檔時才由伺服器判斷。新增記錄時伺服器也還沒配號，所以引用自動編號的條件在新增時看到的是空值。
- **條件引用某些人看不到的欄位**時，這條規則不會送給那些人，他們的表單不會即時反應，但伺服器存檔時照樣判斷。設計時盡量別讓一般使用者的規則依賴他們看不到的欄位（spec §15 第 24 條）。
- **下拉連動的舊值**：上層欄位改了以後，下層欄位留著的舊選項若不在新的允許範圍，存檔時會顯示「選項不在可選範圍」，要重選下層欄位。
- 錯誤若發生在目前沒顯示的欄位，會出現在表單頂端，格式是「欄位名稱：訊息」。

## 5. 權限

設計器的「權限」分頁有四塊，改完按「儲存權限」。新建的模組預設除了系統管理員以外沒有人有權限。

### 5.1 群組權限與資料範圍

每個群組各有 7 項動作權限：讀取、新增、修改、刪除、列印匯出、金額、核准。

- 沒有「讀取」就完全看不到這個模組，選單也不出現。
- 沒有「金額」的群組看不到所有金額欄位，連帶看不到引用金額的公式。
- **資料範圍**決定看得到哪些記錄：本人（擁有者是自己的記錄）、同群組（擁有者和自己同群組的記錄）、全部。新增記錄時，擁有者就是建立的人。同一個人屬於多個群組時，取範圍最大的那個。

### 5.2 個人權限

按「新增使用者」可以替特定使用者另外加權限。有效權限是個人權限與群組權限逐項合併，任一邊有就算有。

### 5.3 欄位權限

可以替每個群組把個別欄位設成「唯讀」或「隱藏」，沒設就是「預設」。同一個人屬於多個群組時，任一群組設成隱藏就隱藏（限制優先）。

### 5.4 選項範圍

限制某些群組只能選下拉欄位的部分選項。沒有指定群組的選項，所有人都能選。

## 6. 關聯

### 6.1 參照欄位

新增欄位時選「參照」，要設定：

- **目標種類**：「動態模組」或「既有實體」。動態模組的目標必須是一般模組（不是擴充模組），可以選自己這個模組（例如「上層設備」）；既有實體目前只有客戶。
- **目標被刪除時**（只有目標是動態模組時才有）：目標記錄被刪除時，參照它的記錄要怎麼處理。

| 目標被刪除時 | 意思 |
|---|---|
| 禁止刪除（預設） | 還有記錄參照，目標就不能刪除，並列出是誰在參照 |
| 清空欄位 | 目標刪除後，參照它的記錄這個欄位變空白；不能用在必填欄位 |
| 連帶刪除 | 目標刪除後，參照它的記錄一起刪除，最多連鎖 5 層 |

其他限制：

- 目標一旦建立就不能改，要改只能停用舊欄位、另建新欄位；「目標被刪除時」之後還可以改。
- 參照欄位不能設預設值、長度、格式與排序，不能用在公式，也不能當記錄標題。
- 參照欄位一律建索引，所以不必另外開「可篩選」；篩選可用「等於」「不等於」「是其中之一」「不是其中之一」「是空的」「不是空的」。

### 6.2 在表單與明細裡使用

- 表單上的參照欄位是一個挑選框，按下去開搜尋視窗，輸入關鍵字（比對標題）後挑一筆，「清除」可以清空。只列得出你有權讀取、且在你資料範圍內的記錄。
- 明細與列表顯示目標的標題；目標是動態模組時，標題是連結，點了到目標的明細頁。
- 目標已被刪除，或既有實體已失效，顯示「已失效」，沒有連結。你沒有目標模組的讀取權限、目標不在你的資料範圍，顯示「無權限檢視」，同樣沒有連結。
- 存檔時，新選的目標不存在或你選不到，會顯示「參照的資料不存在或無權選取」。已經存好的舊值就算之後失效，只改別的欄位照樣存得進去。

### 6.3 反向關聯分頁

記錄的明細頁，會替每個「指向這個模組、且你有權讀取」的參照欄位多一個分頁（分頁名稱是「模組名稱 · 欄位名稱」），列出參照這筆記錄的來源記錄，依建立先後由新到舊，只列你資料範圍內的。你有來源模組的新增權限、且能寫入那個參照欄位時，分頁上有「新增」鈕，帶你到來源模組的新增表單，參照欄位已經填好這筆記錄。

### 6.4 刪除被擋時

刪除一筆被參照的記錄，若某處設定的是「禁止刪除」，整筆刪除都不會執行（包含連帶刪除的部分），並跳出對話框：「還有其他資料參照這筆記錄，不能刪除」，列出最多 10 筆參照來源（模組、欄位、記錄標題；你沒有讀取權的記錄不顯示標題）與總數。先處理掉這些參照再刪除。連帶刪除超過 5 層時也會擋下，要先手動刪除下層資料。

### 6.5 擴充模組

擴充模組替「既有實體」的資料加自訂欄位，不另外維護一份主檔。

1. 新增模組時選「擴充模組」，再選要擴充的既有實體（目前只有客戶）。同一個實體只能有一個擴充模組；種類與實體建立後不能改。
2. 擴充模組沒有標題欄位，也不能設定；記錄標題取自既有資料（例如 `C-001 嵐岳精密`），新增時存下當時的標題。
3. 新增擴充資料時，表單最上面先挑既有資料；存檔後不能再換。
4. 每筆既有資料只能有一筆擴充資料，重複新增會顯示「這筆既有資料已經有擴充資料」。刪除後可以再建。
5. 其他模組的參照欄位不能指向擴充模組，要透過既有實體參照。

### 6.6 表頭與明細、彙總

**把模組設成明細**

1. 先建好表頭模組（例如訂單），再建明細模組（例如訂單明細）。
2. 在明細模組加一個參照欄位，目標選表頭模組，「關聯方式」選「明細」。這個欄位自動必填、表頭刪除時一起刪除；建立後不能改回一般參照，也不能停用。一個模組只能有一個明細欄位。
3. 明細模組不會出現在左側選單，也不能單獨打開；它的記錄只在表頭的表單與明細頁裡出現。模組清單會標示「明細：表頭名稱」。
4. 自動編號欄位在明細模組裡可以打開「在表頭內編號」：每張表頭的項次從 1 開始，格式不能含日期。刪掉的項次不會重用。

**明細的權限**

明細模組沒有自己的群組與個人權限：能看、能改表頭，就能看、能改它的明細；明細列的擁有者跟著表頭。權限分頁只能設定欄位例外與選項範圍。

**在表單裡編輯明細**

- 表頭表單下方，每個明細模組一張表格：「新增一列」加列、每列右側的按鈕刪列。存檔時表頭與明細一起送出，一個明細模組最多 200 列。
- 驗證錯誤顯示在出錯的那一格；改過那一格錯誤就消失。
- 規則逐列判斷，例如某列符合唯讀條件，那一列就不能改。表頭整筆唯讀時，明細表格也全部唯讀。
- 明細頁在欄位下方以唯讀表格列出明細。

**彙總欄位**

欄位型別選「彙總」，設定：

- **來源欄位**：其他模組指向本模組的參照欄位，明細或一般參照都可以（例如維修紀錄的「申請單」）。
- **函數**：加總、計數、最小、最大。計數不用選彙總欄位。
- **彙總欄位**：來源模組的數字、金額或日期欄位；彙總欄位本身、引用彙總欄位的公式不能選。
- **條件**（選填）：只計入符合條件的子記錄，例如「狀態 等於 已完成」。

結果型別與小數位數由伺服器依彙總欄位決定。沒有子記錄時，加總與計數是 0，最小與最大是空白。彙總只算一層：被彙總的欄位不能再是彙總。

**什麼時候重算**

- 子記錄新增、修改、刪除（含連帶刪除、清空參照、改指向另一筆）時，重算受影響的父記錄。
- 子記錄所在模組的公式重算時、彙總欄位新增、修改設定或重新啟用時，整個模組重算一次。
- 重算不改修改者與修改時間；值有變才更新記錄版本，所以有人正在編輯父記錄時，存檔可能收到「資料已被其他人修改」。
- 表單上不即時計算，存檔後才看到新的合計。
- 彙總計入所有子記錄，不看你能看到哪些；結果是金額的彙總，沒有金額權限的人看不到。
- 明細模組若另有一個一般參照也指向同一個表頭模組，靠這個參照做的彙總在存表頭時不重算，要等整個模組重算（例如修改彙總設定）時才更新。

範例（[第 6 階段驗收](acceptance/phase6.md)）：訂單明細的金額 `{數量} * {單價}`；訂單的未稅合計是加總金額、稅額 `ROUND({未稅合計} * {稅率}, 0)`（百分比欄位已是小數，不用再除以 100）、含稅總額 `{未稅合計} + {稅額}`。

## 7. 使用模組

**首頁**：登入後看到的第一個畫面，左側選單最上方的「首頁」或點左上角的產品名都能回來。內容由上而下是：

- 歡迎區：你的姓名與產品名。
- 最近開過：你最近打開的模組，最多 5 個，記在這個瀏覽器裡、依使用者區分；換瀏覽器或裝置會重新累積，瀏覽器不讓網站存資料時這一區不顯示。已停用或沒有讀取權限的模組不會列出。
- 我的應用：你有權限的模組卡片，分區方式與左側選單相同，點卡片進入模組。完全沒有可用模組時會說明並請你聯絡系統管理員。
- 報表：連到「我的報表」。
- 系統管理：只有對應權限的人看得到，項目與左側選單「系統管理」相同。

首頁沒有待辦、通知或統計數字，這些功能平台尚未提供。

模組啟用並授權後，左側選單會出現這個模組。沒有設定選單分區的模組放在「自訂功能」底下；有分區的依分區名稱分組，「自訂功能」排最前面，其餘分區依名稱排序。

### 7.1 列表

- **搜尋標題**：依記錄標題做關鍵字搜尋，不分大小寫。
- **篩選**：按「篩選」，選「全部符合」或「任一符合」，再逐條加條件。可用的運算子依欄位型別而定；「包含於」「不包含於」以逗號或換行分隔，最多 50 個值。
- **排序**：點表頭依序切換升冪、降冪、取消；要多欄排序用排序編輯器。空值一律排最後。
- **顯示欄位**：勾選要顯示的欄位，並可上移、下移調整順序。
- **檢視**：把目前的篩選、排序、欄位存成檢視，可勾「共用給所有人」或「設為預設檢視」。個人檢視只有自己看得到；共用檢視所有人都能套用，但只有建立的人能更新與刪除。進入列表時自動套用自己的預設檢視。
- 檢視裡的欄位如果之後被停用，或不再開放篩選、排序，列表會提示「此檢視有 N 個欄位已停用或不再開放篩選、排序，已略過」。

### 7.2 新增、編輯、明細、刪除

- 列表按「新增」開表單；存檔後到明細頁，公式與自動編號的結果在這裡出現。
- 明細頁按「編輯」修改、按「刪除」刪除（刪除前會再確認）。
- 規則在表單上即時作用：欄位依條件出現或消失、標上必填記號、下拉只剩允許的選項、驗證錯誤送出前就顯示。
- 兩個人同時編輯同一筆時，後存的人會看到「資料已被其他人修改，請重新載入」，重新載入後再改。
- 下拉選單都能直接打字篩選選項；沒有符合時顯示「沒有符合的選項」。

### 7.3 歷程

明細頁最下面的「歷程」卡片列出這筆記錄的變更，最新的在最上面，每頁 20 筆：

- **新增、刪除**：一列「建立了這筆記錄」「刪除了這筆記錄」。
- **修改**：每個有變的欄位一列，顯示修改前與修改後的值。下拉顯示選項名稱、參照顯示對方的標題、使用者顯示名稱。一次存檔什麼都沒變，不會留下歷程。
- **明細列**：表頭的歷程也包含它的明細列，前面標「明細模組名稱 › 列標題：」，例如「訂單明細 › 甲：數量」。刪掉的明細列，歷程照樣看得到。
- **清空參照**：刪除被參照的記錄、而參照欄位設成「清空欄位」時，被清空的那筆記錄多一列修改，修改者是發起刪除的人。

幾點要注意：

- 公式、彙總、自動編號欄位由系統計算，它們的變化不記；設計器改公式觸發的重算也不記。
- 你看不到的欄位，它的歷程也看不到。例如沒有金額權限的人，看不到單價改了幾次。
- 參照的標題是看歷程當下查的：對方改名後，舊歷程也顯示新名稱；對方被刪除後顯示「（已刪除）」。

### 7.4 匯出

列表右上角「匯出」選 CSV 或 Excel，下載目前篩選、排序、搜尋後的全部記錄（不分頁）。需要「列印匯出」權限，沒有這個權限就看不到「匯出」按鈕。

- 欄位是你看得到的啟用欄位，依區塊與欄位順序；第一列是欄位名稱，不含記錄 id、擁有者與修改時間，所以匯出檔可以直接拿去匯入。
- 值和畫面一樣：下拉是選項名稱、是否欄位是「是」「否」、日期是 `2026-11-05`、參照是對方的標題。
- 沒有金額權限的人，匯出檔沒有金額相關的欄位（整欄不含，不是空白）。
- CSV 是含 BOM 的 UTF-8，Excel 直接打開不會亂碼。數字、百分比以外的欄位（文字、下拉、使用者、參照標題等）以 `=`、`+`、`-`、`@` 開頭時，前面加一個 `'`，避免 Excel 當成公式執行；匯回時會自動去掉。參照標題來自別的模組裡使用者輸入的文字，所以也要防。
- 一次最多 10000 筆，超過時會提示「匯出最多 10000 筆，請加篩選條件」。
- 檔名是「模組代碼-日期-時間」，例如 `p7-order-20261104-1549.csv`。

### 7.5 匯入

列表右上角「匯入」，選一個 CSV 檔。需要「新增」權限；擴充模組不能匯入。

1. 選好檔案後先預覽，不會寫入任何資料：
   - **檔案欄位與對應欄位**：表頭先比對欄位代碼（例如 `f_12`，設計器的欄位設定裡看得到），再比對欄位名稱（任一語系、不分大小寫）。略過的欄位會寫原因：「系統計算的欄位」（公式、彙總、自動編號）、「唯讀欄位」、「找不到這個欄位」；名稱同時對到好幾個欄位時是「對到多個欄位，請改用欄位代碼」，把表頭改成欄位代碼即可。兩欄對到同一個欄位時整個檔案退回，訊息是「欄位「名稱」重複」。
   - **共 N 筆，M 筆可匯入**，下面列出有錯的列：行號就是檔案裡的行號（表頭是第 1 行），可以直接對照檔案修改。
2. 有任何一列錯誤時，「確認匯入」不能按，畫面提示「修正檔案後重新選擇」。改好檔案再選一次。
3. 全部通過後按「確認匯入」，伺服器會重新檢查整個檔案，全部通過才一起新增；完成後顯示「已匯入 N 筆」。

值的寫法：

- 和匯出檔相同：下拉填選項名稱、使用者填帳號或名稱、參照填對方的標題（完全相同才算找到，同名多筆會報錯）、是否欄位填「是」「否」（也接受 true／false、yes／no、1／0）。
- 數字可以有千分位逗號（必須每三位一個，`1,234.5` 可以，`1,5` 會看到「請輸入數字」），百分比可以帶 `%`；日期可以是 `2026-11-05` 或 `2026/11/5`。
- 空白格視同沒填，欄位有預設值時套用預設值。
- 每筆的自動編號、擁有者（匯入的人）與歷程，都和手動新增一樣。
- 匯出再匯回不一定完全相同的情況：日期時間只到分鐘，秒數會變成 0；文字原本就以 `'=` 這類開頭時，匯回會少掉 `'`；選項名稱含 `;` 的多選會被拆開；同名的使用者用名稱對不到（改填帳號）；參照顯示「（無權限）」「（已刪除）」的格子匯回會找不到。

檔案限制：

- 必須存成 UTF-8 的 CSV。繁中 Windows 的 Excel「另存 CSV」預設是 Big5，會看到「請把檔案存成 UTF-8 的 CSV」；請改選「CSV UTF-8」格式。
- 檔案最大 1 MB、最多 1000 筆；空白列不算。
- 匯入只新增，不會更新既有記錄，也不含明細列。

## 8. 範例：模具維修申請

這是[第 4 階段驗收](acceptance/phase4.md)實際走過的情境，截圖都在 `docs/acceptance/phase4/`。

1. 設計器新增模組 `repair-request`（模具維修申請）。
2. 欄位：
   - 申請人（文字，必填）
   - 申請日、需求日（日期）
   - 故障類別（下拉：模具損壞、機台異常、外包）
   - 故障細項（下拉：模仁崩裂、頂針斷裂、油壓異常、加熱失效、委外修復）
   - 外包廠商（文字，必填）
   - 預估費用（金額）
   - 狀態（下拉：草稿、已結案）
3. 加公式欄位「距需求日天數」：`DATEDIFF({需求日的編號}, {申請日的編號})`，結果型別為數字、小數位數 0。
4. 加自動編號欄位「申請單號」：`REP-{yyyyMM}-{0000}`，並設成記錄標題。
5. 規則分頁新增：
   - 顯示：故障類別 等於 外包 → 外包廠商。外包廠商本身設了必填，但被隱藏時不檢查，所以只有選外包時才必填。
   - 驗證：任一符合「需求日是空的、需求日 大於等於 申請日（另一個欄位）」→ 需求日，訊息「需求日不得早於申請日」。
   - 選項限制 3 條：模具損壞 → 模仁崩裂、頂針斷裂；機台異常 → 油壓異常、加熱失效；外包 → 委外修復。
   - 唯讀：狀態 等於 已結案 → 整筆記錄。
   - 必填：預估費用 大於 1000 → 外包廠商。
6. 按「儲存規則」，再到「權限」分頁給「現場人員」讀取、新增、修改，不給金額，資料範圍全部。
7. 啟用模組，登出後用不同帳號登入實際操作：
   - 選外包才出現外包廠商；故障細項只剩對應的選項。
   - 需求日早於申請日時，送出前就擋下。
   - 存檔後明細顯示 `REP-202611-0001` 與天數。
   - 狀態改成已結案存檔，再打開編輯時整張唯讀。
   - 切到現場人員，表單沒有預估費用，其他規則照樣作用；引用預估費用的必填規則不會送給他。

## 9. 已知限制

目前刻意不處理、或正式上線前要再確認的事，完整清單見設計文件 §15。和操作直接相關的：

- 沒有寄信重設密碼，忘記密碼只能由管理員重設。
- 沒有公司帳號（AD、SSO）登入，也沒有雙因素驗證與自助註冊。
- 舊資料庫裡的使用者沒有密碼，無法登入；要由 `admin` 逐一重設密碼，或直接刪庫重建。
- 列表的「使用者」欄位仍顯示帳號，不是姓名。
- `Demo__LoginEnabled` 絕不能在正式站開啟，開了就等於不驗密碼就能登入。
- 登入失敗的計數用程序內的鎖保護，假設每家客戶只跑一個後端 instance；多個 instance 並行時要改成資料庫層的原子更新。
- Docker 部署要把資料庫目錄（預設 `/app/data`）掛成 volume，登入用的金鑰才會保留；沒掛的話，每次重建容器所有人都要重新登入，資料也會一起清空。
- Swagger 只在 Development 環境開放，正式站沒有。
- 直接呼叫 API 仍可把記錄指派給已停用的使用者；畫面上選不到。
- 在 Render 上，反向代理後 cookie 帶 `secure; samesite=lax; httponly`（2026-11-05 實測）。

- 前端的「今天」用電腦本機日期，後端用台灣時間；不在 UTC+8 的電腦，跨日前後可能和伺服器差一天（§15 第 26 條）。
- 自動編號在 SQLite 上不會重號；換成 SQL Server 時要另外處理同時取號（§15 第 23 條）。
- 修改公式會在一次交易內重算整個模組的記錄，期間有人正在編輯的話，會看到「資料已被其他人修改」（§15 第 21 條）。
- 同時被規則隱藏、又受選項限制的下拉欄位，若留著超出範圍的舊值，會卡住存檔，要先把上層欄位改回去並清掉它（§15 第 27 條）。
- 既有實體（目前只有客戶）不檢查權限，任何登入的人都挑得到（§15 第 28 條）。
- 連帶刪除只看你對發起刪除的那筆有沒有刪除權，不檢查被連帶刪除的來源模組（§15 第 29 條）。
- 刪除被參照的記錄時，若同時有人新增參照或修改來源記錄，SQLite 上不會出事，換成 SQL Server 要另外處理（§15 第 31 條）。
- 彙總計入所有子記錄，不看讀者的資料範圍，只看得到本人資料的人可以從合計推測別人的記錄（§15 第 32 條）。
- 子記錄存檔會重算並更新父記錄，正在編輯父記錄的人存檔會收到「資料已被其他人修改」（§15 第 33 條）。
- 逐列編輯明細時，金額與合計要存檔後才更新（§15 第 34 條）。
- 公式、彙總、自動編號的變化，以及系統重算，都不寫歷程（§15 第 38 條）。
- 歷程裡的參照標題是現在的名稱，不是當時的名稱；對方刪除後顯示「（已刪除）」（§15 第 39 條）。
- 匯入只新增、不更新，不含明細列；擴充模組不能匯入（§15 第 40 條）。
- 匯出上限 10000 筆、匯入上限 1000 筆（§15 第 41 條）。
- 沒有金額權限時，匯出檔整欄不含金額欄位，而不是留空（§15 第 42 條）。
- 設計器預覽看不到還在草稿的明細模組（§15 第 44 條）。
- 選單分區只有一種語系，切換語系時不會翻譯（§15 第 45 條）。
- 範本只帶群組權限，欄位權限、選項範圍、個人權限要建好後自己補（§15 第 47 條）。
- 匯入的範本不能刪除或覆蓋，同代碼再匯入會被拒（§15 第 48 條）。
- 範本改了，已經從範本建出的模組不會跟著更新（§15 第 49 條）。
- 匯出範本時表達不了的引用直接略過，只寫在檔案的 `warnings`（§15 第 50 條）。
- 匯入範本只檢查結構，型別設定的錯誤要到從範本建立時才發現（§15 第 51 條）。
- 「預設今天」在表單用電腦本機日期，伺服器用台灣時間（§15 第 52 條）。
- 「帶表頭的值」只在新增明細列時帶入，改表頭不會更新既有明細（§15 第 53 條）。
- 從範本建立是逐條重播設計器指令，新模組的版本號一開始就大於 1（§15 第 54 條）。
- 產生 Demo 資料期間（本機約數十秒），整個 SQLite 資料庫由一個寫入交易鎖住，其他人的寫入要等它結束，等太久會逾時（見 [§10](#10-系統管理demo-資料)）。
- 「已產生」只看四組範本的模組代碼是否都存在，沒有另外的標記；部分存在時整批不做，也不提供補齊或清除。
- 品質異常範本需要庫裡已有 `order` 模組，沒有時套用失敗。
- 欄位層權限（重大只有品保能選、責任單位對業務唯讀、不良率對現場人員隱藏）與選項範圍是 Demo 產生器補的；單獨「從範本建立」這三個新範本時沒有，和訂單範本一致。
- Demo 的反向關聯只示範在更換零件、訂單的品質異常、報修單的關聯報修單。
- Demo 資料的稽核時間是模擬的，最晚到昨天；「建立時間」不是真實產生的時間。

## 10. 系統管理：Demo 資料

系統管理員可以一鍵產生一批像真的業務資料，用來示範、試用或教育訓練。入口是左側選單「系統管理 → Demo 資料」。各情境怎麼示範見 [Demo 腳本](demo.md)。

**會產生什麼**：訂單、故障報修、模具保養（含 MES 自己的模組 mes-mold「模具資料」與客戶的擴充）、品質異常四組模組，共數百筆記錄；記錄的建立者、日期與變更歷程都是模擬的，日期以產生當天為基準往前展開，所以任何時候打開都有逾期與本週到期的資料。同一天產生兩次內容相同。

**狀態**

| 狀態 | 畫面 | 按鈕 |
|---|---|---|
| 尚未產生 | 「尚未產生」 | 可按 |
| 產生中 | 「產生中（已完成／總步數）」 | 停用，轉圈 |
| 已產生 | 「已產生」 | 停用 |
| 已有同代碼的模組 | 列出衝突項目，例如「模組代碼 order 已存在」 | 停用 |
| 產生失敗 | 紅字顯示失敗原因 | 可再按 |

剛開始總步數還是 0，這時只顯示「產生中」，不顯示已完成與總步數。

**操作**

0. 登入頁要列出 Demo 帳號，需要 `Demo__LoginEnabled=true`（只限 Demo 站，見 [§9](#9-已知限制)）。
1. 以 `admin` 開「系統管理 → Demo 資料」，按「產生 Demo 資料」。
2. 看進度到「已產生」。整批在同一個交易裡，任何一步失敗就整批回滾，不會留下殘缺資料。
3. 左側選單出現四組模組：訂單、故障報修、模具保養紀錄與品質異常，以及 MES 自己的模組 mes-mold「模具資料」與「客戶」的擴充。

**注意**

- 要有設計器的新增與修改權限才能按；沒有時按鈕顯示但停用。
- 只在四個範本的模組代碼與兩個擴充都不存在時才產生；任何一個已存在就整批不做，並列出衝突項目，不覆寫既有資料。
- 部署時設環境變數 `Demo__SeedOnStartup=true`，站台啟動後會在背景自動產生（本機預設關閉）。失敗只寫 log，不影響站台啟動。Render 改用 `poc/Dockerfile.demo`，在建置映像時執行 `--generate-demo-data` 產生好資料，失敗就建置失敗、舊版繼續運作；代價是資料日期停在建置那天。
- 沒有清除或重設按鈕：本機停止服務後刪 `poc/backend/data/poc.db`；Render 重啟就回到映像裡的 Demo 資料。

Demo 登入：設環境變數 `Demo__LoginEnabled=true`（Render 設定檔已開啟，預設關閉，啟動時 log 會印 Warning）。登入頁會多列一份帳號清單，點一下就以該身分登入，不驗密碼；換人要先登出再點另一個帳號。清單只列啟用中的 Demo 帳號加上 `admin`。Demo 資料還在產生時，清單只有 `admin`，並顯示「正在產生 Demo 資料，完成後這裡會出現可用的帳號」。Demo 模式下 `admin` 不會被強制改密碼。Demo 帳號沒有密碼，不能用密碼登入。

## 11. 系統管理：使用者

本節的「重設密碼」、編輯既有使用者與「已鎖定」標示未實機驗證（走查時沒有在畫面上操作）；新增使用者（含加入兩個群組）已實機驗證。停用使用者是用 API 驗證，沒有在畫面上按停用鈕。

左側選單「系統管理 → 使用者」，只有系統管理員看得到，伺服器端也會檢查，否則回 403。可以有多位系統管理員。

欄位有帳號、姓名、群組（可多個）、狀態（啟用或停用）、系統管理員，另外會標示已鎖定的帳號。

- **新增**：填帳號、姓名、初始密碼與群組。帳號存小寫，格式是 2 到 50 個英數字或 `.`、`_`、`-`，建立後不能改，因為記錄、歷程與檢視都用它關聯。新使用者第一次登入必須改密碼。帳號重複會顯示錯誤。
- **編輯**：可改姓名、群組、是否為系統管理員。
- **重設密碼**：管理員輸入新的臨時密碼，同時解除鎖定、要求改密碼，並讓這個人既有的 session 失效。
- **停用與啟用**：不提供刪除。停用後不能登入，既有 session 在下一個請求就失效，也不再出現在使用者欄位的下拉選項與權限畫面的挑選清單；舊記錄與歷程仍正常顯示名稱。
- **防呆**：不能停用或取消最後一位啟用中的系統管理員，也不能停用自己，兩者都由伺服器擋。

一個人可以同時屬於多個群組，他的模組權限是各群組授權的合併。權限本身不在這裡設，沿用各模組的權限分頁。匯入 CSV 時，使用者欄位只接受啟用中的帳號。

## 12. 系統管理：群組

本節只實機驗證了新增群組，改名、維護成員、刪除群組的影響對話框與擋下，都未實機驗證（由前端單元測試與後端測試涵蓋）。

左側選單「系統管理 → 群組」，權限同上。欄位是名稱與成員數。

- **新增**：只填名稱，內部代碼由系統產生（`g-` 加短亂碼），不可改。
- **改名**：畫面只編輯目前語系的名稱，其他語系沒填就用既有的備援。
- **成員**：可以從群組這邊「維護成員」，也可以從使用者那邊改，兩邊是同一份資料。
- **刪除**：按下後先列出影響，包括成員數、有授權的模組、欄位例外與資料範圍的筆數。若有欄位的選項範圍還指定這個群組，會直接擋下並列出是哪個模組的哪個欄位選項，要先到模組權限移除。這是因為選項範圍一移除，該選項可能變成所有人都能選，等於放寬權限。其他情況確認後，成員對應、模組授權、欄位例外與資料範圍會在同一個交易裡一起刪除。
- 刪除帶有「隱藏」或「唯讀」欄位例外的群組，也可能放寬權限；對話框會寫明「成員會失去這個群組的授權與限制」，但不擋。
- 範本用群組代碼指定權限建議；全新安裝沒有這些群組時，會略過並顯示警告，不影響建立。

## 13. 報表

左側選單「報表 → 我的報表」列出自己建立的與別人分享給我的報表。報表依觀看者自己的權限計算，所以同一張報表，不同人打開看到的數字可能不同。

### 一列代表什麼

每張結果上方都寫「每列代表：一筆訂單」或「一筆訂單明細」。沒有合併子模組時，一列是一筆主模組記錄；合併了子模組，一列是一筆子記錄（例如一筆訂單明細）。沒有子記錄的主記錄仍保留一列，子欄位是空的；但條件如果設在子欄位上，會先篩子記錄，沒有符合子記錄的主記錄（包含本來就沒有子記錄的）那一列會消失。

### 建立報表（五個步驟）

1. **選資料**：選主模組，可選擇合併一個子模組（主模組的明細模組，或有參照欄位指回主模組的模組；有多個參照欄位時要指定用哪個）。明細模組不能當主模組。同時合併兩個子模組會互相相乘，所以不提供。
2. **選欄位**：分成主模組欄位、沿參照帶出的欄位、子模組欄位。只列你看得到的欄位。
3. **設條件**：每個條件是「欄位、運算子、值」，條件之間一律是「而且」（沒有「或」）。參照欄位用記錄挑選器選值。另外可指定「主要日期欄位」與日期區間（今天、本週、上週、本月、上月、今年、去年、近 N 天／週／月）。區間以基準日換算，不是瀏覽器的日期；本週從週一開始。設了日期區間就必須有主要日期欄位。
4. **分組與彙總**：分組欄位、數值與彙總方式（加總、平均、最小、最大、主記錄筆數、子記錄筆數、條件占比）。不設分組就是明細報表。加總與平均只限數字型別，最小與最大也可用在日期。條件占比是符合條件的筆數除以總筆數，適合做達成率。
5. **預覽與儲存**：看結果、切換呈現方式（表格、指標、折線、長條、環圈）、命名、儲存。

分享要先儲存才有對象可分享，所以在儲存後的結果頁按「分享」，不在設計器裡。分享對話框列出所有群組的名稱，任何登入的使用者都看得到群組名稱（只有名稱，沒有成員與權限）；載入失敗時對話框會顯示錯誤與「重試」，不會是空的。

結果頁的「重新預覽」會用目前的設定再算一次。

### 合併後的數字：去重與「明細列相加不等於總計」

合併子模組之後，一筆訂單會有多列明細。主模組的欄位（例如訂單的稅率、訂單金額）在彙總時，每筆主記錄在每個分組內只算一次，用記錄的 `Id` 判斷。例如一張訂單分三次出貨，合併後訂單金額加總仍是原金額，不會變三倍。

這有一個必須知道的代價：列相加或下鑽列數對不上總計時，結果下方會顯示「總計每筆記錄只算一次；同一筆可能出現在多列或多個分組，所以各列相加不一定等於總計」。依子模組欄位分組時，同一筆訂單可能落在多個分組，每組各算一次，所以**各組相加可能大於總計**；總計一律獨立去重重算，不是把各組加起來。把下鑽的明細列加起來，同樣不會等於這個數字。

會出現這段說明的情況：

- 合併了子模組，且彙總了主模組欄位（加總、平均）或用了主記錄筆數。
- 依多選欄位分組，且用了加總、平均或筆數：一筆記錄有兩個選項就算進兩組。彙總的是主模組或子模組欄位都一樣。

最小、最大與條件占比不是相加出來的，不會顯示。

筆數分「主記錄筆數」與「子記錄筆數」，要依想問的問題選。

### 權限

- **模組**：要有該模組的讀取權限。非明細的子模組與參照目標各自授權。
- **記錄**：只算你資料範圍內的記錄；你看不到的子記錄不計入。
- **欄位**：報表任何地方（欄位、分組、彙總、條件、排序、帶出欄位）用到你看不到的欄位，整張報表顯示「無權限檢視：隱藏欄位」，不回部分結果。這包含條件：否則可以用篩選條件猜出隱藏欄位的值。條件用到你讀不到的帶出欄位、或參照目標模組讀不到時，也一樣整張擋下。
- **金額**：金額權限只管「金額」型別的欄位與結果為金額的公式；型別設成「小數」的金額不受控（既有行為）。沒有金額權限時，用到金額的報表整張無權限。
- **彙總欄位不能用**：彙總欄位存的是全域值，不看讀者的範圍，所以不列入報表欄位，引用彙總欄位的公式也一樣。要這個數字，請改成合併子模組自己加總。
- **規則隱藏不算權限**：表單規則造成的隱藏，報表不套用，和列表一致。

### 看到別人的報表

打開別人分享的報表只能看，不能改。

- **隱藏條件**：報表的條件用到你看不到的欄位，或你沒有模組讀取權限時，條件列表只顯示「隱藏條件」，不顯示欄位和值。看得到有條件，但看不到內容；擁有者自己也一樣。
- **不能另存**：看不全定義的人不能「另存為我的報表」，畫面顯示「這張報表用到你看不到的欄位，無法另存」。另存不會悄悄移除你看不到的條件，那樣會改變報表的意思。
- **系統管理員**：看得到並可以刪除所有共用報表，但**不能編輯、不能改別人的分享**；要改只能另存或刪除。
- **擁有者被停用**：報表留著，分享照常。

### 下鑽與匯出

點結果表格的某一列（或圖表的某個分組）會開「明細」，用同一套範圍與欄位過濾，最多 500 列。沒有分組的明細報表畫面上最多顯示 1,000 列，並提示總列數；總計依全部列計算，要看全部的列請用匯出，匯出不受這個上限影響。「匯出 Excel」要有所有涉及模組的列印匯出權限，沒有的人，「匯出 Excel」按鈕會停用並提示沒有匯出權限（是否有權限由後端判斷，與實際匯出時的檢查相同）；匯出檔含總計與上述說明，比例與百分比用 Excel 的百分比格式，用意是不讓報表變成繞過匯出權限的路。

### 資料量上限

有兩個上限，超過都不回部分結果：

- **合併後 5 萬列**（`Reports:MaxRows`，預設 50000）：合併且套用條件之後的列數超過就停止，顯示「資料太多，請縮小條件」。這裡縮小條件有用。
- **載入 20 萬筆**（`Reports:MaxLoadRows`，預設 200000）：單一來源模組（主模組或子模組）在你範圍內的記錄超過就停止，顯示「來源資料超過系統的載入上限，縮小條件也無法改善，請聯絡管理員」。條件要載入後才能套用，所以這個上限縮小條件也過不了；它只用來防止記憶體用盡。

### 資料基準日

報表的「今天」是基準日。一般情況用台灣時間的今天。Demo 站（`Demo__LoginEnabled`）的資料日期停在映像建置那天，所以報表以產生日當基準日，當它和今天不同時，結果旁標示「資料基準日 yyyy-MM-dd」，「近 90 天」這類區間也是從那天往前算。

### 幣別

系統沒有幣別欄位，「幣別」只是一般下拉，與金額欄位沒有關聯，報表無從判斷。第一版金額直接相加。**混用幣別時，請依幣別欄位分組，或用條件篩出單一幣別**，否則會算出沒有意義的數字。

### 欄位或模組被改之後

報表定義存的是欄位 ID，欄位改名不影響。欄位被停用或沒有權限時，結果顯示「欄位已不存在：X」，在設計器裡也會標示「不可用」，要先把它移除才能繼續與儲存。模組停用則顯示「模組已停用」。公式的結果型別改變，讓已存的量值或條件對不上（例如數字改成日期後的加總），結果顯示「欄位型別已變更：X」，不會算出空結果或假數字；到設計器重選欄位或條件值即可。

### 已知限制與路線圖

- 載入上限：來源模組超過 `Reports:MaxLoadRows` 的報表跑不出來，縮小條件也一樣；之後要放大時，方向是先用索引縮小記錄。
- 帶出實體標題的條件用挑選器比對鍵，不能用文字搜尋標題。
- 圖表模式的三條 y 軸（比例、日期、一般數字）並存時，手機寬度下繪圖區會變窄。
- 之後要做：**幣別綁定**（讓金額欄位指定幣別欄位，混幣別時自動分組）、**結果快取**（放大資料量時，先用索引縮小記錄再快取結果）。

## 14. 儀表板

儀表板是一組卡片，每張卡片是一張報表的一種呈現。左側選單「報表 → 儀表板」進入；只要有儀表板，首頁也會直接顯示（上次開的那張，沒有紀錄就是第一張），沒有任何儀表板時首頁維持原樣。卡片依**觀看者**的權限計算：同一張儀表板，業務主管與業務看到的數字不同，現場人員沒有金額權限的卡片只顯示「無權限檢視」，其他卡片不受影響。

### 兩種儀表板

- **指派版**：系統管理員建立並指派給群組，所屬群組的成員都看得到，依管理員排的順序列在前面。
- **我的儀表板**：自己建立，只有自己看得到。卡片只能放你看得到的報表（自己的或分享給你的）。

### 編輯版面

按「編輯版面」進入編輯狀態：拖曳卡片標題移動、拉邊角調整大小、「新增卡片」放上報表、卡片右上角的設定與關閉。每次放開滑鼠或確認設定就立刻存檔，沒有「儲存」鈕。版面是 12 欄的格子，一張儀表板最多 40 張卡片。手機寬度（小於 600px）卡片排成單欄、由上到下，不能拖曳；清單預設收合。

### 卡片設定

| 設定 | 作用 |
|---|---|
| 標題、呈現方式 | 預設用報表名稱與報表的呈現方式，改了只影響這張卡片 |
| 日期區間 | 設了就以卡片為準（見下方「日期的優先順序」） |
| 只顯示前 N 名 | 1 到 100。不會把其餘合成「其他」；總計仍是**全部**分組的合計，所以前 N 名相加可能小於總計 |
| 排序依據、由大到小 | 覆蓋報表原本的排序 |
| 累計占比 | 只有長條圖。依第一個量值由大到小排序，每一格顯示累計占比；分母是全部分組的合計，不受前 N 名影響 |
| 與前幾期比較 | 只有指標卡，1 到 12 期。拿前面「同樣長度」的區間算平均，顯示變動百分比；前期平均為 0 時只顯示平均 |
| 點擊後前往的儀表板 | 目標儀表板觀看者看不到時，不顯示連結 |

點圖表或表格的某一組會開明細，與報表的下鑽一樣。

### 日期的優先順序

卡片的區間 > 儀表板上方的暫時日期篩選 > 報表自己的區間，**只取一個，不會交集**。例如報表是「近 90 天」，儀表板篩選選「本月」，沒設區間的卡片就算本月；設了「近 30 天」的卡片仍算近 30 天，並註明「這張卡片有自己的日期區間，不受上方日期篩選影響」。暫時篩選只在目前畫面，不存檔，也不算「調整」。

### 個人調整版與還原最新版

指派版的成員也可以編輯版面。第一次調整時系統替你另存一份個人版，其他人不受影響，儀表板旁標示「已調整」。之後管理員更新了指派版，你的個人版不會被覆蓋，而是顯示「已更新」與「還原為最新版」；按下並確認後，捨棄你的調整、改用管理員的最新版。

### 卡片的特殊狀態

- 「報表已不再分享給你」：你自己放上的卡片（自己的儀表板，或在指派版的個人調整版上靠分享加入的卡片），報表被取消分享。指派版給的卡片不看分享，照樣執行，但仍依你的權限計算；即使管理員之後把那張報表從指派版移除，你的個人版保留的卡片仍可顯示。
- 「報表已被刪除」：卡片引用的報表不在了，可以把卡片移除。
- 刪除報表時，如果有儀表板引用，系統會列出哪些儀表板並擋下；只有擁有者自己儀表板上的卡片會隨報表一起移除。
- 單張卡片載入失敗只影響那一張，有「重試」。

### 系統管理：儀表板指派

管理員在「系統管理 → 儀表板指派」新增、改名、刪除指派版，用上下移調整順序，勾選要指派的群組，編輯版面（這裡的卡片只顯示報表名稱與呈現方式，不執行查詢）。存檔時帶版本號，若別的管理員剛更新過會顯示衝突訊息，重新選取後再改。取消指派後成員看不到該儀表板，個人調整版保留，重新指派時恢復。刪除群組前的影響清單會列出已指派給它的儀表板。

2. **預覽分頁**
   - 以 API 在 `p7-draft` 加了「優先度」（下拉：高、低）與「預計完成日」（日期、必填）。

## 未實機驗證

下列項目在實機走查中沒有實際操作，只靠自動測試或程式碼判斷：

- **設計器改了欄位或規則後，切回「預覽」分頁會重新載入**：前端 `PreviewTab.vitest.spec.ts` 的 `refetches when the module version changes` 驗了 query key 帶 `module.version`；沒有實際在設計器改欄位再切分頁。
- **匯入 Big5 檔案顯示「請把檔案存成 UTF-8 的 CSV」**：後端 `ImportTests.Preview_FileErrors_400`、`CsvReaderTests.Read_Big5_ReturnsUtf8Error`，前端 `ImportDialog.vitest.spec.ts` 的 `shows the server file error (key "file") inline`；沒有用 Excel 存出的 Big5 檔實測。
- **超過 1 MB 的檔案顯示「檔案不能超過 1 MB」**：後端 `ImportTests.Preview_FileErrors_400`，只測到 handler 層；沒有經過 HTTP 上傳實測。
- **超過 2 MB 的檔案由框架回 413**：沒有測試，只有 `ImportExportController` 的 `[RequestSizeLimit(2 * 1024 * 1024)]`；前端遇到 413 顯示什麼也沒驗。
- **超過 1000 筆資料列顯示「一次最多匯入 1000 筆」**：後端 `CsvReaderTests.Read_SkipsBlankRows_CountsLimit`；沒有經過 API 與畫面實測。

## 已知限制

- 系統重算（彙總、設計器觸發的公式重算）不寫歷程；公式、彙總、自動編號欄位的變化也不記（spec §15 第 38 條）。
- 歷程的參照標題依目前資料解析：目標改名後舊歷程顯示新名稱，目標刪除後顯示「（已刪除）」，SetNull 清空的那一列也是（spec §15 第 39 條、裁決 R14）。
- 匯入只新增、不更新，不含明細列；擴充模組不能匯入（spec §15 第 40 條）。
- 匯出上限 10000 筆、匯入上限 1000 筆，都一次載入記憶體；上線前改成串流與分批（spec §15 第 41 條）。
- 沒有金額權限時，匯出整欄不含金額欄位（照 §10），不是 §7 寫的「空白」；上線前和既有匯出做法對齊（spec §15 第 42 條）。
- `ClosedXML` 是 POC 自選的套件，正式版改用團隊選定的 Excel 元件（spec §15 第 43 條）。
- 設計器預覽看不到草稿中的明細模組（spec §15 第 44 條）。
- 選單分區只有一種語系（spec §15 第 45 條）。
- 歷程每頁都把明細模組整個載入，再挑出本頁用到的明細列標題；上線前改成依 Id 批次查詢（spec §15 第 46 條）。

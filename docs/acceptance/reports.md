## 權限

`ReportPermissionMatrixTests` 以不同身分跑同一份定義，涵蓋：

- 隱藏欄位放在欄位、分組、量值、條件、排序、帶出、主要日期、量值條件八個位置，都回 `restricted`，訊息不含欄位名稱。
- 沒有 Pricing 時，金額欄位、金額結果公式、引用金額的數字公式放在欄位、分組、加總、條件、排序、比率六個位置都回 `restricted`，序列化結果不含數值；條件猜中與猜錯的回應完全相同。明細金額跟著表頭的 Pricing，帶出金額跟著目標模組的 Pricing。
- 本人與全部範圍的數字不同；明細繼承表頭範圍；子模組無讀取權限、彙總欄位與間接引用彙總的公式、模組無讀取權限。
- 同群組範圍只算群組成員的記錄；下鑽走同一套檢查，隱藏欄位與金額欄位在下鑽時同樣回 `restricted` 且結果不含數值。
- 不可讀模組的帶出欄位放在條件、比率條件、主要日期、量值時整張回 `restricted`；放在欄位與分組時值標「（無權限）」。
- 參照欄位本身放在條件或比率條件時，目標模組不可讀或標題看不到也整張回 `restricted`；目標模組停用回 `moduleDisabled`。目標模組可讀、只是單筆記錄不在範圍內時，是逐列不符合。

## 已知限制

載入上限在套用條件之前檢查：來源模組（主模組或子模組）在觀看者範圍內的記錄超過 `Reports:MaxRows` 時，就算條件後或合併後列數很少，也回 `tooMany`。這一版接受：只會多擋，不會算錯。之後要放大時，方向是先用索引縮小記錄（spec §5）。

### 走查發現的問題

1. **日期軸從 0 起算（已修）**。圖表用日期型量值（例如最早訂單日期）時，日期軸刻度顯示 0001-01-01 到 2191-04-30，各組長條幾乎一樣高。修法是日期軸改依資料範圍（`scale: true`）。先寫失敗測試（`ReportChart.vitest.spec.ts` 的「日期軸不從 0 起算」，修前 `scale` 為 undefined），再改 `ReportChart.vue`；修後刻度是 2026-08-18 到 2026-09-12，長條高低不同。
2. **非系統管理員無法分享報表（已修）**。分享對話框用的 `GET /api/v3/dynamic/groups` 要求設計器讀取權限（`IDesignerRequest`），業務主管等一般使用者得到 403，對話框只剩標題與按鈕，沒有任何提示，也沒有群組可勾。設計文件的目標 2 與 §7 都說一般使用者可以把報表分享給群組，所以現在只有系統管理員做得到。修法需要判斷：新增一個報表專用的「可分享的群組清單」端點（只回 id 與名稱，不回成員），或放寬現有端點。這會讓所有登入者看得到所有群組的名稱，要決定可不可以。另外，對話框在載不到群組時應該顯示錯誤，而不是空白。**修正輪的裁決與做法**：新增報表專用的 `GET reports/share-targets`，只回群組 id 與名稱，任何登入者可讀，不放寬原本的 `GET /dynamic/groups`；分享對話框改用它，載入失敗時顯示錯誤與「重試」，儲存鈕停用。
3. **匯出 Excel 按鈕在沒有權限時仍可按（已修）**。現場人員在無權限報表上仍看到「匯出 Excel」按鈕，按了才回 403 並顯示錯誤。設計文件 §7 寫「沒有則按鈕停用」。**修法**：報表詳細資料回傳 `canExport`，與匯出時用同一段權限判斷；沒有權限時按鈕停用並提示。
4. **手機寬度的條件運算子下拉被截成「等」（已修）**。條件列在窄螢幕改為換行（欄位名稱一行，運算子與值並排），寬螢幕維持單列；實機 400px 看到完整的「等於」。
5. **Demo 沒有「客戶地區」欄位（資料，未修）**。brief 的範例報表「依客戶地區分組」在 Demo 資料做不出來，客戶擴充模組也沒有地區欄位；沒有改 Demo 資料。
6. **示範報表的資料來源（已修）**：原本 Demo 沒有任何報表分享給現場人員。現在「近 90 天各客戶訂單金額」也分享給現場人員，現場人員開啟顯示「無權限檢視：隱藏欄位」，有自動測試（`FloorStaff_OpenAmountReport_SeesRestricted`）。

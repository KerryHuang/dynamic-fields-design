# 主題與四種風格 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (recommended for this plan) or superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 使用者可選淺色、深色、依系統三種模式與四種風格，管理員設全站預設，個人可覆寫，所有既有畫面與報表圖表都跟著變。

**Architecture:** 後端在 `AppUser` 存個人設定、在 `SystemSetting` 存全站預設，由 `ThemeResolver` 逐欄解析。前端由 `use-theme-store` 把結果寫到 `<html>` 的 `data-style`、`data-mode` 並呼叫 `Dark.set()`；CSS token 掛在這兩個屬性上，`quasar-bridge.css` 再接到 Quasar。圖表透過 `themedChartOption()` 讀同一組 token，主題變更時只重新套色。

**Tech Stack:** Vue 3、Quasar 2、Pinia、TanStack Query、ECharts、vitest、bun；.NET 8、EF Core SQLite、MediatR、xUnit。不新增任何相依套件。

**Spec:** [`docs/superpowers/specs/2026-11-06-theme-design.md`](../specs/2026-11-06-theme-design.md)。附錄的色值與版面值在 Task 5 使用。

## Global Constraints

- 模式允許值 `light`、`dark`、`system`，出廠 `system`；風格允許值 `workbench`、`airy`、`enterprise`、`industrial`，出廠 `workbench`。比對區分大小寫。
- 解析順序逐欄獨立：個人、全站預設、出廠預設。
- 系統設定鍵為 `theme.defaultMode`、`theme.defaultStyle`，不預先寫入。
- API 前綴 `api/v3/dynamic`。`AuthSettings.DemoLoginEnabled` 開啟時，兩個 `PUT` 一律回 403。
- 內文對比至少 4.5:1，大字與圖示至少 3:1；附錄的值與對比衝突時以對比為準。
- 不載入外部字型，四種風格只用系統字型堆疊。
- `localStorage` 只放視覺偏好，不放身分資料，且所有讀寫都要能在不可用時正常運作。
- `.vue` 不得新增寫死的顏色（Task 7 的掃描測試會擋）。
- 公開 repo：程式、文件、commit message 不得出現公司名稱、個人絕對路徑、內網 IP 或非範例信箱。
- git 逐檔指名 add，不用 `git add -A`、`git add .`；commit 前看 `git status`；不用 `--no-verify`。不 push、不 merge、不開 PR，除非使用者要求。

## 合併與後續介面

- **small-gaps 若先合併，主題分支要先 rebase。** 目前看到的衝突點：`MainLayout.vue`（第 7 行的改密碼按鈕與 `watch(me, ...)`）、`domain/dynamic/types.ts` 的 `Me`、`PermissionResponses.cs` 的 `MeResponse`、`GetMeHandler.cs` 的回傳行。兩邊都是新增欄位，保留雙方即可。

- Migration 由本分支新增。如果另一條線也新增了 migration，rebase 後要重新產生本分支的 migration，讓快照一致。
- **儀表板可直接使用：** 版面與顏色用 `--t-*` token 與 `.text-stat`、`.text-muted` 等 class；圖表用 `themedChartOption()`，並監看 `useThemeStore().appliedKey` 重新套色。

## Review Focus

1. 快速連選兩個設定，前一次失敗、後一次還在送：畫面要留在後一次的選擇，兩次都失敗才回到原本的設定（Task 8）。
2. 已登入者重新整理：auth guard 還在等 `/me` 時不能先打 `GET /theme`，否則個人主題會閃成全站預設（Task 8）。

4. `localStorage` 的內容損毀、值不在允許範圍、或存取時直接丟例外：內嵌 script 和 store 都要退回預設值，不能白畫面（Task 3、Task 4）。
5. Quasar 的 `color="primary"` 會產生 `bg-primary text-white`，`text-white` 又帶 `!important`：深色模式與現場工業的主色按鈕、深色的 `bg-negative` 都會因此對比不足，要由 bridge 覆寫（Task 5、Task 6）。

```csharp
public record UpdateMyThemeRequest(string? Mode, string? Style) : IRequest<ServiceResult>, ITransactionalRequest;
public record UpdateSiteThemeRequest(string? Mode, string? Style) : IRequest<ServiceResult>, ITransactionalRequest, ISystemAdminRequest;
```

**檢查順序（重要）：** 這兩個請求不寫 FluentValidation validator。`ValidationBehavior` 在 handler 之前執行，用 validator 的話，Demo 站送無效值會回 400，違反「一律回 403」。Handler 依序做：

1. `AuthSettings.DemoLoginEnabled` 為 true 就回 `ServiceResult.Forbidden()`。
2. 驗證允許值，不符回 `ServiceResult.Invalid`，錯誤鍵為 `mode`、`style`。
3. 寫入並 `uow.CommitAsync`。

`PUT /system/theme` 的管理員檢查由既有的 `SystemAdminBehavior` 負責，它排在最前面。

```ts
// theme-model.ts
export const THEME_MODES = ['light', 'dark', 'system'] as const;
export const THEME_STYLES = ['workbench', 'airy', 'enterprise', 'industrial'] as const;
export type ThemeMode = (typeof THEME_MODES)[number];
export type ThemeStyle = (typeof THEME_STYLES)[number];
export type ResolvedMode = 'light' | 'dark';
export interface ThemeChoice { mode: ThemeMode | null; style: ThemeStyle | null }
export interface ThemeDefaults { mode: ThemeMode; style: ThemeStyle }
export interface MeTheme extends ThemeChoice {
  effectiveMode: ThemeMode; effectiveStyle: ThemeStyle;
  defaultMode: ThemeMode; defaultStyle: ThemeStyle; canSave: boolean;
}
export const FACTORY_THEME: ThemeDefaults;           // { mode: 'system', style: 'workbench' }
export const SIDEBAR_WIDTH: Record<ThemeStyle, number>; // 172, 188, 208, 186（q-drawer 的 width 只收數字，所以放這裡）
export function parseMode(v: unknown): ThemeMode | null;
export function parseStyle(v: unknown): ThemeStyle | null;
export function resolveTheme(choice: ThemeChoice, defaults: ThemeDefaults): ThemeDefaults;

// theme-storage.ts：所有函式內部 try/catch，不往外丟例外
export const THEME_CACHE_KEY = 'formwright.theme.cache';
export const THEME_DEMO_KEY = 'formwright.theme.demo';
export function readThemeCache(): ThemeDefaults | null;  // 逐欄 parse，未知值用出廠值；無快取或 JSON 損毀回 null
export function writeThemeCache(t: ThemeDefaults): void; // mode 存未解析的值（可能是 system）
export function readDemoChoice(): ThemeChoice;           // 損毀時回 { mode: null, style: null }
export function writeDemoChoice(c: ThemeChoice): void;

// use-theme-store.ts
useThemeStore(): {
  choice, defaults, canSave,                 // state
  effective: ThemeDefaults, resolvedMode: ResolvedMode,
  appliedKey: string,                        // `${style}:${resolvedMode}`，圖表監看這個值
  sidebarWidth: number,                      // getters
  hydrate(): void,                           // 開機讀快取並套用，註冊 matchMedia 與 beforeprint/afterprint
  applyMe(t: MeTheme): void,                 // canSave 為 false 時 choice 取 readDemoChoice()
  applyAnonymous(d: ThemeDefaults): void,    // choice 取 readDemoChoice()
  setChoice(c: ThemeChoice): void,           // 立刻生效；canSave 為 false 時另寫 demo 鍵
}
```

套用時寫 `document.documentElement` 的 `data-style`、`data-mode`，呼叫 `Dark.set(resolvedMode === 'dark')`，再 `writeThemeCache(effective)`。

`applyAnonymous` 直接讀 Demo 偏好、不另外判斷站台種類：`GET /theme` 只回兩個值，判斷不出來；正式站又從不寫這個鍵，所以讀到的一定是空值。

列印時 `beforeprint` 暫時把 `data-mode` 與 `Dark` 切成淺色，並讓 `appliedKey` 跟著變，圖表才會改成深字；`afterprint` 還原。這段切換不寫快取。

**`useThemeSync` 的規則：**

- 已登入（`identity.userId` 非空）：查 `['me', userId]`，與 `useMe` 共用快取，資料更新時 `applyMe`。正在送儲存時略過，避免舊資料蓋掉剛選的值。
- 未登入：只有 `identity.userId` 為空**且** `route.meta.public === true` 才查 `['theme-defaults']`，成功就 `applyAnonymous`，失敗什麼都不做（留在快取或出廠值）。
- Quasar 的 SPA 模式在 auth guard 跑完前就會 mount。起始路由沒有 `meta.public`，所以上面這個條件也擋住了 guard 還在等 `/me` 的那段時間。

**`useSelectTheme` 的規則：**

- `canSave` 為 false：只呼叫 `theme.setChoice`，不打 API。
- `canSave` 為 true：`useMutation` 帶 `mutationKey: ['my-theme']`、`scope: { id: 'my-theme' }`，讓請求依序送出。
- `onMutate`：`cancelQueries(['me', userId])`，呼叫 `theme.setChoice(choice)`。
- 記一個 `confirmed`，初值是第一次送出前的選擇，每次成功更新為伺服器回應。
- 只有佇列裡最後一個請求（`qc.isMutating({ mutationKey }) === 1`）結束時才收尾：成功就 `setQueryData` 寫入 `me.theme`；失敗就 `theme.setChoice(confirmed)`。
- 任何一次失敗都呼叫 `onError`，讓呼叫端顯示訊息。

**`useSaveSiteTheme`：** 成功後 `invalidateQueries(['me'])`，管理員自己的畫面會更新；其他已開著的畫面不主動推送，下次重新取得 `/me` 時生效。

```ts
export interface ChartTheme { text: string; muted: string; grid: string; panel: string; palette: string[] }
```

# 報表第一段實作裁決

計畫（[reports-stage1](2026-11-05-reports-stage1.md)）和設計文件（[reports-design](../specs/2026-11-05-reports-design.md)）沒寫清楚、或兩者互相衝突的地方，實作中逐項裁決。後面的工作都以這份為準。每條寫三件事：裁決、理由、裁錯的代價。

## 資料與合併

**報表條件是平面 AND 清單。** 條件用既有運算子串起來，不用列表篩選的 any／巢狀樹。理由是設計文件的五步驟畫面不需要巢狀，之後放寬不會讓已存的定義失效。代價：使用者暫時無法表達 OR，要等放寬。

**需要「全部共用報表」時，倉儲層可多一個方法。** 計畫要求管理員看得到所有共用報表，第 1 項的介面表達不了，所以第 5 項可以另加一個「列出全部報表與分享」的方法。代價小：方法加錯了位置，只是之後搬動。

**載入上限在套用條件之前檢查（`tooMany`）。** 來源模組（主模組或子模組）在觀看者範圍內的記錄超過 `Reports:MaxRows`，即使條件之後只剩幾筆，也回「資料太多，請縮小條件」。理由是這樣永遠不會回部分或錯誤的數字，而且記憶體有上限；用索引先縮小是設計文件列的後續放大方向。代價：有些其實放得下的報表被擋，訊息還告訴使用者縮小條件，但縮小條件不一定有用。

**日期區間必須搭配主要日期欄位。** 設了區間卻沒有主要日期欄位，儲存時就拒絕。否則「本月」報表會悄悄算出全部時間的數字。代價：幾乎沒有，設計器一定會帶出主要日期欄位。

**資料格式不符的條件值，逐列視為不符合，不整張報錯。** 公式欄位的結果型別在報表存檔後可能改變，卡片不該因此失敗。代價：改型別後報表可能變空，而畫面沒有提示原因。

**沒有時區的日期時間值，視為台北牆上時間。** 條件值與存的值都這樣處理，與設計文件 §6.4 一致，也符合 `datetime-local` 輸入產出的格式。代價：只有送 UTC 卻沒帶時區的用戶端會差 8 小時；系統自己寫入的值一定帶 `+08:00`，不受影響。

## 權限與隱藏

**條件用到看不到的欄位，整張報表擋下，不是部分數字。** 觀看者看不到的「帶出欄位」若出現在篩選條件、數值條件或主要日期欄位，整張回「無權限檢視」；欄位與分組位置則保留標記值。理由是設計文件反目標：不能出現「看起來對、其實錯」的數字，而悄悄略過條件會回不同的結果，還能被拿來推測隱藏值。代價：本來可以看部分數字的人，會看到整張被擋。

**同一條規則涵蓋數值（彙總）、直接參照與停用。**

- 彙總的量值放在看不到的帶出欄位上，整張擋下，不留一個值為空的 ok 卡片，那樣看不出原因。代價：觀看者會連同其他量值一起看不到。
- 直接參照欄位在篩選或量值條件中使用，而目標模組讀不到時也整張擋下。欄位本身看得到，所以在欄位與分組位置仍可顯示。代價：看得到欄位的人，沒有目標模組讀取權限就不能拿它當條件。
- 參照的目標標題欄位隱藏（`restricted`）或目標模組停用（`moduleDisabled`），同樣擋下，與帶出欄位一致。代價：觀看者無法用這個參照當條件。已知小問題：停用的目標會先回 `moduleDisabled`，沒有讀取權限的人因此分得出「停用」和「不可讀」。

**不含價格權限的人，看不到金額。** 金額型欄位與結果為金額的公式，不得外洩給沒有 Pricing 權限的觀看者，一律走既有的權限檢查，並有必要的測試。代價：外洩價格，是這條規則最重的風險。

**讀報表時，隱藏欄位上的條件值被遮蔽，連擁有者也一樣。** 觀看者沒有模組讀取權限、欄位不可見、或帶出欄位的目標不可讀時，條件的值不回傳，只標記「隱藏」。理由是設計文件反目標與 §7：看得到有條件，但看不到內容。代價：擁有者自己也看不到條件值，用被遮蔽的定義送回儲存會被拒（400）；畫面因此不提供「含隱藏條件的編輯後儲存」。

**看不全定義的人不能另存。** 另存會跑和儲存相同的驗證，觀看者有任何看不到的欄位就拒絕，而不是悄悄移除條件。理由是移除條件會改變報表的意思，而且會讓人以為是同一張。代價：把設計文件 §7「可以另存一份」縮窄為「看得到完整定義的人」；權限較少的分享對象不能另存。畫面把 400 與 403 都解讀為「這張報表用到你看不到的欄位，無法另存」。

**匯出包含總計與去重說明。** 設計文件 §6.3：各列加總可能大於總計，不寫說明會被當成錯誤。代價：xlsx 多幾列。

**管理員可以看與刪除所有共用報表，但不能編輯或分享別人的。** 設計文件 §7 寫「看得到與刪除」。管理員要改只能另存一份或刪掉。代價：管理員無法幫離職者修報表。

## 目錄與設計器

**目錄不列出目標模組讀不到的直接參照。** 這種欄位每個值都會變成「（無權限）」，分組只有一組、條件會擋下整張，所以不列。設計器仍必須能顯示已存的、目錄裡沒有的欄位。代價：觀看者不能把這個欄位挑成普通欄位。

**目錄不列出另一個模組的明細若它以一般參照指回來。** 保守列出，儲存時比較寬鬆。代價：這種子模組在設計器選不到。

**目錄的實體標題用 id 0，由前端翻譯。** 後端寫死 `標題`，前端依語系翻。代價：標題翻譯依賴字尾字樣。

**設計器提供「條件占比」。** 設計文件 §6.3 與 §4 步驟 4 都有，計畫沒列。代價：設計器比計畫大。

**參照欄位的條件用真正的記錄挑選器，不是原始 id。** 沿用列表篩選的挑選器。代價：設計器更大，目錄要多提供挑選器需要的資訊。

**建立後才能分享，分享在檢視頁，不在設計器第 5 步。** 報表要有 id 才能分享，已有分享對話框。代價：多按一次。設計文件 §4 寫分享在第 5 步，使用者可以改裁決。

**排序在第一段不能編輯。** 排序和前幾名屬於卡片選項（第二段）。第一段只在欄位或量值被移除時清掉排序，並在不可用時標記。代價：第一段沒有排序控制。

**圖表模式也顯示總計。** 設計文件 §6.3 的說明提到的數字必須在畫面上。代價：卡片多一點內容。

## 資料基準日、Demo 與文件

**「近 90 天訂單狀態分布」也分享給業務群組。**，才能在第一段就示範同一張報表、不同身分、數字不同。代價：業務多看一張示範報表。

**Demo 文件留在 Task 10。** `docs/demo.md` 依計畫在最後一個 task 寫。代價：中間幾個 task 的 Demo 沒有文件。

**報表路由分兩個 task 註冊。** 第 7 項只註冊 `/reports` 與 `/reports/:id`，第 8 項才加 `/reports/new` 與 `/reports/:id/edit` 並修改路由檔，因為設計器頁面到第 8 項才存在。代價：無。

**驗收文件 `docs/acceptance/reports.md` 由第 4 項建立。** 計畫該項的檔案清單漏列，但基準測試結果要記在那裡。代價：無。

**群組刪除的影響對話框加上「報表」筆數，放在 Task 7。** 第 1 項只做後端，報表畫面歸第 7 項。代價：到第 7 項前，刪群組不顯示報表影響。

**`ReportRunner.cs` 在修正輪維持單一檔案（674 行）。** 計畫只列一個檔；在修正輪拆檔會擴大審查範圍。代價：之後較難維護，最終審查可再決定拆不拆。

## 走查後的修正

**分享用報表專用的群組清單端點，不放寬管理端點。** 新增 `GET reports/share-targets`，只回群組 id 與名稱，任何登入者都能讀；原本的 `GET /dynamic/groups` 維持只有設計器權限能讀。理由：使用者明確要求一般使用者可以把報表分享給群組，而管理端點回傳成員與權限，不該放寬。代價：所有登入者都看得到每個群組的名稱。

**沒有匯出權限時停用「匯出 Excel」，由後端旗標決定。** 報表詳細資料回傳 `canExport`，判斷與匯出時的檢查是同一段程式（所有涉及模組的列印匯出權限），前端不自己重算。理由：設計文件 §7 寫沒有權限則按鈕停用。代價：報表詳細資料多一次權限判斷。

**Demo 資料把一張用到金額的報表分享給現場人員。** 「近 90 天各客戶訂單金額」分享給業務主管與現場人員，現場人員一登入就看到「無權限檢視」的卡片，不必先由管理員手動分享。理由：設計文件 §10 的走查要求。代價：Demo 多一筆分享。

**Demo 的客戶維持沒有地區欄位，走查改依客戶標題分組。** 客戶是既有實體，只有標題。理由：範例報表「依客戶地區分組」照字面在 Demo 資料做不出來，為它加欄位會動到 Demo 結構。代價：走查與 brief 的範例不完全相同。

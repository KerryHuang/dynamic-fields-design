# 主題與四種風格設計

狀態：已核准。

## 目的

Formwright 是每家客戶各裝一套的產品。不同客戶、不同職務看系統的方式不一樣：內勤要看大量資料，主管要看得舒服，現場人員要遠距離看得清楚。使用者的裁決是「它是個產品，一定要有彈性」，所以四種風格都做，由客戶自己選。

示意頁：<https://claude.ai/artifact/CuLbkVpQ38qKKeDnGyS2aQ>（私人頁面，實作者可能打不開）。四種風格的色彩、圓角、密度以本文附錄為準，附錄的值取自這一頁。示意頁上的舊產品名不適用。

## 目標

- 使用者可以選明暗模式：淺色、深色、依系統。
- 使用者可以選四種風格：資料工作台、簡潔留白、正式企業、現場工業。
- 系統管理員設定全站預設；每個使用者可以覆寫，也可以改回跟隨全站預設。
- 明暗模式和風格各自獨立，所以共有 12 種組合，每一種都要可讀。
- 所有既有畫面、Quasar 元件和報表圖表都跟著主題變。

## 非目標

- 客戶自訂顏色、字型或 Logo。這次的「自訂」指在四種風格和三種模式之間選擇。
- 依模組或群組設定不同主題。
- 第五種風格，或讓客戶自己新增風格。
- 重新設計版面、導覽或既有功能流程。
- 改 repo、命名空間等舊名稱。

## 已定決定

這些是使用者已裁決的事項：

- 四種風格都做，不是擇一。
- 模式有淺色、深色、依系統三種。
- 系統管理員設全站預設，個人可以覆寫。
- 順序排在報表第一段之後、儀表板之前。

## 設定模型

| 設定 | 允許值 | 出廠預設 |
|---|---|---|
| 模式 `mode` | `light`、`dark`、`system` | `system` |
| 風格 `style` | `workbench`、`airy`、`enterprise`、`industrial` | `workbench` |

實際套用的值依下列順序決定，兩項分開計算：

1. 使用者自己的設定。
2. 全站預設。
3. 出廠預設。

例如使用者只改模式，風格仍跟隨全站預設；之後管理員改預設風格，這位使用者的風格也會跟著變。

後端要驗證允許值，不符就回 400。讀取時遇到未知值（例如資料庫被手動改過），要當作沒有設定，不能讓畫面失敗：

- 個人欄位的未知值退回全站預設，`/me` 的個人設定回 null。
- 全站預設的未知值退回出廠預設。
- 每個欄位各自判斷。

`SystemSetting` 不預先寫入主題的鍵，缺鍵就用出廠預設。

## 後端

**資料：**

- `AppUser` 新增可為 null 的 `ThemeMode`、`ThemeStyle`；null 代表跟隨全站預設。
- 全站預設放在既有的 `SystemSetting`，鍵為 `theme.defaultMode`、`theme.defaultStyle`。

**API（前綴 `api/v3/dynamic`）：**

| 方法與路徑 | 權限 | 用途 |
|---|---|---|
| `GET /me` | 已登入 | 回應新增 `theme`：個人設定（可為 null）與實際套用的值 |
| `PUT /me/theme` | 已登入 | 更新個人設定；傳 null 代表改回跟隨全站預設 |
| `GET /theme` | 匿名 | 只回傳全站預設的兩個值，給登入頁使用 |
| `PUT /system/theme` | 系統管理員 | 更新全站預設 |

- `GET /theme` 要加進 `SessionMiddleware` 的匿名清單。這個端點只回傳兩個固定選項，不含其他資訊。
- `PUT /me/theme` 不加進「必須改密碼時仍可使用」的清單，規則維持不變。

**Demo 站：** 判斷依據是 `AuthSettings.DemoLoginEnabled`。這個設定打開時，任何訪客都能不用密碼登入 Demo 帳號和 `admin`，所以整個站的帳號都不算個人帳號：

- `PUT /me/theme` 和 `PUT /system/theme` 一律回 403。
- `/me` 的 `theme` 加上 `canSave: false`，前端據此把選擇只存在瀏覽器的 `localStorage`。這份偏好每個瀏覽器一份，不分帳號。
- 訪客可以試用所有外觀，不同訪客互不影響。
- 「外觀預設」頁在 Demo 站唯讀，並說明原因，不能讓人以為按了沒反應。

正式站不要打開這個設定；打開就等於任何人都能當 `admin`，這是既有行為，這次不改。

## 前端

### 套用方式

`<html>` 上放兩個屬性：`data-style="workbench"` 和 `data-mode="light|dark"`。`system` 會先依瀏覽器設定解析成 light 或 dark，並監聽 `prefers-color-scheme` 的變化，不用重新整理就能切換。

新增 `src/css/themes/`：

- `tokens.css`：定義語意 token，例如背景、文字、邊框、主色、狀態色、圓角、間距、列高。
- 每種風格一個檔案，各有淺色與深色兩組值。
- `quasar-bridge.css`：把 token 接到 Quasar 的 `--q-primary` 等變數，以及表格、輸入框、按鈕、卡片、對話框的密度與圓角。

明暗模式同時要呼叫 Quasar 的 `Dark.set()`，因為 Quasar 元件依它決定深色樣式。

### 既有寫死的顏色

目前有 20 個 `.vue` 檔、共 30 處寫死的顏色，多數是 `text-grey-7`、`text-grey-8`、`bg-blue-1`。這些在深色下會看不清楚，要改成語意 class，例如 `text-muted`。`text-white` 搭配 `bg-negative` 這種固定組合，只要對比足夠就可以保留。

`.vue` 不得新增寫死的顏色。測試要掃描原始碼，出現新的就失敗。

「寫死的顏色」指 Quasar 調色盤 class（例如 `text-grey-7`、`bg-blue-1`）、行內 `style` 的顏色，以及 scoped CSS 裡的 hex、rgb。語意色（例如 `text-primary`、`text-negative`、`bg-negative`）不算。前面的 30 處是調色盤 class 的盤點結果，實作時要依這個定義重新盤點；確定要保留的固定組合列入測試的例外清單。

### 圖表

`ReportChart.vue` 目前沒有指定顏色。要從 CSS token 讀取主色、文字色和格線色，設定給 ECharts；主題變更時重新套用，不重新查詢資料。

### 字型

不載入外部字型。客戶可能在內網安裝，也不應該因為字型把使用者資訊送到第三方。四種風格只使用系統字型堆疊，靠字級、字重和數字樣式做出差異。示意頁的 Google Fonts 不會帶進產品，所以現場工業的細長數字字型效果會有差異。

### 避免閃爍

- 每次解析完主題，把結果寫進 `localStorage`。這份快取只有一份、不分帳號，登入、登出後由新的結果覆蓋，只用來避免閃爍，不是偏好。
- Demo 站的偏好用另一個鍵存放，不和快取共用。
- `index.html` 用一小段內嵌 script，在 Vue 啟動前讀取快取並設定 `<html>` 屬性。
- 登入頁先用快取，再以 `GET /theme` 校正；登入後以 `/me` 為準。
- `localStorage` 不可用時（例如無痕模式或被封鎖）要照常運作，改用預設值。
- 只有視覺偏好放在 `localStorage`，不放身分資料。

### 操作入口

- **個人：** 右上角新增「外觀」，可選模式與風格，各有「跟隨全站預設」。選了立刻生效。
- **全站：** 「系統管理」新增「外觀預設」頁，只有系統管理員看得到。

每種風格旁要有一句說明與小型預覽。文案要加進 zh-TW、en-US、th、vi 四個語系。

### 列印與匯出

列印和匯出檔不跟隨深色主題。目前前端沒有 `@media print` 樣式，若列印畫面時帶到深色背景，要補一段強制白底黑字的列印樣式。

## 可讀性要求

12 種組合都要符合：

- 內文對比至少 4.5:1，大字與圖示至少 3:1。
- 狀態（例如逾期）不能只靠顏色區分，文字要保留。
- 鍵盤焦點在每種組合都看得到。

測試要對每種組合的主要文字與背景 token 計算對比。附錄的值和對比要求衝突時，以對比為準：實作者調整該值，並在 PR 說明列出改了哪些值。

## 錯誤處理

- 儲存失敗：畫面顯示錯誤訊息，並回到上一個設定，不能看起來已存好。
- `GET /theme` 失敗：登入頁使用快取或出廠預設，不擋登入。
- 全站預設被改動時：已開著的畫面不強制即時更新，下次重新取得 `/me` 時生效。

## 驗收

**自動測試：**

- 後端：優先順序、允許值驗證、權限、匿名端點只回兩個值、`DemoLoginEnabled` 開啟時兩個 `PUT` 都回 403、缺鍵與未知值退回預設。
- 前端：解析順序、`system` 跟隨瀏覽器變化、儲存失敗會還原、`localStorage` 不可用、圖表會重新套色、原始碼沒有新增寫死的顏色、12 種組合的對比。
- 既有後端與前端測試全部通過，`vue-tsc` 與 build 通過。

**實機：**

- Demo 站與本機：12 種組合都開過主要畫面（列表、表單、明細、設計器、報表、系統管理），每種組合留一張截圖。換主題時畫面不閃爍；重新整理和換瀏覽器分頁後，設定還在。
- Demo 站：選擇只留在這個瀏覽器，用另一個瀏覽器開不受影響；「外觀預設」頁唯讀。
- 本機（`DemoLoginEnabled` 關閉）：Demo 站測不到伺服器儲存，所以在這裡驗。一般帳號的設定換瀏覽器後仍在，管理員改預設後未覆寫的使用者跟著變。

視覺好不好看要由使用者判斷。AI 走查的結果只能代表畫面沒有壞掉，不能代替使用者驗收。

## 實作者可自行決定

- token 的命名與檔案細節，只要語意一致。
- 設定 UI 的元件選擇，優先用 Quasar 既有元件。
- 預覽用縮圖還是即時小樣本。

## 主控代為決定的事項

這些不是使用者的裁決，核准時請特別確認：

1. 「自訂」解讀成在既有選項中選擇，不包含自訂顏色和 Logo。
2. 出廠預設是依系統加資料工作台。
3. 不載入外部字型。
4. 個人設定存在伺服器，所以換裝置也會跟著。
5. `DemoLoginEnabled` 開啟的站，所有帳號的外觀都只存在瀏覽器，包括 `admin`，也都不能改全站預設。
6. 附錄的值和對比要求衝突時，對比優先。

**各風格的特徵：**

- `workbench`：密度最高，表格標題粗體，色彩克制。
- `airy`：卡片無框線，淺色模式用柔和陰影，深色模式改用邊框；標題和大數字字級較大。
- `enterprise`：深藍頂列，有麵包屑，選取項左側有 3px 主色標記，表格標題下方 2px 線。
- `industrial`：卡片與表格標題使用 2px 粗框，大數字 40px 粗體，深色邊欄；邊欄未選取項固定用 #f0efe9，因為淺色模式的邊欄也是深色。

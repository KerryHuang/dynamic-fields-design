# 文件

- **功能清單** `docs/feature.md`：每項一行，`[x]` 完成、`[ ]` 加 🚧 進行中／📋 已規劃／💡 構想、`[-]` 不做附理由；打勾時在行尾加灰底完成日 `` `YYYY/MM/DD` ``（使用者裁決 2026-11-21）。改完用 lifecycle plugin `scripts/` 下的 `feature_checklist.py docs/feature.md --write` 重算統計，不手改統計行。沒裝 lifecycle（找不到腳本）時照常改項目、統計行不動，回報寫「統計行待重算」，由有腳本的 session 補跑。
- **裁決**寫回對應的設計文件（`docs/superpowers/specs/`），標明是使用者裁決還是主控暫定；進度寫在 `docs/roadmap.md` 的工作段表格。
- **roadmap 狀態欄**（使用者裁決 2026-11-21）：做完的段以「✅ 」開頭（`✅ 已上線（日期，SHA）`、`✅ 已完成…`）；內容長的在括號外的「；」後與開頭摘要的「：」後加 `<br>` 換行，一個子段一行。
- **設計文件**：應用程式或功能設計要有「ERP 對照」一節；寫明各開關組合下誰負責；新的寫死項目要列在已知限制或「可寫死清單」。
- **手冊** `docs/manual.md`：使用者看得到的行為改變要同步；文案以畫面實際文字為準。
- 站內連結用相對路徑；搬檔時同步修所有引用。
